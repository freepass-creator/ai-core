# 어디를 보나 — Development Center Routing Map

개발 관련 요청은 먼저 아래 표에서 **Primary Hub**를 정한다.

| 요청 | Primary Hub | 같이 보는 Hub |
|---|---|---|
| 디자인 통일, UI/UX, 버튼·표·헤더·패턴 | Design Hub | Quality Hub |
| 데이터 구조, SSOT, Schema, Lineage, Migration | Data Hub | Integration, Quality |
| 보고서, 계약서, 제안서, 양식, PDF/PPT | Document Hub | Design, Quality |
| 공통 코드, SDK, Repository, Adapter/Provider 패턴 | Engineering Hub | Quality |
| Firebase, Google, GitHub, API, Webhook, Connector | Integration Hub | Engineering, Quality |
| 테스트, 회귀, 접근성, 성능, 보안, Conformance | Quality Hub | 대상 Hub |
| Build, Deploy, Release, Rollback, Recovery | Delivery Hub | Quality |

## Control Plane으로 가는 요청

다음은 Hub가 아니라 Development Center 공통 Control Plane이 직접 관장한다.

- 작업 요청·배정·인계 → `operations/`
- 요구사항·정본·예외·규격 → `standards/`
- 정본 포인터 검색 → `registry.json`
- SSOT 검증 → `ssot/`
- 지도점검·시정 → `operations/inspection/`
- 센터 공통 실행 → `engine/`
- 실행 증거 → `runs/`

## 상위/하위 관계

```text
AI Core Contract
      ↓
Development Center
      ↓
Primary Hub + Secondary Hubs
      ↓
Project implementation
      ↓
Quality evidence
      ↓
Delivery evidence (배포 작업일 때)
```

AI Core와 Hub의 내용이 충돌하면 Hub가 AI Core Contract를 임의로 재정의하지 않는다. 프로젝트가 Hub보다 앞선 구현을 가지고 있으면 검증 후 candidate로 역수입한다.
