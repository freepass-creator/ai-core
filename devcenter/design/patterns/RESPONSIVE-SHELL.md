# 개발센터 반응형 작업 화면 v1

채택 근거: 사용자 2026-09-09 요청 — 「지금 옆에 반응형 화면 아주 좋구먼?? 저거도 규격화 해놓자」.

적용 범위: 개발센터와 같은 **메뉴 + 작업 영역 + 카드/목록 + 미리보기** 형태의 관리 화면. 기존 프로젝트의 UI 규격을 자동 대체하지 않는다. 다른 프로젝트에 사용할 때는 해당 프로젝트의 정본·적용 범위와 먼저 대조한다.

상태: **사용자 채택, 현재 구현을 재사용 기준으로 등록**. 전체 접근성·모든 해상도·네 AI 기술 검수의 합격을 의미하지 않는다.

이 문서는 적용 범위와 재사용 계약을 정하고, 실제 동작·치수의 정본은 아래 구현 코드다. 현재 사용처는 `devcenter/portal` 한 곳이다. 왼쪽 탐색과 하나의 주 작업 영역을 갖는 관리 화면에 적용하며, 공개 랜딩·다중 편집 패널 화면은 별도 검토한다. 다른 프로젝트의 기존 규격과 충돌하면 기존 정본을 우선하고 적용 차이를 그 프로젝트에 기록한다.

## 재사용할 구조

- 넓은 화면: 왼쪽 탐색 메뉴와 오른쪽 작업 영역. 상단에 현재 위치를 표시한다.
- 좁은 화면: 상단 메뉴 버튼으로 탐색을 열고 닫는다. 항목을 선택하면 메뉴가 닫히고 본문 첫 위치로 이동한다.
- 화면 폭에 맞춰 요약 카드, 원자 선택, 규칙 카드, 상세 패널의 열 수와 배치를 바꾼다.
- 검색 결과는 목록에서 고르고 상세 근거를 확인한다. 빈 결과와 필터 해제를 제공한다.
- 실제 부품 미리보기와 사용 예제·원본 코드를 같은 작업 영역에서 확인한다. 미리보기 iframe은 제품 원본 CSS와 센터 CSS를 분리한다.
- 선택 메뉴와 표시 방식의 선택 상태를 시각 표시와 접근성 속성으로 함께 제공한다.

## 현재 코드 관찰값 — 별도 토큰 정본 아님

아래 숫자는 개발센터 Git `ef076c8` 시점의 위 구현 파일에서 읽은 파생 설명이다. 재사용할 때 현재 코드와 대조하며 이 표를 복사해 별도 치수 정본으로 만들지 않는다.

| 구간 | 현재 배치 |
|---|---|
| 1100px 초과 | 왼쪽 메뉴 238px, 요약 카드 4열, 원자 선택 5열 |
| 768–1100px | 왼쪽 메뉴 유지, 여백 축소, 목록·상세 패널을 세로 배치 |
| 767px 이하 | 상단 메뉴 버튼, 요약 카드 2열, 원자 선택 3열, 보조 카드 1열 |

원자 미리보기의 모바일 모드는 최대 390px로 제한하며 작은 작업 영역에서는 그 폭에 맞춰 줄어든다. 원본 제품 원자의 760px 경계와 센터 화면의 767px 경계는 **적용 대상이 다르다**. 숫자가 다르다는 이유로 합치지 않는다.

## 외관과 기능 분리

이번에 채택한 핵심은 반응형 화면 구조와 메뉴 동작이다. 현재의 연한 바탕·초록 강조·글꼴·아이콘 등 외관은 현행 스킨이며 전 프로젝트의 필수 테마로 확정하지 않는다. 외관을 다듬을 때도 메뉴, 상태 표시, 검색, 미리보기 동작을 유지한다.

## 재사용 시 확인

- 390px 모바일에서 메뉴 열기·항목 선택 후 닫기·본문 이동.
- 767/768px 및 1100/1101px에서 메뉴와 카드 배치 경계.
- 긴 제목·긴 코드·빈 검색 결과가 메뉴나 작업 영역을 밀어내지 않는지 확인.
- 키보드 포커스·선택 상태·미리보기 안쪽 스크롤 확인.

이전 실행 확인은 [브라우저 검증 기록](../../docs/BROWSER-VERIFICATION.md)을 참조한다. 재사용하는 새 프로젝트의 검증을 대신하지 않는다.

등록 시 추가 확인: 767px에서는 메뉴 버튼 표시·탐색 숨김, 768px에서는 메뉴 버튼 숨김·탐색 표시를 실브라우저에서 확인했다. 모바일 메뉴 선택 후 `aria-expanded=false`도 확인했다. Claude의 설명 기반 검토 중 범위·정본 우선순위·파생 숫자 구분을 반영했다. 등록 당시 build-static.mjs에 있던 레이아웃 CSS는 CSS 창고 확장 때 foundation.css로 옮겼다. 동작은 그대로이며 빌드는 그 원본을 읽는다. Cursor·Gemini는 폴더 신뢰 설정 때문에 검토하지 못했으며 기술 검수 전체 상태는 HOLD다.
