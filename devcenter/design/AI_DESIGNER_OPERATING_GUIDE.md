# DevCenter AI Designer 운영 기준

상태: Design Hub 제작 방법론 — AI Core UI/UX 정본에 종속
대상: 디자인 작업자와 AI
목적: 문서·화면·시각자료의 콘텐츠 설계와 제작 순서 안내. 공통 토큰·컴포넌트·브랜드 값을 정의하지 않음

현재 규격 진입점은 `../../docs/UI_UX_START_HERE.md`, 값의 정본은 `../../design-system/`과 제품별 브랜드 원본이다.

> **핵심 원칙**
> Design Hub의 중심은 이미지 생성이 아니라 **디자인 판단**임.
> 원고의 목적과 독자를 이해하고, 정보구조를 설계하고, 실제 브랜드 기준을 적용하고, 대표 시안을 승인받은 뒤 전체 결과물을 일관되게 제작하는 구조로 운영함.

---

## 1. Design Hub 역할

Design Hub는 단순 이미지 생성기나 템플릿 적용기가 아님.

다음 과정을 연결하는 AI 디자인 제작 시스템으로 봄.

`기획 이해 → 정보 위계 설계 → 페이지 구성 → 디자인 방향 설정 → 대표 시안 제작 → 사용자 승인 → Design Lock → 전체 제작 → 검수 → 최종 산출물`

목표는 예쁜 이미지를 만드는 것이 아니라 **실제 업무에 바로 사용할 수 있는 완성도 높은 디자인 결과물**을 만드는 것임.

---

## 2. 적용 대상

특정 회사·브랜드에 한정하지 않음.

- 내부 사업기획안
- 경영 보고서
- 외부 제안서
- 투자·협업자료
- 회사소개서
- 계약서·약관
- 운영매뉴얼
- 체크리스트
- 브로슈어·포스터
- 웹페이지
- 모바일 앱
- ERP/UI
- 인포그래픽
- 기타 업무용 시각자료

문서·화면 종류에 따라 정보밀도와 표현방식을 달리 적용함.

---

## 3. 작업 시작 전 판단

AI Designer는 바로 디자인하지 않고 아래를 먼저 판단함.

### 3.1 목적

- 내부 의사결정용인지
- 외부 제안용인지
- 설명용인지
- 판매용인지
- 계약·증빙용인지
- 화면 UI인지

### 3.2 독자

- 대표이사·경영진
- 직원
- 투자자
- 금융회사
- 고객
- 파트너사

같은 원고라도 독자에 따라 페이지 구조와 톤을 달리함.

### 3.3 핵심 메시지

각 페이지에서 독자가 기억해야 할 메시지를 1개 중심으로 잡음.
페이지 공간을 채우기 위해 내용을 늘리지 않음.

---

## 4. 디자인 전에 콘텐츠 설계부터 함

이미지·PDF·PPT를 바로 만들지 않음.
먼저 페이지 설계안을 작성함.

예:

```text
PAGE 01
- 목적: 사업 전체 방향 설명
- 타입: 설명형
- 제목
- 2~3줄 요약
- 본문
- 핵심정리
- 도식 없음

PAGE 02
- 목적: 사업구조 설명
- 타입: 관계형
- 본문
- 관계도 1개
- 핵심정리

PAGE 03
- 목적: 상품 비교
- 타입: 비교형
- 표 1개
- 보조설명
- 핵심정리
```

**콘텐츠 설계와 디자인 렌더링을 분리함.**

---

## 5. 글 / 표 / 도식 선택 기준

모든 내용을 시각화하지 않음.

### 글로 작성할 내용

- 사업 판단
- 배경과 이유
- 경영자의 관점
- 정책 설명
- 리스크
- 예외사항
- 전략적 의미

### 표로 정리할 내용

- 숫자
- 기간
- 상품조건
- 가격
- 상태
- 확정/미정
- 항목별 비교
- 체크리스트

### 도식으로 표현할 내용

- 순서
- 관계
- 조직구조
- 데이터 흐름
- 업무 흐름
- A → B → C 형태 프로세스

> **판단 원칙:** 글로 읽는 것이 더 빠르면 글로 씀. 도식이 더 빠르게 이해되는 경우에만 도식 사용함.

---

## 6. 과도한 디자인 금지

다음 표현은 기본적으로 지양함.

- 카드 UI 남발
- 아이콘 남발
- 모든 내용을 박스 처리
- 의미 없는 원형 아이콘
- 장식용 자동차·건물·인물 사진
- 과도한 그래디언트
- 장식용 3D 요소
- 의미 없는 일러스트
- 큰 제목으로 공간 채우기
- 모든 내용을 인포그래픽화
- 템플릿 티가 강한 구성
- 유치원 과제처럼 보이는 시각화
- 반대로 지나치게 고전적인 공문서 스타일

디자인 요소는 **내용 이해를 돕는 경우에만** 사용함.

---

## 7. 업무문서 기본 위계

기본 문서 구조는 아래를 우선 사용함.

```text
# 전체 제목

문서 전체를 설명하는 2~3줄 요약

## 번호. 제목

해당 섹션을 설명하는 짧은 요약

본문

필요 시 표 / 도식

> 핵심정리: 한 문장
```

제목과 요약만 훑어도 전체 논리를 이해할 수 있어야 함.

---

## 8. 페이지 규격 먼저 확정

레이아웃 작성 전에 출력규격을 먼저 고정함.

- 내부 기획안 → A4 세로 우선
- 보고서 → A4 세로
- 제안서 → A4 또는 16:9
- 발표자료 → 16:9
- 계약서·약관 → A4
- 모바일 UI → 대상 디바이스 규격
- 웹 UI → 반응형 웹 규격

페이지 수를 먼저 정하고 내용을 억지로 맞추지 않음.

---

## 9. 브랜드 시스템 우선

브랜드 작업에서는 임의 로고·임의 컬러 생성 금지함.

작업 시작 전 실제 브랜드 자료를 우선 확인함.

권장 구조:

```text
design-system/
  brands/
    {brand}/
      brand.json
      logo/
      references/
      approved/
      rejected/
```

`brand.json` 권장 항목:

- 정식 로고/CI
- 주색상
- 보조색상
- 배경색
- 텍스트색
- 제목 위계
- 본문 위계
- 표 스타일
- 여백 규칙
- 헤더/푸터
- 보안표시
- 문서 톤

**브랜드 자료가 확인되지 않은 상태에서 임의 CI를 만들어 사용하지 않음.**

---

## 10. APPROVED / REJECTED 학습

사용자 승인 결과를 가장 중요한 디자인 근거로 사용함.

### APPROVED

승인된 결과물과 함께 아래를 기록함.

- 좋았던 이유
- 레이아웃 특징
- 정보밀도
- 컬러
- 글자크기
- 여백
- 표·도식 사용법

### REJECTED

거절된 결과도 사유와 함께 저장함.

예:

- 카드 너무 많음
- 제목 너무 큼
- 도식 과다
- CI 오류
- 색상 오류
- 이미지 장식 과다
- 문서가 아닌 인포그래픽 느낌
- 본문이 너무 작음
- 템플릿 느낌 강함

다음 작업에서는 APPROVED를 우선 참고하고 REJECTED 패턴 반복 금지함.

---

## 11. 대표 시안 승인 후 전체 제작

전체 문서를 한 번에 만들지 않음.

기본 프로세스:

`원고 분석 → 페이지 설계 → 대표 페이지 1장 제작 → 사용자 검토 → 수정 → 사용자 승인 → Design Lock → 전체 제작`

승인 전 전체 페이지 대량 제작 지양함.

---

## 12. Design Lock

대표 페이지 승인 후 아래 요소를 고정함.

- 로고
- 색상
- 폰트
- 제목 크기
- 본문 크기
- 페이지 여백
- 헤더/푸터
- 표 스타일
- 핵심정리 스타일
- 페이지 번호
- 보안표시

나머지 페이지는 내용에 필요한 배치만 변경함.
페이지마다 디자인 언어가 달라지지 않도록 함.

---

## 13. AI 역할 분리

### 기획 AI / Art Director

- 원고 이해
- 핵심 메시지 추출
- 페이지 분할
- 정보 위계 결정
- 글 / 표 / 도식 선택
- 디자인 방향 제시
- 결과물 비평
- 수정방향 결정

### 제작 AI / Production Designer

- 확정된 설계 구현
- HTML/CSS/PPT/PDF 제작
- 브랜드 규칙 적용
- 정렬·간격·크기 통일
- 텍스트 정확성 유지
- 전체 페이지 일관성 유지
- 수정사항 반영

기획 AI가 확정된 사업내용을 임의로 변경하지 않음.
제작 AI가 디자인 편의를 위해 의미를 왜곡하지 않음.

---

## 14. 이미지 생성 AI 사용범위

이미지 생성은 Design Hub의 보조도구임.

### 적합

- 디자인 방향 탐색
- 대표 페이지 시안
- 표지 비주얼
- 배경 비주얼
- 컨셉 이미지

### 부적합

- 긴 한국어 본문
- 숫자가 중요한 표
- 계약서
- 정확성이 중요한 보고서 본문
- 세밀한 데이터
- 최종 문서 전체를 래스터 이미지 하나로 제작

최종 본문 문서는 가능하면 **HTML/CSS, PPT, PDF, 문서 렌더러 등 텍스트 기반 방식**으로 제작함.

프로젝트별 산출물과 공통 디자인 규칙을 분리함.

## 16. 검수 기준

최종 생성 직후 완료 처리하지 않음.

### 콘텐츠 검수

- 원문 누락 여부
- 숫자 오류
- 제목 오류
- 확정/미정 혼동
- 임의 문구 추가

### 브랜드 검수

- 실제 로고 사용
- CI 색상
- 문서 톤
- 승인 디자인과 일관성

### 시각 검수

- 글씨가 너무 작은지
- 여백 부족 여부
- 표 과밀 여부
- 도식 과다 여부
- 정렬 오류
- 페이지별 스타일 일관성

---

## 17. 품질 기준

좋은 디자인은 화려한 디자인이 아님.

다음 조건을 만족해야 함.

1. 내용을 빨리 이해할 수 있음
2. 중요한 내용이 먼저 보임
3. 페이지마다 목적이 분명함
4. 읽을 부분과 볼 부분이 구분됨
5. 브랜드가 자연스럽게 느껴짐
6. 장식보다 정보가 우선임
7. 실제 업무에 사용할 수 있음
8. 수정·재사용이 쉬움

---

## 18. 사용자 피드백을 공통 규칙으로 승격

프로젝트 피드백 중 반복 가능한 원칙은 Design Hub SSOT에 반영함.

예:

- `도식 너무 많음` → 도식 사용 Gate 강화
- `차 사진 빼라` → 장식 이미지 기본 비사용
- `CI가 틀림` → 브랜드 확인 Gate 추가
- `글씨가 너무 큼` → 제목 위계 수정
- `메일은 승인 후 발송` → 디자인 산출물 외부 전달 전 사용자 최종 승인 필수

특정 프로젝트의 취향을 무조건 공통규칙으로 만들지 않고, 재사용 가능한 원칙인지 검토 후 반영함.

---

## 19. 다른 AI가 작업을 시작할 때

### UI / 앱 / 웹 / ERP 화면

UI/UX 작업은 아래 순서를 먼저 탄다.

1. `hubs/design/README.md`
2. `../registry/design-hub-binding.json` — AI Core canonical source bundle digest 확인
3. pinned AI Core의 `docs/UI_UX_START_HERE.md`
4. pinned AI Core의 `registry/ui-ux-entrypoint.json`
5. 대상 제품 UI profile
6. 해당 브랜드의 실제 CI/브랜드 자료
7. 대상 화면 feature ID
8. Design Job compile
9. Quality Hub 검증

FreePass 계열은 `FREEPASS` 제품 프로필을 명시하지 않으면 작업을 시작하지 않는다.

### 문서 / 제안서 / 기타 시각자료

그 외 Design Hub 작업은 아래 순서로 확인함.

1. `design/AI_DESIGNER_OPERATING_GUIDE.md`
2. `design/README.md`
3. 해당 브랜드의 실제 CI/브랜드 자료
4. 해당 프로젝트 APPROVED / REJECTED 기록
5. 현재 프로젝트 원고와 결정사항

위 자료와 충돌하는 과거 시안·임의 템플릿을 우선하지 않음.

---

## 20. 최종 목표

사용자가 "이 자료 디자인해줘"라고 했을 때 단순 템플릿을 적용하는 시스템이 아니어야 함.

AI가 먼저:

- 문서 목적을 이해하고
- 핵심 메시지를 잡고
- 무엇을 글로 둘지
- 무엇을 표로 만들지
- 무엇을 도식화할지
- 어느 브랜드 스타일을 적용할지
- 어떤 대표 페이지를 먼저 승인받을지

를 판단해야 함.

최종적으로 **사람 디자이너에게 원고와 CI를 전달해 디자인을 맡기는 것과 유사한 경험**을 제공하는 것이 목표임.

---

## 핵심정리

**Design Hub의 핵심은 이미지 생성이 아니라 디자인 판단임.**

`내용 이해 → 정보구조 설계 → 브랜드 적용 → 대표 시안 승인 → Design Lock → 전체 제작 → 검수` 순서로 운영함.

어떤 작업자나 AI가 사용하더라도 이 방법론은 AI Core UI/UX 정본과 대상 제품의 현재 브랜드 원본에 종속됨.
