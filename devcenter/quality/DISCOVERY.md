브라우저 DISCOVERY 검사는 보호 유무에 따른 결과, 초안 보존과 수동 병합, 동일 이벤트 배치 안의 두 클릭, 검색·필터 초기화, 학습 전용 상태, 계획 클립보드, 코드 사본 조회, HTTP 503 재시도, source와 sha를 같이 바꾼 자기일치 사본 거부, 1440/390 레이아웃을 확인한다. 새 체크는 기존 50개 분모 밖의 확장 검사다.

빌드는 학습 모델 원문을 한 번 고정해 실행 코드와 코드 사본 양쪽에 사용한다. 실행 묶음에는 모델 SHA를 삽입하고 표시용 사본을 이 값과 대조한다. 빌드 중 원문이 바뀌면 출력 교체 전에 중단한다. 이 방식은 실행 묶음·표시 사본의 버전 일치 확인이며, 서버가 침해되어 둘 다 바뀌는 상황의 위변조 방지나 원본 규격의 현행 승인을 보증하지 않는다.

## 독립 검토와 판정

입력 SHA는 discovery-review-inputs.json, 실제 Claude 응답은 discovery-claude.md다. 수정 전 정적 검토이며 최종 수정본의 전체 승인을 뜻하지 않는다. 도구·원문 접근 없이 학습 코드 두 파일을 검토했다.

반영: 표시 사본만 자기 체크섬을 검사하던 방식 → 실행 묶음에 고정한 SHA와 교차 확인; 초안 삭제 → 초안 보존·원본 비교 후 병합; 렌더 클로저 계산 → 한 상태 객체의 순수 함수형 갱신; 중간 보호 전환 → 실험 상태 초기화와 안내; 필터와 상세 불일치 → 필터 안의 선택으로 제한; 버전 번호 접근성 설명 연결; 검색 대소문자·공백 정리; secure-context 요구 설명.

기각/정정: 멱등성 키를 소문자·trim으로 통합하라는 제안은 채택하지 않았다. 키는 불투명한 작업 식별자이며 정규화가 다른 작업을 합칠 수 있어 정확한 문자열 일치로 유지하고 동작을 설명한다. 렌더 클로저 계산이 곧바로 중복 ID 배열을 만든다는 주장은 정적 코드만으로 성립하지 않는다(통째 대입은 마지막 갱신이 덮어쓰는 양상). 그 주장 자체를 재현 완료로 쓰지 않고, 실제 같은 배치의 두 클릭을 검사하고 함수형 갱신으로 보완했다. 금액/권한/저장 계약 전체로 확대하지 않았다.

Cursor와 Gemini는 이번 실제 비대화형 호출 모두 종료 1로 실패했다. Cursor는 Workspace Trust Required, Gemini는 trusted directory 제한이다. reviews/discovery-cursor-error.txt 및 discovery-gemini-error.txt에 실제 응답을 보관한다. 정책을 우회하지 않았으며 전원 검수는 HOLD다. 원문·재현 결과가 AI 의견보다 우선한다.
