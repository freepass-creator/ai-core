# 개발센터 완성도 — 집계 원칙

2026-09-09: 이전 대화에서 제시한 영역별 70/30/20/45/15%와 전체 약 30%는 완료 기준·검증된 분모 없이 제시한 추정이었다. 공식 지표로 사용하지 않고 철회한다.

사용자 목표: 다섯 영역의 평균을 최소 70%까지 올린다. 목표 수치는 결과값이 아니다.

## 서로 다른 두 지표

센터의 기능 구현률: 확정한 수집·검색, 규격 정돈·표준화, 기능 재사용, 보여주기·체험, AI 학습·실습·평가의 인수 조건을 실제로 통과한 비율이다. 영역별 분모와 완료 조건을 먼저 확정하고 계산한다.

전체 자산의 정돈·검증률: 조사 범위에 있는 원본 자산 중 적용 범위·설명·실행 예제·실패 사례·검증·사용법과 필요한 검토를 갖춘 비율이다. 함수 선언 수와 독립된 업무 기능 수는 다르다. 사본·내부 함수·익명 콜백·미지원 형식도 별도로 센다. 작은 카드 묶음의 완성도를 전체 자산의 완성도로 바꾸어 부르지 않는다.

2026-09-09 사용자의 계속 진행 지시에 따라, 센터 v1 인수 기능은 acceptance-v1.json의 5개 영역 × 10개 조건으로 고정한다. 이는 이번 작업에서 정한 공개 인수 기준이며 전체 자산의 검증률을 대신하지 않는다. 기준 파일을 변경하면 새 버전으로 검토해야 한다. 전체 자산의 의미 검증 분모는 여전히 미확정이며 그 완성률은 미산정이다.

센터 인수 기능의 각 영역 비율은 실제 PASS 수 / 10이다. 다섯 영역을 같은 비중으로 평균한다. 미구현·미검증·HOLD를 분모에서 빼지 않는다. 필요한 전체 역할 검수 상태는 평균과 별도로 표시한다. 숫자를 만들기 위해 완료 조건을 사후 축소하거나, 새 카드 수를 전체 자산 수로 대체하거나, 읽기/타입검사를 실행·업무 의미 검수로 올려 세지 않는다.

## 지금 집계할 수 있는 사실

규격 카드의 총 등록 수, 필수 내용의 작성 수, 고정한 원본과 현재 해시가 일치하는 수, 연결된 검사에 이번 실행 증거가 있는 수, 필요한 독립 검토를 완료한 수를 각각 공개한다. 단계별 수는 서로 더하지 않는다. 한 카드에서 검사 하나를 통과했다고 그 카드 전체를 승인하지 않는다.

원본이나 검사 입력이 바뀌면 과거 검사 증거는 오래된 것으로 표시한다. 증거에 실패·미실행·접근 불가가 있으면 통과로 집계하지 않는다. 증거의 날짜·검사 범위·출처를 함께 표시한다.

현재 브라우저는 검사/빌드 시점 스냅샷이다. 실행 중인 원본 파일을 실시간 감시하지 않는다. `node scripts/card-audit.mjs --verify`로 검사를 실행하고 다시 빌드해야 화면이 갱신된다. `--report <경로>`는 기존 증거의 입력 해시를 재대조하며 검사를 새로 실행하지 않는다.

학습 문제의 정답 수는 해당 이해 문제에 대한 결과다. AI의 개발 능력 인증이나 실무 적용 합격으로 표시하지 않는다. 실제 작업 계획·코드·원본 대조·독립 검토는 별도다.

근거: quality/acceptance-machine.json, quality/acceptance-browser.json 및 portal/static/catalog/acceptance.json. sourceDigest는 센터 구현·검사 파일·카드와 원본·수집 스냅샷·시험 패키지에 묶는다. 브라우저 근거는 app.js 해시도 대조한다. 스냅샷 이후 파일 변경은 다시 집계·빌드해야 반영된다.

재현: node scripts/card-audit.mjs --verify → node scripts/verify-portable-package.mjs → node scripts/verify-acceptance.mjs → node portal/build-static.mjs. 브라우저 검사는 실제 화면에서 재실행하고 acceptance-browser.json에 해당 입력·관찰·현재 해시를 기록해야 한다. 파일의 PASS 문구만 새 버전으로 옮기지 않는다.
