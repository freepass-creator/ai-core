코드만 읽고 검토했습니다. 실행·수정은 하지 않았습니다.

## 상 — 잘못 가르치는 것

**1. 자기 자신을 검증하는 해시 (`discovery.tsx` useEffect)**
`discovery-source.json` 안의 `source`를 같은 파일 안의 `sha256`과 비교합니다. 파일을 바꾸는 쪽이 해시도 같이 바꾸면 언제나 통과합니다. 무결성이 아니라 **파일 내부 정합성**만 확인하는 것인데, 화면에는 "실제 코드와 출처 · SHA-256"으로 제시됩니다. 더 큰 문제는 표시되는 코드가 실행 중인 `discovery-model.ts`의 *복사본*이라는 점입니다 — 빌드가 누락되면 옛 코드가 유효한 해시를 달고 "실제 코드"로 표시됩니다. 비전문가에게 "해시가 맞으니 이 코드가 맞다"는 잘못된 판단 근거를 줍니다.
→ 최소 수정: 문구를 "빌드 시점 사본의 자기 체크섬(위변조 검증 아님)"으로 낮추고, 빌드 스크립트가 원본 파일 해시와 대조하도록.

**2. 동시성을 가르치는 세 실험이 모두 stale state로 갱신합니다**
`setState(startSearch(state,query))`, `setLedger(r.ledger)`, `setDoc(r.document)` — 전부 렌더 클로저의 값을 읽어 계산한 뒤 통째로 덮어씁니다. 함수형 업데이터(`setState(s=>...)`)가 아닙니다. 한 배치 안에서 두 번 호출되면 같은 `state`를 읽어 `pending`에 **같은 id가 두 개** 생기고, 이후 `finishSearch`의 `filter(r=>r.id!==id)`가 둘 다 지웁니다. React key도 중복됩니다. OnceLab은 `DEMO-${rows.length+1}`이 같은 값을 두 번 만들어 `key={r.result}`가 겹칩니다. 낙관적 동시성·경합을 가르치는 화면이 정확히 그 버그를 갖고 있습니다.

**3. "원본 다시 읽기"가 초안을 지우면서 "이전 초안과 비교하라"고 말합니다 (VersionLab)**
버튼은 `setA(doc.value)`로 입력을 원본 값으로 덮어쓰는데, 같은 클릭의 메시지는 "이전 초안과 비교 후 새 내용을 작성하세요"입니다. 비교할 초안이 방금 사라졌습니다. `gate`도 "충돌 후 재조회·차이 검토"를 요구하지만 모델에 차이 검토가 없습니다. 충돌 해결의 핵심(내 변경 보존 + 병합)을 가르치지 못하고 반대 습관을 학습시킵니다.

## 중 — 무효 동작 · 경계 누락

**4. 멱등성 키에 정규화가 없습니다 (`submitOnce`)**
`r.key===key` 완전 일치입니다. `request-001`과 `request-001 `(뒤 공백), 대소문자 차이가 별개 키가 되어 **보호를 켠 상태에서도 중복 기록이 생깁니다.** 학습자는 멱등성이 실패했다고 오해합니다. `value`/`payload`도 `trim()`으로 검사만 하고 원본 그대로 저장합니다.

**5. 보호 스위치를 도중에 껐다 켜면 거짓 결과가 나옵니다**
- OnceLab: 보호를 끈 채 같은 키로 3건 만든 뒤 켜면, `find`가 첫 행만 찾아 "기존 결과 재사용 · DEMO-1"이라고 표시합니다 — 화면에는 중복 3건이 그대로 보입니다.
- RaceLab: 주석대로 보호가 **응답 도착 시점**에 적용됩니다. 실제 가드는 요청 시점에 고정되며(클로저에 잡힌 id), 나중에 소급 변경될 수 없습니다. 정직하게 고지는 했지만 잘못된 심상을 남깁니다.
→ 스위치 변경 시 해당 실험 상태를 초기화하는 편이 안전합니다.

**6. `crypto.subtle` 미존재 경로가 없습니다**
HTTPS/localhost가 아닌 곳(사내 IP의 http)에서 `crypto.subtle`은 `undefined`이고, `.digest` 접근이 TypeError를 던집니다. `e.message`가 그대로 노출되어 비전문가에게 "Cannot read properties of undefined"가 보이고, "다시 읽기" 버튼은 영원히 실패합니다. `r.ok` 통과 후 HTML 폴백이 오는 경우의 JSON 파싱 오류도 같은 경로입니다.

**7. 필터가 선택 항목을 감춰도 우측 패널은 그대로입니다**
`filtered`에서 빠져도 `topic=topics.find(t=>t.id===selected)!`는 계속 이전 항목을 보여줍니다. 목록이 비었을 때조차 상세 패널에 "동시 수정 충돌"이 남아, 어떤 항목이 선택된 상태인지 알 수 없습니다.

## 하

**8. `aria-label`이 감싼 `<label>` 텍스트를 덮습니다.** `<label>AI A · 읽은 버전 v1 <Input aria-label="AI A 수정 내용"/></label>` — 스크린리더는 `aria-label`만 읽으므로 **버전 번호가 전달되지 않습니다.** 이 실험의 핵심 정보입니다. 키보드·접근성을 주제로 가진 포털이라 더 눈에 띕니다. 모든 랩에 반복됩니다.

**9. 검색 필터가 대소문자 구분·미trim이고 `title/term/scene`만 봅니다.** 플레이스홀더는 "겪는 문제나 기술 이름"인데 `group`·`sourceName`·`question`은 검색되지 않고, 뒤 공백 하나로 결과가 사라집니다.

**10. 실험 상한이 제각각입니다.** OnceLab 30건, RaceLab 대기 10개, VersionLab은 무제한. 상한 도달 시 안내가 예외 메시지로만 나옵니다.

## 확인해서 문제 없던 것
9개 항목의 `live` 개수(3/6)와 상단 안내 문구 일치, 각 `source` URL과 `term`의 대응(412·Stripe 멱등·useEffect의 `ignore` 플래그·WCAG 키보드 등), `saveVersion`의 `MAX_SAFE_INTEGER`·정수 검사, `AbortController`의 `signal.aborted` 가드(비동기 digest 이후 검사까지 포함), 클립보드 실패 폴백 문구.
