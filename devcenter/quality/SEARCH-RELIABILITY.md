# 전체 기능 검색 안정성 보완

- 요청: 억지로 범위를 늘리지 않고 실제로 필요한 부분을 개선한다.
- 범위 / 위험: 낮음. 기존 FunctionSearch 단일 컴포넌트의 조회·입력 처리와 회귀검사. 데이터 쓰기·권한·외부 전송 없음. core SSOT 및 승인 기준 변경 없음.
- 정본: C:/dev/devcenter/portal/app/function-search.tsx, main 작업 트리. 이전 학습·실험 변경은 그대로 보존한다.
- 재사용: 기존 검색 색인과 Input/Button, 기존 학습 패널 스타일, 기존 브라우저 검사기.

## 발견과 수정

1. 요청 대기 중 검색어가 바뀌어도 이전 요청이 결과를 덮어쓸 수 있었다. 검색어 변경과 재요청·화면 이탈 때 이전 요청을 취소하고, 요청 순번이 현재와 같은 경우에만 결과·오류·로딩 상태를 반영한다.
2. JSON을 검증 전에 캐시에 넣어, 잘못된 모듈 참조나 형식이 들어오면 다음 검색도 같은 캐시를 재사용했다. 모듈·항목 튜플, 문자열, 모듈 인덱스 범위, 양의 행 번호를 검사한 후에만 저장한다. 오류 후 검색은 원문을 다시 받는다.
3. Enter 키로 검색할 수 없었다. 기존 검색을 form 제출에 연결했다. 검색어 변경 즉시 옛 결과를 지우고, 표시 결과에 검색어를 함께 쓴다.

## 검증

scripts/verify-browser.cjs의 SEARCH_RECOVERY는 잘못된 참조 색인을 받은 뒤 같은 화면에서 재시도하여 성공하는지, Enter 제출, 짧은 검색어 거부, 검색어 변경 시 결과 제거를 확인한다. 실제로 늦은 응답이 JS에 도착하도록 테스트 브라우저에서만 해당 fetch의 AbortSignal을 무시시킨 뒤 요청 순번으로 옛 결과가 배제되는지 검사한다. 운영 앱의 취소 동작은 유지한다.

타입 검사·빌드·기존 브라우저 회귀검사와 기존 인수 증거를 갱신한다. 새 검사 이름은 고정 50개 조건의 분자에 추가하지 않는다. 단일 가역적 조회 컴포넌트 수정이므로 이번에는 결정론적 실행 증거로 확인하며 외부 AI 합격을 주장하지 않는다. 개발센터 전체의 기존 전원 검수 HOLD는 유지한다.

GitHub 반영은 기존 index.lock 제한으로 미완료인 작업 트리 상태를 이어받았다. 잠금 삭제나 우회를 수행하지 않는다.

최종 결과: 타입 검사·빌드 통과, 브라우저 31개 체크 PASS(SEARCH_RECOVERY 포함), 관련 기존 회귀검사 통과. 고정 인수 결과는 41/50=82%로 유지했다. .git/index.lock 존재를 다시 확인했으며 GitHub 반영은 미완료다.
