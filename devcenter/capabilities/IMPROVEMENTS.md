# 기능 창고 — 오류·부족·개선 기록

2026-09-09 사용자 요청: 기존에 쓰는 기능을 수집하고 부족·오류 항목을 개선한다. 기존 1차 문서의 기능 수집 범위를 이번 요청으로 확장한다. 기존 프로젝트의 정본은 제자리에 유지하며 운영 배포·민감 데이터 변경은 별도 실행 범위를 따른다.

## F001 — 오류가 있는 TypeScript도 정적 빌드가 만들어지는 문제

원본: devcenter/portal/build-static.mjs. 기존 포장기는 transpileModule을 사용하고 사전 타입검사를 하지 않았다. 직전 견학 작업에서도 잘못된 TSX의 타입검사는 실패했지만 build 명령은 성공하는 증거가 남았다. build 단독 실행 시 잘못된 코드가 출력 폴더를 교체할 수 있었다.

개선: devcenter/scripts/typecheck-gate.mjs에서 기존 두 tsconfig를 검사하고 오류면 출력 생성·교체 전에 중단한다. 기존 원본 해시 검증과 완성된 출력의 교체 방식은 유지한다.

확인: scripts/verify-typecheck-gate.mjs는 별도 임시 폴더에서 타입 불일치 거부, 정상 코드 허용, 구문 오류 거부를 재현한다. 실제 빌드와 테스트 결과는 이번 실행 기록에서 확인한다. 이 항목은 다른 프로젝트 전체의 합격을 뜻하지 않는다.

실행 결과(2026-09-09): 기존 transpile-only 방식이 놓치는 타입 오류를 재현했다. 모듈 간 타입 오류·구문 오류·없는 설정 파일은 거부, 정상 소스와 실제 두 설정은 통과했다. 실제 포장기 코드를 별도 임시 폴더에서 실행했을 때 오류로 종료하고 새 staging 폴더를 만들지 않았으며 기존 출력 표식도 유지했다. 원자 미리보기 진입점도 tsconfig.gallery.json의 검사 대상에 포함했다.

## F002 — Python 한글 경로를 읽을 때 수집 오류

원본: 이번에 추가한 scripts/function-python-index.py. Windows 기본 표준입력 인코딩으로 Node의 UTF-8 경로 목록을 읽으면 한글 파일 경로가 달라져 읽기에 실패했다.

개선: Python 표준입력 인코딩을 UTF-8로 고정한다. 한글 경로 fixture로 회귀 확인하며, 수집기의 오류를 대상 프로젝트 오류로 오인하지 않는다.

실행 결과(2026-09-09): 한글 Python 경로, 주석·문자열의 가짜 함수 제외, 기본값 리터럴 비게시, 상대경로 연결·중복 제거, 미해결 별칭, 구문 진단, 동일 파일 해시, 실행 미검증 상태의 회귀검사를 통과했다.

## 이번 수집과 검증의 범위

2026-09-09 스냅샷: 70개 폴더, 27,453개 파일, 163,133개 함수 선언. 파일 내용 해시는 5,446종이며 사본을 포함한 수치다. 익명 콜백 등 별도 등록하지 않은 함수 구문 267,244개, 파일만 등록한 미지원 형식 110개, 구문 진단 1개, 읽기 오류 0개다. 최신 수치는 재수집한 브라우저 자료를 확인한다. aiops는 일반 코드 폴더 허용 목록을 사용하고, 민감 경로·생성물·SSOT 작업 사본은 제외했다.

원본 freepasserp4/lib/format.ts의 kmValue와 fileSizeText 예시 11건을 실행해 통과했다. 원본 해시는 01c53a801932331974e0b62d36c1587770225992d796c940e2e2bd6914d73b19다. 브라우저 검색·참조 복사·빈 결과·두 함수의 입력 변화도 확인했다. 나머지 선언의 업무 의미·실행 검증은 미완료다.

Claude 설계/코드 자문은 원본 보존·실행 여부 구분에 동의했고, 누락 수치·인코딩·실제 빌드 중단 검증을 보완하도록 지적했다. 해당 항목을 반영했다. 원문 SHA를 개행 정규화 해시로 바꾸자는 제안은 원본 바이트의 동일성 증거를 유지하기 위해 적용하지 않았다. 현재 설정에 없는 emitDeclarationOnly 충돌은 실제 기본 설정 검사 통과와 대조해 현행 결함으로 채택하지 않았다. 마지막 테스트 보완본의 재승인으로 이전 자문을 옮겨 적지 않는다.

Cursor와 Gemini는 이번 읽기 전용 호출도 작업 폴더 신뢰 설정에서 종료했다. 네 역할 전체 검수 상태는 HOLD이며, 수정한 센터 기능의 검사 통과와 구분한다. 실제 응답·최종 파일 해시·세부 검증 이력은 로컬 reviews/functions-*에 남긴다.

## 확인할 과제

수집 시점의 구문 진단 후보: sheetops/codex/make_v2.py, L116 (Python 구문 진단). 실제 실행 대상·사용 Python 버전·현역 여부를 확인하기 전까지 원본 수정과 오류 확정을 보류한다. 이 파일의 원문 내용은 창고에 게시하지 않는다.

- 구문 진단 파일: 프로젝트의 실제 도구·언어 버전으로 재현한 뒤 수정 여부를 결정한다. 수집기 진단만으로 운영 원본을 자동 수정하지 않는다.
- 입력·출력의 업무 의미, 단위·빈값·오류·권한·부작용: 선언 목록만으로 알 수 없다. 함수별 원문·사용처·테스트를 연결하는 후속 검토 대상이다.
- 별칭 경로·동적 호출·재수출·Python 소비 관계: 아직 해석하지 못하므로 미사용으로 판정하지 않는다.
- Vue/Svelte/PowerShell/Shell: 파일 위치는 등록하지만 내부 기능 해석은 미지원이다.
- 같은 내용의 사본: 해시로 모아 보여주되 현역·정본·통합 여부는 원본과 적용 범위를 확인한다.

## 변경 기록 방식

각 개선에는 원본 경로·변경 전후 버전, 재현 입력과 기대/실제 결과, 영향받는 사용처, 수정 내용, 실제 실행한 검사와 남은 항목을 기록한다. 위험에 맞는 독립 검토를 받는다. 발견 → 재현 → 수정 → 검증 상태를 구분한다. 기능 창고의 모든 선언은 별도 실행 근거를 붙이기 전까지 정적 수집 상태다.
