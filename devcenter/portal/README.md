# 개발센터 브라우저

기존 개발 규격의 출처·규칙·실제 UI를 한곳에서 확인하는 **검토 중인 기준 카탈로그**다. 전체 의미 통합·대표 승인 완료가 아니다.

## 사용

- 원자 실험실: 원본 FP4 버튼, 입력, 드롭다운, 표, 박스, 토큰을 예시 상태로 실행한다.
- 만드는 규칙: SSOT → 계약 → 기존 원자 → 조합 → 검증 → 인계의 기본 흐름과 13개 원자 규격의 원문/소비 코드 대조.
- 전체 규격 찾기: 프로젝트·주제·검색, 원문 위치/행/해시.
- 충돌과 확인 과제: 발견된 불일치. 전수 결함 목록이라고 주장하지 않는다.
- 조사 범위와 근거: 제외 범위, 작업 사본 포함 여부, 조사 분모.

## 정본과 파생물

정본은 각 원본 저장소다. `public/catalog`의 발췌와 `static/`은 원본의 특정 시점에서 만들어진 **파생 자료**다. 정책 정본이 아니며 이 파일을 편집해 원본을 바꾼 것으로 취급하지 않는다. `static/source-manifest.json`이 미리보기 원본 9개 파일의 SHA-256을 고정한다. 다음 빌드에서 원본이 바뀌면 중단한다. 원문을 다시 검토한 뒤에만 `node build-static.mjs --refresh-sources`를 실행한다. 게시 화면이 로컬 원본 변경을 실시간 감지하는 것은 아니다.

제품 전체의 테마/provider/업무 데이터는 실행하지 않는다. 예시는 저장·API·햅틱을 호출하지 않는다. 원본의 차이를 센터가 임의의 글로벌 수치로 합치지 않는다.

## 재생성

`npm ci --ignore-scripts`, `npm run typecheck`, `npm run build`, `npm run dev` 순서. 타입검사와 빌드는 해시가 고정된 `public/catalog/source-code.json`과 `styles.json`에서 임시 소스 트리를 복원하므로 형제 저장소 checkout이 필요하지 않다. 새 원본을 반영할 때는 해당 카탈로그를 원본 저장소의 exact revision에서 먼저 갱신·검토해야 한다. `static` 출력만으로는 Python 등 일반 정적 서버에서 표시할 수 있다. 파일 더블클릭은 fetch 제한 때문에 지원하지 않는다.

전체 후보 재색인은 상위 저장소에서 `python scripts/scan-standards.py`로 수행한다. 이는 C:/dev의 허용 개발 문서·코드를 읽는다. 제외 범위는 스크립트와 브라우저에 명시했다. 외부·운영 원본은 수정하지 않는다.

네이티브 빌드 도구가 Windows Application Control에 차단되어 순수 JavaScript/TypeScript 정적 생성기를 사용한다. 보안 정책은 변경하지 않았다. 타입 검사는 센터 UI에 한정한다. 원본 제품 전체의 타입 검사/운영 검증 통과를 의미하지 않는다.

## 검수 상태

Codex는 실브라우저 버튼/입력/선택/표/검색/모바일을 확인했다. Claude는 설명 기반 PM 검토를 했으며 실행본 합격이 아니다. Cursor/Gemini는 현재 workspace trust 미설정으로 비대화형 검토가 거절되었다. 따라서 네 역할 전체 게이트와 전체 규격 승인 상태는 **HOLD**다.
