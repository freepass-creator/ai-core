# 프로젝트 시작틀 — 후보와 제작 원칙

상태: **후보 정리, 실제 템플릿 파일 미구현**. 기존 `틀/README.md`의 고유 내용을 후보 안내 문서로 정리했다. 이 문서는 시작틀의 정본 지정이나 후보 승인이 아니다.

대표(2026-09-09): 「어떤 개발을 하기 전에 그 내용을 갖고와서 틀로 삼고 시작하게끔」

시작틀은 프로젝트를 시작할 때 가져가서 채우는 파일이다. 실행 도구인 루트 `틀.mjs`, 디자인 원자, SSOT 검사기와 역할이 다르다. 기존 시작틀이 있다면 새로 만들지 않고 [통합 등록부](../../registry/devcenter-datasets.json)에서 원본을 가리킨다.

## 후보 — 아직 채택하지 않음

| 후보 | 초기 문서의 조사 단서 | 다음 확인 |
|---|---|---|
| 프로젝트 AGENTS.md 뼈대 | `freepasserp4/AGENTS.md` | 현역 원본·적용 범위 확인. `_base`(2026-08-29 멈춘 워크트리)는 «보관»이라 쓰지 않는다 |
| 프로젝트 CLAUDE.md 뼈대 | `freepasserp4/CLAUDE.md` | 현재 등록부와 원본 비교 |
| 화면 작성 체크리스트 | `freepasserp4/CLAUDE.md` 내부 | 기존 규격을 참조하는 빈 양식이 필요한지 판단 |
| 신규 저장소 초기 구조 | 초기 조사 당시 존재 미확인 | 전수 수집 결과에서 기존 구현 확인 후 결정 |

## 기존 문서에서 보존한 제작 원칙

- 실제 시작틀에는 사용자가 채우는 빈 칸이 있어야 한다. 예시를 그대로 복사해 확정 값처럼 쓰지 않는다.
- 규격의 값과 문장을 시작틀에 복제하지 않는다. 원본의 위치·범위·버전을 참조한다.
- 다른 곳에 없는 시작틀만 신규 제작 후보로 삼는다.
- 신규 시작틀을 채택하면 원본 위치와 상태를 등록부에 등록한다. 후보를 승인된 정본으로 자동 등록하지 않는다.

## 기존 규격 찾기

```powershell
node C:\dev\devcenter\틀.mjs dev.design.token
```

현재 `틀.mjs`는 규격 검색과 경로 확인 도구다. 한글 별칭 검색이나 템플릿 생성은 구현하지 않았다. 초기 안내의 `디자인` 검색 예시는 실제 지원되는 scope 검색으로 바로잡았다.
