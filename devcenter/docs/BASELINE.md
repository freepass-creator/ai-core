# 개발센터 기본 규격 v0.1

기준: 2026-09-09 사용자 지시와 현재 원본. **1차 참조용 기본 규격**이다. 기존 승인 원본을 찾고 적용하기 위한 입구이며, 이 문서만으로 규격 준수/합격을 판정하지 않는다. 공통 원칙을 적용하되 프로젝트의 확정 업무 규칙·수치·권한을 새로 정의하지 않는다. 충돌 부분은 아래 목록에 남기며 전체 4-AI 검수는 아직 HOLD다.

## 0. 적용 우선순위

사용자의 현재 명시 지시 → 대상 범위의 승인된 원본 → 재현 가능한 검증 → 로그 → AI 의견. 코드가 현재 동작한다는 이유만으로 승인 기준을 바꾸지 않는다. 문서끼리 또는 문서와 코드가 충돌하면 해당 항목을 HOLD하고 원본·승인 근거로 해소한다. 나머지 확인 가능한 조사와 문서 정리는 계속할 수 있다. [출처 S01~S06, S09](baseline-sources.json)

## 2. 디자인 기본 규격

- **공통으로 통일할 것은 원본 사용 방식이다.** 전 프로젝트의 버튼 높이·라운드를 현재 임의의 하나로 합치지 않는다.
- fp4 작업은 [현재 규격 목록](CURRENT-STANDARDS.md)의 FP4 프로필과 기존 `@/components/ui` 진입점을 먼저 확인한다. 컴포넌트의 입력·상태·모바일 처리와 의존성은 실제 코드로 확인한다.
- 직원 워크 ERP 작업은 WORK-ERP 범위의 규격을 참조한다. 원본/사본 귀속 미확정 항목을 명시한다.
- 신규 프로젝트는 기존 프로필 중 적용할 것을 범위에 명시한 뒤 시작한다. 임의 글로벌 기본값이나 타 프로젝트의 승인된 규칙을 덮는 값을 만들지 않는다.
- 색·글꼴·높이·간격·모서리·아이콘은 해당 프로필의 원본 토큰/규격에서 가져온다. 이 문서에 원본 값 전체를 복제하지 않는다.
- 버튼·드롭다운·표·박스는 기존 부품을 찾아 선택한다. 이름이 있다는 사실만으로 접근성·사용성·실행 합격으로 취급하지 않는다.

## 3. 기능 기본 규격

기능은 기존 엔진/모듈의 책임과 입력·출력·단위·오류·권한·소비자를 확인하고 사용한다. 화면에서 계산·상태 변경 규칙을 별도로 만들지 않는다. 외부 자료 수집이 승인된 의미 범위를 넓히지 않도록 한다. aiops의 업무 엔진과 정본을 개발센터에 복사하지 않는다. 같은 이름이나 같은 입력 타입만으로 기능을 합치지 않는다. 통합 패키지/연동 엔진 제작은 2차다.

## 4. 검증과 네 AI

센터 PM은 Claude, Codex는 구현/재현/증거 통합, Cursor는 자산/코드/소비 경로, Gemini는 구조/참조/사본 관계를 맡는다. 대상 프로젝트의 기존 역할 규칙과 다르면 작업 범위를 구분하고 임의 덮어쓰지 않는다. 적용 정족수는 [공동 작업안](FOUR-AI-WORKFLOW.md)이 참조하는 현행 규칙에 따른다. 본 문서는 새 정족수나 도구 권한을 만들지 않는다.

1차 규격 작성 검증은 출처 존재·버전 재대조·누락/충돌·상호 링크·작업 범위 확인이다. 전 프로젝트 빌드·배포·자동 검사를 이번 문서 작성의 완료 증거로 주장하지 않는다.

## 6. 업데이트

원본 변경을 발견하면 원본 해시와 영향을 다시 확인하고 출처 목록/관련 절만 갱신한다. 새 기본 규격을 계속 만들지 말고 이 문서의 버전을 올린다. 원문의 의미 변경·규격 통합은 승인된 범위에서만 한다. [1차 범위](PHASE1-SCOPE.md) 밖 고도화는 별도 작업이다.

## 이번 문서 검토 상태

Codex는 원본 발췌·export·경로와 21개 해시의 재대조를 수행했다. Claude는 비민감 요약 기반으로 조건부 OK(확인 범위 라벨·충돌값의 기본값 유입 방지·결손 목록)를 회신했다. 해당 표시를 반영했다. Cursor/Gemini는 이번 요청도 신뢰 제한으로 미검토(종료 1/55). 따라서 문서 작성과 출처 검사는 완료했지만 전원 최종 규격 검수는 HOLD다.
