# 네 AI 공동 작업 실행안

사용자 요청: 문제·개선·통일 항목을 개발센터에 남기고 네 AI가 같이 움직인다. 이 문서는 현재 역할 규칙을 실행에 연결하는 작업안이다. 자동 스케줄러/외부 발송/권한 변경을 켜지 않는다. 적용 규칙의 정본은 AGENTS.md와 ssot/PART.md의 참조이며 여기서 정족수를 새로 정하지 않는다.

## 역할

| 역할 | 담당 | 결과 |
|---|---|---|
| Claude Code / PM | 목적·범위·우선순위·충돌 정리, 요구사항 반례 검토 | 작업 패킷·결정 필요 항목·게이트 의견 |
| Codex | 구현·연결·반례 재현·테스트·증거 통합 | 변경 diff·실행 증거·잔여 위험 |
| Cursor Agent | 기존 자산 수집·실제 소비 경로·정적 분석·회귀 누락 | 경로/버전 근거와 누락·중복 후보 |
| Gemini CLI | 자료 구조·참조·사본 관계·의미/버전 혼용 검토 | 관계 불일치·소유자/범위 확인 항목 |

## 한 작업의 순서

1. PM이 issue ID, 목표, 허용 범위, 원본 참조와 버전/hash, 완료 조건을 고정한다. 사용자 확정 기준을 임의로 만들지 않는다.
2. 같은 기준의 필요한 자료를 각 역할에 보낸다. 첫 의견은 다른 AI 결론 없이 독립 작성한다. 개인정보·고객 원문·인증정보는 보내지 않는다.
3. Codex가 반례를 재현하고 원본/요구사항 > 재현 테스트 > 로그 > AI 의견 순서로 이견을 정리한다. 찾거나 구현한 사람만으로 합격시키지 않는다.
4. 변경 담당은 하나로 지정한다. 다른 AI는 기본 읽기 전용이다. 같은 파일의 별도 작업은 작업 ID와 변경 목록으로 드러내고 덮어쓰지 않는다.
5. 최종 diff/hash가 바뀌면 해당 최종 버전으로 필요한 검토를 다시 받는다. 응답 없음·실행 실패·조건부 의견을 무조건 OK로 세지 않는다.
6. 적용되는 센터/SSOT 검수 규칙과 알려진 중대 오류 여부로 최종 gate를 기록한다. 원본 확인이 안 되거나 중요한 이견이 남으면 HOLD.
7. 승인 필요한 실제 반영은 대상·범위·사용자 승인을 확인한 뒤 실행하고 결과를 다시 읽는다. 문제가 재발하면 원인과 재현 검사를 해당 issue에 연결한다.

## 최소 작업 기록

`task_id / issue_ids / objective / scope / source_refs / revisions / owner / allowed_actions / acceptance / reviewer_requests / reviewer_results / changes / evidence_refs / unresolved / next_action`

실행 상태(pending/running/blocked/completed)와 검사 상태(PASS/HOLD/FAIL)는 다르다. 조회·인계 화면은 같은 run을 참조한다. 고객자료·토큰 없이 필요한 근거를 보존한다. 도구 요청/응답/판정의 원본은 로컬 제한 저장, 저장소에는 검토 가능한 요약을 남긴다.

## 이번 연결 상태

Codex가 현재 관찰과 보고서를 작성했다. Claude 검토 요청 및 Cursor/Gemini 실제 요청 결과는 이번 보고서 검토 기록에 남긴다. 최근 두 도구는 작업폴더 신뢰 제한으로 실패했다. 사용자의 신뢰 변경 허용 없이 우회하지 않는다. 현재 자동 공동 실행/전원 최종 OK는 완료되지 않았다.

## 첫 공동 작업

[개선 리포트](IMPROVEMENT-REPORT.md)의 DC-003/004를 먼저 배정한다. 이동 최종 경로·코드 허용목록·원격 참조를 대조하는 작은 작업으로 네 역할의 실제 입력/출력 연결부터 확인한다. 필요한 설정/원본/응답이 막히면 담당과 재개 조건을 기록한다.

이번 보고서 발행 절차에 대해 Claude는 조건부 OK를 회신했다. 이는 요약 기반 자문이며 원문·실행 검증이나 설계 OK가 아니다. 발행자는 파일별 스테이징·정제 확인·관측 시각·좁은 허용목록 조건을 확인한다. Cursor/Gemini는 이번 호출에서도 신뢰 제한(종료 1/55)으로 미검토, 전체 공동 검수는 HOLD다.
