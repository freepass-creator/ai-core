# 개발센터 1차 범위 — 현재 규격 정립

사용자 확정(2026-09-09): 지금은 개발센터를 어떻게 꾸릴지 정리하고, 이미 만들어진 규격을 취합해 기본 규격을 마련한다. 고도화는 2차다.

## 1차 산출물

1. [기본 규격 v0.1](BASELINE.md): SSOT 우선 원칙, 작업·디자인·기능·검증 기본선.
2. [현재 규격 목록](CURRENT-STANDARDS.md): 원본 위치·적용 범위·기존 UI 부품·차이/미확정.
3. [원본 버전 기록](baseline-sources.json): 현재 선택한 원본의 경로·해시·확인 범위. registry.json을 대체하지 않는다.
4. 5그룹·12파트 골격은 유지하되 별도 실행 프로그램을 지금 만들지 않는다.

## 그룹의 1차 책임

| 그룹 | 지금 남길 것 |
|---|---|
| operations | 요청 범위·역할·인계 양식과 네 AI 검토 상태 |
| standards | 요구사항·정본·기본 규격·충돌/예외 목록 |
| design | 현재 토큰·버튼·드롭다운·표·박스의 원본과 사용 진입점 |
| capabilities | 기존 기능/연결 원본과 사용 범위. 새 통합 엔진은 만들지 않음 |
| quality | 확인한 근거·검증 방법·미검증·개선 과제 |

## 2차로 넘기는 것

자동 AI 배정/상태머신, 통합 실행 엔진, 자동 규격-구현 대조, 부품 갤러리 UI, 신규 공통 패키지 추출, 자동 회귀/CI, Firebase 도입, 전 프로젝트 디자인 강제 통합. 현재 엔진/프로젝트는 변경하지 않는다.

## 1차 완료의 뜻

규격 초안과 출처/충돌/예외를 갖춰 사람이 현재 작업에 참조할 수 있다는 뜻이다. 충돌한 규격을 통합 승인했거나 모든 자산이 실행 검증됐다는 뜻이 아니다. 원본 재대조와 네 AI 검수 상태를 각각 보고한다. 기존 개선 리포트의 자동화 과제는 1차 완료의 선행 조건으로 확장하지 않는다.
