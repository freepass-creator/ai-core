# 정본 숫자 읽기 — 세지 말고 «읽는다»

★세션마다 새로 세서 하루에 대수를 다섯 번 다르게 답한 적이 있다. 시트를 새로 세지 않는다.

## 길 — `C:\dev\ai-ops\scripts\데이터\bogi.mjs` (2026-10-03 실행 확인)
```bash
cd C:/dev/ai-ops
node scripts/데이터/bogi.mjs            # 전체 요약 — 모음마다 «문서 수»만. 대수·가동률·미수 합계가 아니다
node scripts/데이터/bogi.mjs <차번>     # 차 한 대: 누가 타나(contract_history)·얼마 냈나(money_tx)·밀렸나(arrears)·자산코드(holding)·서류·보험
```

## 읽는 도구가 없는 것 → 「모른다」
- **대수·가동률** — 요약은 문서 수만 찍는다. 새로 세지 않는다.
- **과태료 몇 장 남았나·자료가 어디까지** — 읽는 도구가 확인되지 않았다. 세지 않는다.
- 빈 목록은 «없다»가 아니라 «못 읽었을 수 있다»(실패가 빈 목록으로 바뀌는 곳이 있다).

## 열쇠
`npm ci`(firebase-admin) + 열쇠 `C:\dev\teamjpkwork\.env.local` 의 `FIREBASE_ADMIN_KEY`. **열쇠는 AI 가 만들거나 찾아다니지 않는다** — 없으면 「지금 정본을 읽을 수 없다」고 답하고 멈춘다(`blocked-escalate`).

정본과 다른 값이 나오면 도구가 틀린 것이다. 알아낸 것은 그 자리에서 정본(지도·도구)에 박는다.
