# 실제 서버 세우기 — 남은 것은 «설정» 이지 코드가 아니다

★2026-09-17 실측. 코드 쪽은 준비돼 있고, **대표가 정할 것 둘과 넣을 것 셋**이 남았다.

## 왜 필요한가

이 오더(`ORD-31638d3e` 「공통 AI 오더 데스크 첫 구현」)의 **마지막 받을 조건**이다:

> 「실제 서버를 지정한 후 원장 이관과 SSH 연결을 검증한다」

지금은 `http://127.0.0.1:4318` — **자기 자신**을 가리킨다. 그래서
**다른 기계·다른 AI 가 같은 오더를 못 본다.** 「여러 AI 가 같은 오더를 공유한다」는
이 오더의 취지가 아직 반쪽인 이유다.

## 잰 것 — 코드는 준비돼 있다

| | |
|---|---|
| 공유 모드 서버 | ✅ 실제로 뜬다 — `AI Core order desk: http://127.0.0.1:4319 / Shared private ledger` |
| 원장 ID 핀 | ✅ `orders.connection.json` 에 `ledger-66ca4559-…` 가 박혀 있고, 다른 DB 면 `LEDGER_MISMATCH` 로 선다 |
| SSH 워크플로 | ✅ `.github/workflows/shared-order-check.yml` 이 이미 `AI_CORE_SSH_*` 를 기다린다 |
| 루프백·Origin·CSP | ✅ 서버가 이미 막는다(`HOST_DENIED` / `ORIGIN_DENIED`) |
| **저장소 변수** | ❌ **하나도 없다**(`gh variable list` 가 비었다) |
| **저장소 비밀** | ❌ **하나도 없다**(`gh secret list` 가 비었다) |

★**남은 것은 코드가 아니라 설정이다.**

## 대표가 정할 것 둘

1. **어느 기계를 중앙으로 쓸 것인가** — 늘 켜져 있어야 한다. 이 PC 여도 되고 별도 서버여도 된다
2. **원장 DB 를 어디에 둘 것인가** — 그 기계의 «절대경로». 지금은 `C:\dev\ai-core\.local\orders.sqlite`

## 대표가 넣을 것 셋 (★AI 가 하면 안 되는 일)

GitHub 저장소 설정에 넣는다. **자격증명이라 제가 대신 넣지 않는다.**

```
변수  AI_CORE_SSH_HOST          중앙 기계 주소
변수  AI_CORE_SSH_USER          접속 계정
비밀  AI_CORE_SSH_PRIVATE_KEY   그 계정의 개인키
```

## 그 뒤에 도는 것

중앙 기계에서:
```bash
# 원장 DB 를 절대경로로 지정해야 공유 모드로 뜬다
set AI_CORE_ORDERS_DB=<그 기계의 절대경로>\orders.sqlite
npm run orders:serve
```

다른 기계에서는 SSH 터널로 붙는다 — **서버는 루프백만 듣는다.** 그게 설계다.

## ★옮기기 전에 반드시 확인할 것

★**원장 ID 가 다르면 서버가 «안 뜬다».** 새 기계에 빈 DB 를 만들면 새 `ledger-…` 가
생기고 `orders.connection.json` 의 핀과 어긋나 `LEDGER_MISMATCH` 로 선다.
**이건 고장이 아니라 안전장치다** — 그래야 두 개의 원장이 조용히 생기지 않는다.

그래서 순서는 하나뿐이다:
1. 지금 DB(`.local/orders.sqlite`)를 **그대로 옮긴다**. 새로 만들지 않는다
2. 옮긴 뒤 `npm run orders:serve` 가 뜨는지 본다
3. 안 뜨고 `LEDGER_MISMATCH` 가 나오면 **옮긴 것이 아니라 새로 만든 것**이다

## 안 한 것 / 못 하는 것

- **자격증명을 넣지 않았다.** 외부 서비스에 키를 넣는 일은 대표가 직접 한다
- 중앙 기계를 **고르지 않았다.** 어느 기계가 늘 켜져 있는지는 내가 모른다
- SSH 왕복을 **검증하지 못했다.** 붙을 곳이 없다
