## 3. aiops — 확인된 사실과 계획

### 오늘 한 것 (되돌릴 수 있음을 먼저 증명하고 지웠다)

Codex의 로컬 체크포인트 ref(`refs/codex/turn-diffs/*`)가 `.gitignore`로 막아둔 개인정보를
git 오브젝트 DB에 스냅샷해 두고 있었다 — `lib/wonja/.칸/고객.json`, 과태료 고지서 png 6장.
**GitHub로 나간 적은 없다**(push refspec에 안 걸림). 하지만 `push --mirror/--all` 한 번이면 나간다.

| 항목 | 결과 (내가 직접 재확인함) |
|---|---|
| 개인정보 blob | 소멸 (`Not a valid object name`) |
| `refs/codex/*` | 4개 → 0개 |
| 브랜치·태그 | **4개 그대로** |
| 워크트리 | **7개 그대로**, HEAD 정상 |
| pack | 6.37 GiB → **60.11 MiB** |
| 백업 복구 검증 | 번들을 실제로 clone해서 blob·ref 4개 복구 가능 확인 |

백업: `D:\backup\aiops-2026-09-16\`(40.4GB 전체) + `D:\backup\aiops-all-2026-09-16.bundle`(80MB).

### push가 막힌 진짜 이유 — 기존 기록이 틀렸다

「100MB 파일 때문」이 아니다. 실제 거부는 **`non-fast-forward`** — 로컬이 원격보다 199 앞서고 **14 뒤처져** 갈라져 있다.
용량 벽은 그 뒤에 따로 있다(제거되지 않았다).

대용량 blob은 **199커밋 중 딱 3개 커밋**(`8b014385`, `edaf7ba4`, `d947a98a`)에서만 들어왔다.
그래서 전체 재작성이 아니라 **분기점 이후만 국소 수술**이 가능하다 — force-push 충격 범위가 최소화된다.

★단, 13개 대용량 파일은 `.gitignore`에 있어도 **지금 HEAD에서 추적 중**이다.
gitignore는 이미 추적 중인 파일을 빼주지 않으므로, 어떤 안을 택하든 `git rm --cached`가 선행되어야 한다.

**실행 전 필수**: 활성 워크트리 7개(codex 5 + cursor 1 + 본체)에 다른 세션이 물려 있다.
조율 없이 진행하면 그 세션들의 작업이 날아간다. **대표 승인 + 세션 조율 둘 다 있어야 한다.**

## 5. 오늘 내가 틀린 기록 7건 — 원인이 하나다

**확인 안 하고 적어둔 것을 다음에 사실로 읽었다.** 일곱 건 모두 한 번만 확인하면 바로 드러났다.

| 내가 적어둔 것 | 실제 |
|---|---|
| ai-core `main`은 run-control-tower 구판 | `scripts/` 자체가 없는 **문서 전용 브랜치** |
| 최신판에 `subject_revision` null guard 추가 | 방향이 반대 — **구판이 fail-open**이던 것을 최신판이 막음 |
| `손오공.mjs`는 수동 병합 필요 | 두 커밋이 **직계 부모·자식**이라 누적 관계, 병합할 것 없음 |
| aiops는 100MB 파일 때문에 push 막힘 | 실제는 **non-fast-forward** |
| sonogong-estimator·freepasshomepage·sheetops는 참조 없음 | 셋 다 fp4가 **임베드·링크·호출** 중 |
| `견적-원가-로직.md`가 main에 없음 | **있다.** git이 한글 경로를 8진수로 따옴표 처리해 grep이 빗나감 |
| `docs/HANDOFF.md`가 git 바깥에 있음 | **이미 커밋됨**(5커밋 이력). push만 안 된 상태 |

### 장부에 박은 규칙 (`aiops/wonja/silsu-jangbu.mjs`)

1. **인계 문서에 「확인한 것」과 「추측한 것」을 같은 어투로 적지 않는다.** 확인 안 했으면 그 자리에 「미확인」을 쓴다. ★**「없다」는 grep을 돌린 뒤에만 쓴다.**
2. **한글 경로 저장소에서는 `git -c core.quotepath=false`를 쓴다.** 그리고 더 큰 규칙 — **「검색 0건」과 「대상이 없음」은 다른 주장이다.** 0건이 나오면 먼저 내 검색식을 의심하고, 있는 줄 아는 것으로 한 번 맞혀보고 나서 0건을 믿는다.
3. **브랜치의 초록불은 「이 브랜치의 테스트가 통과했다」는 뜻이지 「이 코드가 옳다」는 뜻이 아니다.** g0-result는 4/4 통과하면서 오승인 2종을 열어두고 있었다 — 그 케이스가 테스트 파일에 아예 없었기 때문이다. 갈라진 코드는 **최신 테스트를 구판에 돌려** 본다.
4. **`.gitignore`는 추적을 막을 뿐 도구가 만드는 ref까지 막지 않는다.** `refs/heads` 바깥도 주기적으로 훑는다.
