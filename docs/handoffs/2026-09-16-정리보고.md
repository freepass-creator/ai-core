## 1. 대표 판단이 필요한 것 — 우선순위대로

### 🔴 보안 둘 — 내가 못 고친다. 잘못 고치면 정상 사용자가 막히거나 남의 데이터가 열린다

**S1. sonogong 견적기 — 누구나 «견적 금액 규칙»을 덮어쓸 수 있다**

`database.rules.json:7-9`가 `/sonogong/config`·`vehicles`·`stock`에 **무인증 읽기·쓰기를 전면 허용**한다.
`config`에 든 것: **금리 · 수익률 · 대출비율 · 취득세율 · 잔존표 · 운영비.**
⇒ **로그인 없이 아무나 덮어쓰면 전 영업자의 견적 금액이 실시간으로 바뀐다.** 저장소 자신의 `SECURITY-rtdb.md:24-27`이 이미 같은 지적을 적어 두었다.

★**규칙만으로는 못 막는다.** 관리자 인증이 PIN + `sessionStorage`뿐이고 **Firebase Auth가 없어** `auth != null`을 쓸 수가 없다. 오늘 하드코딩 PIN(`1234`)을 환경변수로 옮겼지만(`2ffee31`), Vite가 그 값을 번들에 넣으므로 **방어선이 아니다**(그 사실을 코드 주석에 적어 두었다).
⇒ **「인증을 무엇으로 둘 것인가」가 선행 결정이다.**

또한 `/sonogong/quotes/<id>`에 **고객명·전화·담당자명·전화**가 들어 있고 손님이 무인증 단건 읽기를 한다(자물쇠는 난수 12자 id). 완화: 목록 읽기 차단, 기존 견적 위조·삭제 차단.
★**실제 운영 규칙이 리포 파일과 같은지 모른다** — `SECURITY-rtdb.md:96`이 「콘솔이 SSOT이고 리포 파일은 반영되지 않는다」고 적어 두었다.

**S2. freepasserp4 — 개인정보를 «막던 규칙»이 이관을 안 따라왔다**

계약·정산·전자서명 데이터는 `firestore-path-store.ts`가 **이미 Firestore로 옮겼다.** 그런데 그것을 지키던 **RTDB 규칙 761줄이 남았고**, 새 `firestore.rules`는 **98줄이며 스스로 `// [초안]`이라 적고 있다.**

안 따라온 보호 여섯: ①고객 PII 역할 격리 ②전자서명 토큰(주민번호·면허·서명이미지) 게이트 ③정산 수수료율·지급률 위조 차단 ④계약 불변성(계약일·차량 스냅샷·잔금) ⑤역할별 메모 격리 ⑥취소 사유 결속.

완화: 서버 라우트는 admin SDK로 돌아 규칙을 우회한다. **그러나** `contract`·`customer`·`settlement`는 **클라이언트가 붙을 수 있게 열려 있다**(같은 회사면 read/write). 공백이 아니라 **느슨한 규칙**이다.
그리고 이를 잡을 `check-firestore-rules.mts`는 **세 겹으로 죽어 있다** — npm 스크립트 없음 / CI 없음 / 현행 규칙과 전제 불일치. CI 워크플로 15개에 **`rules`라는 낱말이 걸리는 것이 0건**이다.

★**RTDB 검사를 지우면 안 된다.** RTDB가 꺼졌다는 증거가 저장소 안에 하나도 없고, `scripts/` 수십 개가 아직 그 URL을 들고 있으며, RTDB와 Firestore가 **같은 프로젝트**라 같은 토큰으로 둘 다 닿는다.

## 3. 오늘 하루를 꿰는 사실 — 고장이 «초록불»로 나타났다

발견이 산발적으로 보이지만 무늬가 하나다. **빨간불이 안 켜지는 종류**라 아무도 몰랐다.

| 무엇 | 어떻게 초록으로 거짓말했나 |
|---|---|
| 과태료 예약작업 2종 | `.cmd` 마지막 명령이 `echo`라 종료코드가 항상 0. node가 `exit 4`로 죽어도 스케줄러엔 성공. **한 번도 성공한 적 없었다** |
| `프리패스-자동동기` | 본문이 주석 처리되고 `exit /b 0`만 남아 **매시 「성공」하며 아무것도 안 함** |
| `check:store` | 자가진단이 깨진 채 방치. 그 뒤에 **RTDB 기준 24→0 미갱신**이 숨어 있었다(23개를 새로 만들어도 통과) |
| `check:tokens` | **「여기서 다시 걸지 마라」고 적어 둔 설명 주석**을 위반으로 셈 |
| `check:workflows` | `rm` 줄을 「준비」로 오인 — **삭제는 준비의 증거가 아니다** |
| `/api/drive-backup` | 환경변수가 비면 **승인 대기 검사를 통째로 건너뛰고 통과** |
| 릴리스 관문 2종 | **폐기한 RTDB 변수를 「필수」로 요구** |
| **출시 게이트 자체** | 없는 파일을 읽다 **크래시** — 리포트를 한 줄도 못 냈다 |
| 링크 검사 (PR #38) | **엉뚱한 봉쇄에 먼저 걸려** 통과 — 시험된 적 없었다 |
| head 검사 (PR #38) | `appendLedgerEvent`가 **같은 에러 코드**를 던져 「원장 전에 막았다」와 구별 불가 |

★**마지막 둘은 「봉쇄를 하나씩 빼 보기」로만 나왔다.** 통과만 보고 끝냈으면 「막힌다」고 보고했을 것이고 실제로는 안 막혔다.

### 그래서 규칙이 하나 섰다

> **봉쇄가 N개면 N번 돌린다. 매번 하나만 빼고, «그것이 지키는 검사만» 빨개지는지 본다.**
> 아무것도 안 깨지면 그 봉쇄는 **시험된 적 없는 것**이고, 엉뚱한 게 깨지면 **시험 자리가 틀린 것**이다.

오늘 이 규칙이 **두 갈래에서 각각 값을 했다.**

### 반대 짝도 있었다

지금까지가 「만들어졌는데 안 이어진 것」이라면, 출시 게이트는 **「지워졌는데 같이 안 지워진 것」**이었다. RTDB 컷오버가 어댑터·마이그레이션 파일을 일부러 지웠는데 **그것을 검사하던 게이트는 정리하지 않았다.** 죽은 게이트는 아무도 못 보니 그대로 굳었다.

그리고 switchdebt는 **「판정났는데 실행이 안 된 것」**이었다. 지도에 「암호화 D 보관」이라 적혀 있었고 코덱스가 다른 AI들의 push 권고를 반박한 기록까지 있었는데, **보관 쪽이 실행되지 않아 백업이 하나도 없었다.**

## 4. 과태료 — 켤 준비가 됐다

**`exit 4`는 버그가 아니라 설계대로 멈춘 것**이었다(`gwataeryo-achim-hanbaqui.mjs:148` — Firestore 원장을 못 읽으면 엔진을 안 돌린다. 주석: 「반쯤 하다 마는 것이 제일 나쁘다」).

★**진짜 문제는 시각 선택이다.** 06:07은 audit 로그 10,988건을 세어 「토큰이 가장 한가한 시각」으로 골랐다. 그런데 **Firestore 무료 할당량은 한국시간 16시에 리셋**된다 — 06:07은 리셋 후 14시간째다.
**「한가한 시각」과 「할당량이 남은 시각」은 다른 자원인데 앞의 기준으로만 골랐다.**

**고친 것 둘**
- 성공 표식이 「할 일 없다」 갈래에서만 남아 **매일 두 번 돌 뻔했다**(재시도가 「아직 안 됐다」로 읽음). ★고칠 때 **「성공」의 정의**를 종료코드 0 **그리고** 엔진 로그에 `★엎어졌다`·`★★멈춘다`가 없을 것으로 잡았다 — 엔진은 마디가 엎어져도 0을 낼 수 있어서, 단순히 `=== 0`으로 했으면 부분 실패에 표식이 남아 재시도가 영영 안 돌았다
- 시각 재는 도구(`eonje-doljji-jaenda.mjs`)에 **할당량 축을 보강**(새로 만들지 않음). 권장 **본판 21:07 · 재시도 23:07** — 리셋 뒤 같은 날, 저녁 중 바쁨 바닥, 20:00 daily 뒤라 잠금 충돌 없음, 전날 밤에 끝나 아침엔 이미 차 있음

★**표식이 한국 날짜 기준이라 재시도가 본판보다 앞서면 늘 어제 표식을 읽어 매일 두 번 돈다.** 본판을 옮기면 재시도도 같이 옮겨야 한다.

★그리고 **PR #37을 병합할 때 `npm test 316/316`과 `verify PASS`를 보고 승인했는데, GPT가 그 안에서 경계 결함을 찾아냈다.**
**「테스트가 통과한다」와 「경계가 강제된다」는 다른 주장인데 앞의 것으로 뒤의 것을 대신했다.** 오늘 종일 쫓던 문제를 내가 한 번 더 한 것이다.

### 장부에 박은 규칙 (`aiops/wonja/silsu-jangbu.mjs`, 9건)

1. 인계 문서에 「확인한 것」과 「추측한 것」을 같은 어투로 적지 않는다. **「없다」는 grep을 돌린 뒤에만 쓴다**
2. 한글 경로엔 `git -c core.quotepath=false`. **「검색 0건」과 「대상이 없음」은 다른 주장이다**
3. 브랜치의 초록불은 「이 브랜치의 테스트가 통과했다」지 「이 코드가 옳다」가 아니다. **최신 테스트를 구판에 돌려 본다**
4. `.gitignore`는 추적을 막을 뿐 **도구가 만드는 ref까지 막지 않는다**
5. **갈래가 갈리면 커밋 날짜는 내용의 순서가 아니다.** blob과 조상 관계로 판정한다
6. **「백업·덤프·스냅샷」이름이 붙으면 일단 개인정보로 본다.** `.gitignore`는 이미 추적 중인 것을 빼주지 않는다
7. **막힌 까닭을 하나로 단정하지 마라.** 에러는 가장 먼저 만나는 벽만 말한다
8. **돌려도 되는지 «내가 분류해서» 돌리지 마라.** 허용 목록 밖은 묻고 멈춘다
9. **봉쇄가 N개면 N번 돌린다** (위 3절)
