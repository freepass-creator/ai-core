# 로컬·서버 공유 오더 검토

2026-09-15, `work/codex/order-control-v1`. 기준은 동일 작업 트리의 공유 클라이언트·서버·GitHub 영수증·워크플로다. 실제 원장이나 인증정보는 검토 프롬프트에 전달하지 않았다.

## 독립 검토

Cursor Agent를 읽기 전용 Ask 모드로 호출했다. 연결 장애 시 로컬 원장을 만들지 않는 점, 원장 ID 검사, 명시적인 GitHub 메모 입력과 완료 판정 분리에 동의했다.

반영한 지적:

- 서버 라이브러리 호출에도 원장 ID 또는 명시적인 독립 실험 모드를 요구한다.
- 서버와 클라이언트가 같은 연결 정책 검증 함수를 사용한다.
- 장치에 저장한 원장 ID와 코드의 정책이 다르면 재연결을 요구한다.
- 짧은 저장소명 비교를 없애고 버전 관리되는 `ai-core → freepass-creator/ai-core` 매핑으로 소유자까지 대조한다.
- 응답 원장 ID 누락, 장치 ID 불일치, 서버 모드 누락, 다른 GitHub 소유자 거부를 회귀 검사한다.

원장 ID가 인증이 아니라는 지적은 수용하여 실행 안내에 명시했다. SSH/OS가 접근 경계이며 같은 호스트의 신뢰된 프로세스는 원장을 읽고 쓸 수 있다. 애플리케이션 역할별 인증으로 확대하는 제안은 이번 SSH 전용 단일 사용자 범위를 넘어 채택하지 않았다. 복제 DB의 동일 ID가 동시 쓰기 방지를 보장하지 않으므로 운영 절차에서 활성 중앙 서비스를 하나로 제한한다.

Claude는 주간 사용 한도, Gemini는 작업 공간 신뢰 문제로 추가 검토를 받지 못했다. 이를 PASS로 계산하지 않는다. 실제 서버 연결·이관과 필수 추가 검증이 남아 있어 운영 완료 상태가 아니다.

## 검증 범위

독립 코드 폴더의 두 HTTP 클라이언트, 동시 확보 충돌, 응답 유실 후 중복 방지, 연결 부재 시 DB 미생성, GitHub 참고 메모의 명시 입력·프로젝트 일치·요구 버전 충돌을 검사한다. 브라우저 쓰기 후 CLI 재조회와 잘못된 브라우저 원장 ID 거부도 확인했다.

실제 SSH 서버 왕복과 GitHub 수동 워크플로의 비밀 설정·실행은 검증하지 않았다. 기존 로컬 화면 검증은 앞선 커밋의 `ORDER-DESK-VERIFICATION.json`에 별도 보존한다.

## 수정 후 재검토

Cursor의 두 번째 읽기 전용 검토에서는 공유 CLI → 원장 → GitHub 참고 메모 경로에 남은 차단 수준 코드 오류가 없다고 판단했다. 실제 서버·SSH·GitHub 환경 검증은 여전히 별도 미완료다. IPv6 주소 허용과 IPv4 서비스 바인딩 차이, 명시적인 standalone 오용, 잘못된 신규 DB 경로의 빈 파일 생성은 비차단 주의사항으로 남겼다. 운영 연결은 문서의 127.0.0.1 및 원본 절대 DB 경로를 사용한다.
