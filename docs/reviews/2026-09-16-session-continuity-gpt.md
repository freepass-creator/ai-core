## 2. 제품 기능과 우리 운영의 구분

Claude Code 공식 문서상 새 세션의 대화 맥락, CLAUDE.md 지침, 로컬 auto memory, 이전 대화 resume는 서로 다른 수단이다. 로컬 기억은 다른 PC/클라우드로 자동 공유되지 않는다. 지침을 제공하는 것과 실제 도구 호출을 강제 차단하는 것도 다르다. 구체 기능은 실제 설치 버전과 실행 표면(CLI/웹/앱)을 확인한다.[S1][S2]

따라서 CLI에서 이전 대화를 이어갈 때는 검증된 세션 이름/ID로 `claude --resume` 또는 같은 디렉터리의 직전 세션에 `claude --continue`를 사용할 수 있다. 이는 이전 실행의 모든 런타임 설정·권한·서비스가 현재도 있다는 보장이 아니다. 서로 다른 작업이 같은 session ID를 동시에 resume하지 않는다.[S2]

새 세션/다른 AI/다른 PC를 위한 공용 기억은 기존 GitHub의 최소 인계와 원천 포인터로 제공한다. 대화 전문, .claude 전체, 인증정보를 통째로 동기화하지 않는다. 공식 기능을 소개했다고 사용자 환경에 설치·활성화됐다고 보고하지 않는다.

## 4. 새 세션 시작 절차 — STARTUP_CHECK

아래는 기존 AI_CONTINUATION/CROSS_AI_ENTRYPOINT/실행기의 보완 제안이다. 독립된 또 다른 실행기를 만들지 않는다.

1. **실행 환경 확인:** 현재 표면(CLI/웹/일반 채팅), 확인 가능한 host 식별, 작업 디렉터리·remote·branch·HEAD·dirty/원격 비교 상태를 범위 내에서 읽는다. 새 세션이라는 이유로 기존 환경을 초기화하지 않는다.
2. **공용 진입 복원:** 설치된 Claude가 실제 로딩하는 CLAUDE.md에서 기존 공용 진입점으로 연결한다. 로드된 경로와 내용을 확인한다. 필요 시 `/memory` 또는 `/context`를 사용하되 CLI가 아닌 표면에 해당 명령이 있다고 가정하지 않는다.[S1]
3. **현재 작업 복원:** 사용자 최신 결정, 현재 인계, 관련 원격 구현, 해결된 문제·남은 문제·다른 담당의 작업을 읽는다. 본 세션에 파일이 없으면 등록된 다른 branch/ref의 알려진 경로를 먼저 조회한다. 다른 구현자의 checkout을 바꾸지 않는다.
4. **역할 식별:** coordinator / implementation / independent-review / observation 중 현재 구체 배정에 맞는 역할을 기록한다. 과거 검토 패킷은 영구적인 구현 금지 명령이 아니며, 새 구현 배정도 기존 안전 gate의 우회 권한이 아니다.
5. **가용성 판별:** TOOL_CONNECTIONS의 기존 경로를 먼저 사용한다. 연결 이력은 재설치 대신 재사용의 힌트지만 현재 동작 증거는 아니다. 필요한 최소 기능만 안전하게 확인한다.
6. **쓰기 전 배정 확인:** 기존 중앙 업무·scope·소유권·승인 조건을 확인한다. 다 충족하면 할당된 작은 다음 작업부터 진행한다. 빠진 항목은 정확히 구분하고, 허용된 읽기·인계 정리는 계속한다. 쓰기 gate의 부재를 기록을 읽는 단계까지 막는 순환 의존으로 만들지 않는다.

시작 결과는 장문 보고 대신 다음 정보를 짧게 반환한다. 이는 점검 기록이지 실행권 토큰이 아니다.

```text
STARTUP_CHECK
실행 환경 / 실제 읽은 시작 문서:
repo / branch / 실제 대상 revision:
복원한 사용자 결정 / 현재 work 연결:
직전 완료 / 남은 일 / 다시 하지 않을 일:
이번 역할 / 수정 허용 범위 / 다른 담당 영역:
실제 연결 상태와 필요한 기능의 확인 결과:
소유권·승인 확인 또는 정확한 blocker:
다음 한 작업:
```

"이 세션엔 없습니다"는 결론이 아니라 분류 시작이다. `NOT_LOADED / OTHER_REF / LOCAL_ONLY / ACCESS_UNAVAILABLE / AUTH_REQUIRED / NOT_INSTALLED / NOT_IMPLEMENTED / UNVERIFIED` 등을 구분한다. 찾을 수 없거나 권한이 실제로 없으면 사실대로 보고하되, 확인한 경로·호스트·범위와 가능한 다음 행동을 함께 제시한다. 없는 접근권을 있는 것처럼 가장하거나 인증/신뢰 제한을 우회하지 않는다.

## 5. 세션은 모델 이름이 아니라 업무·수정 범위로 나눈다

아래는 역할 배치 제안이며 새 세션을 실제로 열거나 현재 담당을 재배정한 결과가 아니다. 수는 고정하지 않고 독립 작업·현재 자원·검토 필요에 맞춘다.

| 역할 | 책임 | 중복 방지 경계 |
|---|---|---|
| 통합 총괄 한 명 | 최신 사용자 결정, 우선순위, 범위 배정, 공용 최신 인계, 조정·검증 후 최종 통합 | 동일 시점 총괄 소유자는 하나. 새 총괄로 교체할 때 이전 담당의 인계·진행 상태를 확인 |
| 기억·시작 절차 담당 | 기존 CLAUDE.md/AI_CONTINUATION과 시작 검증 보완 | 전용 scope로 배정된 파일만. 공용 파일을 다른 구현자도 수정하면 총괄이 하나의 변경으로 조정 |
| 기능별 통합 구현 담당 | 예: 오더-원장 연결, registry, 물리 편입 등 서로 분리 가능한 업무 | 업무별 실제 branch/worktree·허용 파일·공유 리소스·선행조건을 먼저 배정. 이미 수행 중인 PR21/PR22/group 업무를 다시 만들지 않음 |
| 독립 검토·모니터링 | 같은 대상 revision의 반례·검사·사용자 목적 대조 | 기본 읽기 전용. 제품 코드·원장 수정 금지. 검토 결과는 PR29 또는 해당 구현 PR로 반환 |

모든 세션은 같은 합의를 읽되, 자신의 Work Packet과 필요한 근거만 추가로 읽는다. 총괄 CURRENT/HANDOFF를 전원이 동시에 덮어쓰지 않는다. 각자 자기 결과/PR 댓글에 반환하고 지정 소유자가 공용 요약을 갱신한다.

Worktree는 작업 파일·브랜치 분리 수단이지 같은 업무의 중복 배정, 외부 DB·포트·스케줄러·계정의 경쟁 실행을 모두 막는 장치가 아니다.[S3] 같은 기능을 다른 파일에서 만드는 의미상 중복도 업무 배정에서 막아야 한다.

배정에는 `work_id(확인된 경우) / executor_instance_id / 역할 / requirement revision / repo·branch·worktree / owned paths / shared resources / 선행작업 / 결과 위치`를 연결한다. Claude라는 이름이 같아도 세션별 실행자는 다르다. 기존 토큰·비밀키는 공용 문서로 전달하지 않는다.

기존 중앙 claim의 실제 배선이 없으면 있다고 가장하지 않는다. 검증된 단일 쓰기 담당으로 범위를 제한하고, 병렬 writer를 확대하기 전에 동일 work/resource의 경쟁 획득·중복 제출을 차단하는 기존 코드를 연결·검증한다. 만료/heartbeat 누락만으로 다른 작업을 탈취하거나 재실행하지 않는다. 소유권 이전 시 이전 실행자의 늦은 결과·쓰기가 거부되는지도 검증한다.

## 6. 끝날 때가 아니라 변경할 때 기억을 남긴다

사용자 정정·중요 결정·완료된 작은 변경·검사 실패·blocker 변경·배정 이전 시 기존 인계를 갱신한다. 세션 종료 시에만 맡겨 두지 않는다.

최소 인계는 `이번 결정과 근거 / 실제 완료 / 남은 일 / 이미 시도한 것과 실패 이유 / 재사용할 코드 / 검사 범위·revision / 다른 담당 / 다음 한 작업`이다. 중간 실패나 미게시 수정은 성공/게시로 승격하지 않는다.

저장 상태를 `LOCAL_ONLY → COMMITTED → REMOTE_CONFIRMED → NEXT_SESSION_READ`로 구분한다. 실제 원격 파일을 재조회한 뒤 공개 가능 범위로 기록하고, 새 세션이 해당 체크포인트를 읽어 시작한 기록까지 연결한다. 생략한 내용과 모르는 내용은 명시하며 전체 대화 기억을 보장하지 않는다.

## 7. Claude/Council이 구현할 최소 변경 순서

**우선 목표는 거대한 기억 시스템이 아니라 새 세션 하나의 정상 재개와 중복 쓰기 방지 한 번을 보여주는 것**이다.

A. 현재 로컬 총괄과 작업대장을 읽고 역할/브랜치/수정 범위를 확정한다. PR21 Claude ACK를 전체 통합 배정으로 확대하지 않는다. 이미 적합한 담당이 있으면 새 세션을 만들지 말고 그 담당에게 연결한다.

B. PR22의 기존 CLAUDE.md를 기반으로 **공통 부팅 지침**과 **PR22 독립 검토 전용 패킷**을 분리하는 최소 변경을 검토한다. 기존 read-only 검토 안전 규칙은 해당 검토 패킷에 보존한다. 공통 파일은 역할을 실제 배정에서 읽도록 한다. main과 실제 사용 체크아웃에 보급할 때는 해당 파일과 링크 의존성만 검토하며 전체 PR22를 편의상 자동 병합하지 않는다.

C. WORK_READ_FIRST/AI_CONTINUATION의 기존 읽기 경로에 CURRENT, 해당 브랜치 HANDOFF, TOOL_CONNECTIONS, 현재 배정·소유권의 최소 집합을 연결한다. 거대한 연구 문서 전체를 무조건 import하지 않는다. 로딩 확인, 정확한 사유 분류, STARTUP_CHECK를 기존 시작 경로에서 반환한다. 파일은 안내이고, 강제 차단은 승인된 실행기/권한 통제와 함께 별도로 검증해야 한다.[S1]

D. 기존 read-ai-work-packet, repo-sync-preflight, 중앙 claim/work ledger와 CONCURRENT_WORK의 실제 사용 경로를 대조한다. 판정표를 문서화하는 것과 실행기에서 scope/경쟁 쓰기를 막는 것이 다름을 검사한다. 고객 DB나 실운영 원장은 테스트 대상으로 쓰지 않는다.

E. 아래 수락 시나리오를 기존 테스트에 추가하거나 실제 세션으로 확인한다. 필수 의존 항목을 통과하기 전에는 파일럿 외 병렬 실행을 확대하지 않는다. 각 변경은 기존 Council이 같은 revision을 검토하고 합의·조정/보류를 남긴다. GPT 단독 권고를 다중 AI 합의로 쓰지 않는다.
