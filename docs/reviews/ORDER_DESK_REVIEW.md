## 구현 검토

Cursor 읽기 전용 검토 요청 범위: `src/orders/store.mjs`, `src/orders/server.mjs`, `web/orders/app.js`, `test/orders.test.mjs`. 개인정보·원장·수집 자료는 제외했다.

첫 검토에서 발견하고 반영한 사항:

- 과거 요구 버전 결과가 최근 이벤트 12개 밖으로 밀리면 인계에서 사라짐 → 전체 REPORT 이력을 별도 `historicalResults`에 포함하고 현재 버전 여부를 명시.
- 완료 조건과 근거가 연결되지 않음 → 조건별 현재 작업 근거 참조를 필수로 검사. 내용의 충족 여부는 사용자 판단이며 검증 인증으로 표현하지 않음.
- 저장 후 조회 실패를 저장 실패로 표시 → 저장 성공 안내와 재조회 필요를 구분하고 오래된 상세 화면은 일시 비활성화.
- 만료된 작업 확보 표시 → 패킷에 `leaseState`, 재확보·재배정 행동을 제공하고 화면에서 별도 만료 상태로 표시.

수정 후 Cursor 재검토에서 위 네 수정은 확인됐으며, 추가 UI 상태 문제를 발견해 반영했다:

- 조회 복구 후 오더를 선택해도 상세 화면이 비활성 상태로 남는 문제 → 성공한 상세 조회에서 비활성화를 해제. 실제 브라우저 장애 주입 후 같은 오더 선택으로 복구됨을 확인.
- 목록·상세의 만료 표시 불일치와 만료·수동 대기 혼동 → 공통 표시 함수를 사용하고 만료를 별도 상태로 표현.
- 요구 수정 뒤 과거 실행 횟수 때문에 진행 중으로 표시 → 현재 작업 상태로만 진행 상태 산출. 회귀 테스트에서 NEW 확인.

작업 확보 만료를 타이머로 원장에 자동 기록하는 제안은 이번 버전에 넣지 않았다. 읽기 시점의 만료 표시와 실제 재확보 사건을 구분하며, 자동 실행·예약 시스템은 이후 범위다. 실패한 외부 작업의 자동 재시도는 구현하지 않는다.

Cursor 최종 좁은 범위 재검토에서 위 네 수정이 모두 확인됐고, 해당 변경 경로의 추가 중대 결함은 발견되지 않았다. 이 결과는 전체 시스템 무결성 보증이나 운영 실행 승인이 아니다. 실제 검증 결과는 `docs/evidence/ORDER-DESK-VERIFICATION.json`에 기록한다.

추가 로컬 검사에서 HTTP 청크 경계에 걸친 한국어 문자열 보존을 보완하고 분할 UTF-8 요청의 회귀 검사를 통과했다. 저장된 연구 브랜치까지 기본 테스트 탐색에 포함되는 것을 발견해 `npm test`의 범위를 현재 저장소 `test/*.test.mjs`로 명시했다. 수집 스냅샷 1,005개 파일의 원래 해시는 모두 유지됐다.
