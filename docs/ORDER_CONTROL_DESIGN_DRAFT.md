# AI Core 오더 통합 설계 초안

## 목적과 소유권

저장소는 분리한다. 공통 사고·판단·작업·처리 기능과 모든 오더의 접수·배정·진행·완료 기록은 AI Core에 모은다.

- 프로젝트: 코드·문서·운영 데이터 정본.
- AI Core: 오더·작업 배정·처리 이력·판단 기록·검증 상태 정본.
- 채팅·대시보드·CLI: 같은 중앙 서비스에 접근하는 화면과 입력 경로.
- GitHub: 설계·코드·검증 산출물·인계 문서의 버전 관리. 수시로 바뀌는 작업 상태를 각 브랜치 파일로 경쟁 갱신하지 않는다.
- 자료 수집 폴더: 출처 확인용 스냅샷. 원본과 자동 동기화되거나 운영 정본으로 승격된 것이 아니다.

## 최소 구성

1. 접수 API: 요청 원문 참조, 출처 ID, 요청 버전, 중복 접수 키를 저장하고 영구 오더 ID를 반환한다. 대화의 모든 발언을 새 오더로 만들지 않고 수정·질문·취소를 기존 오더와 연결한다.
2. 중앙 원장: 오더, 프로젝트별 하위 작업, 실행 시도, 변경 이벤트, 근거·승인 참조를 영속 저장한다. 명령 검증과 이벤트 기록, 현재 상태 갱신, 배정 대기 기록을 하나의 트랜잭션으로 묶는다.
3. 작업 조정기: 선행 조건과 담당자, 실행 가능 범위, 다음 행동을 판단한다. 공통 규칙을 적용하되 프로젝트별 업무 의미는 담당 프로젝트에 둔다.
4. 실행 연결부: Codex·Claude·Cursor·Gemini·프로젝트 도구마다 지원 기능과 연결 상태를 선언한다. 배정 수신·실행 시도·결과 회신을 같은 오더에 연결한다.
5. 조회 화면: 전체 오더, 승인 필요, 막힌 작업, 검증 필요, 완료를 보여준다. 오더 상세에는 요구 변경·판단 근거·실행·증거·다음 행동이 시간순으로 남는다.

데이터베이스 제품과 호스팅 위치는 동시 사용자·장치·가용성 요구를 확인한 뒤 선택한다. RTDB는 사용하지 않는다.

## 데이터 관계

Order → Task → Attempt. 각 객체에 프로젝트·원본·결과의 참조가 연결된다.

- Order: 요청자, 원래 의도, 현재 요구 버전, 완료 조건, 우선순위, 담당, 다음 행동, 대기 이유.
- Task: 프로젝트·범위·선행 작업·실행 연결부·완료 조건. 하나의 오더가 여러 프로젝트 작업을 가질 수 있다.
- Attempt: 실행 ID, 도구, 실제 대상·리비전, 시작·마지막 응답 시각, 임대 토큰, 결과.
- Event: 전역 고유 ID, 오더 내 순번, 행위자, 시각, 요구 버전, 상태 변경, 근거 참조. 과거 사건은 수정 대신 정정 사건을 추가한다.
- Evidence / Decision / Authorization: 검증 결과, 판단 이유, 승인 대상·범위·버전·유효 조건. 민감 원문이나 인증 비밀은 중앙 원장에 일괄 복제하지 않는다.

오더의 진행 상태와 실행·검증·승인·외부 결과 상태는 구분한다. 검토 승인이나 테스트 통과를 외부 처리 완료로 바꾸지 않는다. 단순 조회는 필요한 최소 필드로 끝내며 개발 전용 요구를 모든 업무에 강제하지 않는다.

## 흩어짐과 중복 방지

- 연결된 입력 경로는 실행 전에 중앙 접수 성공을 확인한다. 미연결 대화·도구의 요청은 자동 수집된다고 주장하지 않는다.
- 중앙 밖에서 시작된 작업은 기존 실행 ID·출처와 함께 가져와 기존 오더와 연결한다. 불명확한 유사 요청을 자동 합치지 않는다.
- 배정에는 실행 임대와 증가하는 토큰을 사용한다. 오래된 실행자의 늦은 회신은 이력으로 보존하되 최신 상태를 덮어쓰지 못한다.
- 외부 작업은 중복 방지 키와 실행 영수증을 사용한다. 결과를 모르는 타임아웃은 UNKNOWN으로 두고 외부 상태를 재조회한다. 무조건 재실행하지 않는다.
- 연결 장애 중 회신은 재전송 가능하게 보존하고 중앙은 이벤트 ID로 중복을 제거한다. 재시작 뒤 미확인 실행과 원본 상태를 대조한다.
- 외부 부작용까지 정확히 한 번 실행을 일반적으로 보장한다고 주장하지 않는다. 제공자 기능과 재조회·수동 판정 절차를 연결부별로 정의한다.
- 여러 프로젝트 작업의 완료와 오더 전체 완료를 구분한다. 부분 완료·실패·취소 시 되돌리기 가능 범위를 기록한다.

## 공통 기능의 경계

AI Core에 둘 것: 접수, 요구 변경 관리, 출처 선택, 계획·배정, 공통 검증 계약, 승인 확인, 재시도·중복 방지, 증거 수집, 인계·복구·관찰.

프로젝트에 둘 것: 정산 계산식, 계약 업무 규칙, 고객 원본, 제품 UI·도메인 스키마 등 고유 업무 의미. AI Core는 버전이 고정된 기능 계약으로 호출한다.

기존 개발 폼의 source/scope/acceptance/proof/review/authorization/handoff 개념은 재사용한다. 범용 Order를 상위에 두고 개발 폼은 개발 Task의 상세 계약으로 연결한다. 기존 검증기는 개발용이므로 그대로 범용 오더 검증기로 간주하지 않는다.

## 첫 구현과 완료 조건

첫 단계는 단일 중앙 서비스, 영속 원장, 얇은 화면 또는 CLI, 실행 연결부 하나로 제한한다. 여러 장치에서 각자 원장을 쓰고 나중에 합치는 구조는 피한다.

실제 오더 하나로 다음을 검증한다.

1. 같은 요청을 두 번 받아도 하나의 오더로 처리된다.
2. 프로세스나 대화를 재시작해도 담당·진행·다음 행동을 복구한다.
3. 실행자 교체 뒤 오래된 회신이 현재 상태를 덮어쓰지 않는다.
4. 실행은 끝났으나 회신이 유실된 경우 외부 상태 대조로 복구한다.
5. 요구 변경 뒤 이전 버전의 검증으로 완료할 수 없다.
6. 부분 완료와 승인 대기가 전체 완료로 표시되지 않는다.
7. 연결되지 않은 입력 경로와 미확인 결과가 화면에 드러난다.

이 검증 뒤 다른 도구와 프로젝트 연결을 늘린다. 구현 선택, 실운영 권한, 기존 오더의 이관 범위는 별도 확정 사항이다.

## 검토 상태

Codex가 현재 개발 폼·동시 작업 지침과 대조했다. Gemini에 비식별 요구 요약만으로 읽기 전용 독립 설계 자문을 시도했으나 응답 없이 대기하여 중단했다. 앞선 Claude 자문도 주간 사용 한도로 실행되지 않았다. 독립 검토 합의는 확보하지 못했으며, 이 문서는 확정 설계나 검증 완료된 구현이 아니다.
