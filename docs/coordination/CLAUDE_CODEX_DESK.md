# Claude · Codex 책상 — 두 축이 겹치지 않고 같이 일하는 법

- 상태: `AGREED v0.2` — Claude 초안(C-0001) → Codex 검토 MODIFY(X-0001) → 반영(C-0002). 2026-09-22.
- 대표(2026-09-22): 「앞으로 양대축으로 클로드 코덱스만 쓸거야 · 절대 중복되지 않게끔 · 같이 개발하는데 문제 없게끔 · 코덱스랑 상의해서 · 서로 md로 소통하면서」
- 역할의 정본은 [AI Working Standard](../AI_WORKING_STANDARD.md) 「협업 AI 정책」이다. 이 문서는 그 위에서 **겹침을 막는 절차**만 정한다.

## 1. 왜 겹치나 (실제로 겪은 것)

- 대표는 두 AI에게 **따로** 말한다. 비슷한 일을 둘이 따로 받으면 둘 다 시작한다.
- 같은 저장소·같은 운영 대상(시트·Firestore·워크플로)을 둘이 동시에 만졌다
  (aiops 2026-09-02: 「같은 것을 둘이 고쳤다 — 다른 세션이 tmp 파일을 덮어써 옛 값을 읽었다」).
- 한쪽이 물은 것의 답이 어디에도 남지 않았다.

## 2. 역할 (정본 요약 — 바뀌면 정본을 고친다)

| | Codex | Claude |
|---|---|---|
| 주 | 지휘 · 실행 · 통합 · 최종 검증 · 병합 — 병합은 검토된 커밋·PR·필수 검증을 확인해 통합한다. 병합 권한이나 승인을 자동으로 뜻하지 않는다 | 설계 · 반례 · 중요 문안 · 구현 결과의 독립 검토 |
| 부르는 법 | 대표가 직접 · 또는 Claude 가 책상에 요청 | 대표가 직접 · 또는 Codex 가 `npm run claude:review` |
| 대표가 직접 맡긴 일 | 한다 | **한다** — 단 아래 「잡기」 를 먼저 |

## 3. 잡는 자리는 둘 — 로컬 책상 + GitHub

**로컬 책상** `C:\dev\ai-core\.local\desk\` — 빠른 조율용(커밋하지 않는다, `.local` 규약).
이 PC 의 로컬 세션은 함께 보지만, **GitHub-hosted · 원격 · 다른 PC 세션에는 보이지 않을 수 있다.**
그래서 로컬 책상만을 유일한 잠금으로 삼지 않는다 — 쓰는 일은 GitHub 에도 잡는다(4절 3항).
지속 기록(결정·결과)은 해당 저장소의 branch · PR · GitHub 문서다.

**각자 자기 파일만 쓴다.** 남의 파일은 읽기만 한다 → 덮어쓰기 경쟁이 구조적으로 없다.

| 파일 | 쓰는 쪽 | 무엇 |
|---|---|---|
| `지금-claude.md` | Claude | 지금 잡고 있는 일 |
| `지금-codex.md` | Codex | 지금 잡고 있는 일 |
| `claude→codex.md` | Claude | Codex 에게 보내는 말 (덧붙이기만) |
| `codex→claude.md` | Codex | Claude 에게 보내는 말 (덧붙이기만) |

## 4. 잡기 — 시작 «전» 에

겹침 키 = **저장소 + branch/worktree + 쓰는 파일·운영 대상**.
같은 저장소라도 분리된 worktree 에서 겹치지 않는 범위면 병행한다. 읽기 전용 검토는 잡지 않아도 된다.

1. **상대의 `지금-*.md` 와, 그 저장소의 열린 PR(초안 포함)이 건드리는 파일을 본다.** 겹침 키가 겹치면 **시작하지 않는다** → 5절.
2. 내 `지금-*.md` 에 한 줄 적는다:

```markdown
| 번호 | 무엇 (대표 말 그대로 한 줄) | 저장소 · 갈래/작업폴더 | 범위 (파일·경로 / 운영 대상) | 시작 | 끝날 예상 | 상태 |
|---|---|---|---|---|---|---|
| C-J-0001 | 손오공 연령정책 POL-0020 정리 | freepasserp5 Firestore | policy/POL-0020 | 09-22 14:00 | 09-22 15:00 | 하는중 |
```

3. **저장소 파일을 쓰는 일이면 첫 커밋과 함께 초안(draft) PR 을 연다.** 제목 앞에 `[Claude]` / `[Codex]`, 본문 첫 줄에 잡기 번호.
   로컬 책상을 못 보는 원격 세션도 GitHub 에서 「이 파일을 누가 잡고 있나」를 본다.
4. 끝나면 줄을 지우지 말고 상태를 `끝 — <PR·run·원장 사건>` 으로 바꾼다. 하루 지난 `끝` 줄은 지워도 된다.
5. **24시간 넘게 갱신 없는 `하는중` 은 `확인 필요`일 뿐이다.** 상대에게 묻고 worktree · PR · 실행 상태를 확인한 뒤에만 이어받는다.

범위는 좁게 쓴다: 「ai-core」 가 아니라 「ai-core · feat/x · src/integration/ops-watch.mjs」.
운영 대상(Firestore 문서·시트 탭·GitHub 워크플로·예약작업)은 **파일이 아니어도 적는다** — 겹침은 대개 거기서 난다.

## 5. 겹칠 때

- **먼저 잡은 쪽이 한다.** 단, 대표의 더 최신 직접 지시와 프로젝트 권한·병합 규칙이 우선한다.
- 나중에 온 쪽은 시작하지 않고 상대 책상에 말을 남긴다: 「대표가 나에게도 X 를 맡겼다 — 네 C-J-0001 과 겹친다. 나는 (가) 검토로 붙거나 (나) 이 부분만 한다 — 어느 쪽?」
- 역할상 한쪽 몫이 분명하면(병합·통합=Codex, 독립 검토=Claude) 그쪽으로 넘긴다.
- 둘이 정하지 못하면 **대표에게 한 줄로** 묻는다 — 어느 쪽이 무엇을 할지 선택지 둘.

## 6. 말 — 덧붙이기만, 번호로

```markdown
## C-0007 · 2026-09-22 14:05 · 열림
- 무엇: <한 줄>
- 원함: 검토 | 결정 | 실행 | 알림
- 근거: <파일:줄 · PR · run · 원장 사건>
- 언제까지: <시각 또는 「급하지 않음」>
```

- 번호: Claude→Codex `C-####`, Codex→Claude `X-####`. 잡기 번호는 `C-J-####` / `X-J-####`.
- 받는 쪽은 **자기 파일에** 새 번호로 `## X-0012 · 답 C-0007` 만 남긴다. 상대 파일을 고치지 않는다.
- 닫는 것은 **보낸 쪽이** 자기 파일에 새 항목 `## C-0009 · C-0007 닫음` 으로 남긴다 — 번호 소유권을 섞지 않는다.

## 8. 넣지 않는 것

- 비밀·열쇠·고객 개인정보·원문 대화 — 책상에 적지 않는다.
- 결정과 결과의 정본은 GitHub(PR·문서)과 각 프로젝트 정본이다. 책상은 **조율** 자리다 — 거기 적힌 것만으로 권한이 생기지 않는다.
- 새 원장·새 오더 체계를 만들지 않는다(AI Working Standard: 「일반 업무를 위해 order ID, work ID, claim 또는 중앙 서버 연결을 만들지 않는다」). 책상의 잡기는 로컬 조율 표시이지 원장이 아니다.
- aiops `wonja/ai.mjs` 와 합치지 않는다 — 그것은 aiops 업무 원장이고 이 책상은 조율 채널이다. 필요하면 원장 사건 ID 만 책상에 적고 양쪽에 중복 기록하지 않는다.
