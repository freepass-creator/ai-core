# 개발센터 지도점검 규정 v1

개발센터는 모든 프로젝트의 **개발 절차, 규격 연결, 검증 증거, 시정 이력**을 관장한다. 각 프로젝트의 업무 의미와 데이터 정본은 승인된 원본 위치에 남긴다. 개발센터가 그 내용을 복사해 새 정본으로 만들지 않는다.

## 점검 흐름

1. **대상 등록**: 프로젝트 경로, 작업 목표, 허용 범위와 담당자를 고정한다.
2. **기준 고정**: 대상 프로젝트의 지침, 업무 정본, 브랜치·커밋 또는 작업 트리 상태를 기록한다.
3. **지도점검**: 구조, SSOT 연결, 재사용 자산, 보안 경계, 검사 명령, UI 상태와 증거를 읽기 전용으로 확인한다.
4. **시정 배정**: 위반마다 근거, 영향, 수정 방법, 담당 역할, 재검사 명령을 넣은 시정명령을 발행한다.
5. **수정 실행**: 이미 승인된 작업 범위에서만 수정한다. 정본·권한·운영 데이터·배포를 바꾸는 수정은 대상과 범위를 직전에 다시 확인한다.
6. **재검사·종결**: 수정본의 새 해시에서 원래 반례와 회귀검사를 실행한다. 검사 없이 완료 처리하지 않는다.

## 판정

- `FAIL`: 확인된 규격 위반 또는 위험한 유입. 수정 전 통과 불가.
- `HOLD`: 원본, 권한, 버전 또는 검증이 부족해 판단할 수 없음.
- `NOTICE`: 지금 막지는 않지만 정리·개선이 필요한 항목.
- `PASS`: 선언된 검사 범위와 고정 버전에서 위반을 발견하지 못함.

PASS는 프로젝트 전체의 무결점 인증이 아니다. 미등록·미지원·접근 실패를 0건으로 세지 않는다.

## 수정 권한

지도점검기는 먼저 읽기 전용 보고서와 시정 작업 패킷을 만든다. 자동 수정은 규칙별로 검증된 수정기가 있고, 대상 프로젝트 지침과 사용자 승인 범위가 일치하며, 백업·diff·재검사 방법이 준비된 경우에만 허용한다. 그 외 항목은 담당 AI 또는 개발자에게 배정한다. 수정한 역할은 자기 수정의 최종 검수자가 될 수 없다.

## 지휘 관계

개발센터는 어떤 AI의 개인 판단보다 위에 있는 작업 기준이다. AI는 센터가 고정한 범위·정본·검사·승인 상태를 따라 역할을 수행한다. 그러나 개발센터도 사용자 최신 지시와 승인된 원본보다 위에 있지 않다.
