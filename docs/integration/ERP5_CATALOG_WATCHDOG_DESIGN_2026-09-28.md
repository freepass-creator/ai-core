# 상품 갱신 워치독 — 설계안 (2026-09-28)

★대표 2026-09-28: 「문제 처리한 다음에 설계에서 한번 올려봐」

**아직 만들지 않았다. 대표 판단을 받는 설계안이다.**

## 막을 고장 — 오늘 실제로 당한 것

지킴이(`erp5-catalog-refresh-keeper`)가 **6일간 조용히 죽어 있었다**(9/22~9/28).

```
9/20~21  회차 3건 실패 (주간 사용량 한도)
9/22     회차 하나가 시작 7초 뒤 멈춤 — 그런데 «끝나지도» 않음 (running 상태 유지)
9/23~27  스케줄러가 「이미 도는 중」으로 보고 새 회차를 아예 안 검  → 약 44회 증발
9/28     대표가 물어서 알았다
```

멈춘 자리는 **권한 승인 대기**였다. 무인 실행이라 눌러 줄 사람이 없다. 프로세스 목록에 `ops-watch` 도 `gh` 도 없었다 — 일하다 느린 게 아니라 아무것도 안 하고 서 있었다.

★**핵심은 「실패」가 아니라 「안 끝남」이다.** 실패는 다음 회차가 돈다. 안 끝나면 **전부** 막힌다.
그리고 지금 그걸 알아채는 장치가 없다. 이번에도 사람이 물어서 알았다.

## 설계 원칙 — 왜 또 Claude 예약작업이면 안 되나

워치독을 Claude 예약작업으로 만들면 **같은 병에 같이 걸린다**(승인 대기 · 사용량 한도 · 앱이 닫혀 있음).
감시자는 감시 대상보다 단순해야 한다.

그래서 **이미 검증된 패턴을 그대로 쓴다** — `kakao-remote/scripts/카톡-워치독.ps1`:
멍청한 PowerShell 무한 루프 · 상태는 파일 · 자신이 죽는 것은 Windows 시작프로그램이 받는다.

| 재사용 | 무엇을 |
|---|---|
| `ai-core/scripts/ops-watch.mjs` | 발행 상태 읽기 — **새로 세지 않는다**, 정본 관측은 이미 여기 하나다 |
| `kakao-remote/scripts/카톡-워치독.ps1` | 루프·pid·로그·시작프로그램 구조 (형태만 베낀다) |
| `kakao-remote` 카톡 전송 | 알림 통로 — 새 알림 수단을 만들지 않는다 |
| **새로 만드는 것** | 얇은 glue 하나: `상품-워치독.ps1`. `CREATE_NEW_JUSTIFIED` — 위 셋을 잇는 자리가 없고, 어느 하나를 고쳐서 대신할 수 없다 |

## 무엇을 보나 — 지킴이의 건강이 아니라 «발행 나이»

지킴이가 도는지 세지 않는다. **영업자에게 실제로 문제가 되는 것**만 본다: 상품이 언제 마지막으로 발행됐나.

지킴이가 죽어도 GitHub 예약이 돌면 문제가 아니다(실제로 9/23~27 이 그랬다 — 그래서 티가 안 났다).
반대로 지킴이가 멀쩡해도 발행이 멈추면 문제다. **증상을 보는 게 맞다.**

```
매 10분:
  1) ops-watch 를 읽는다 (읽기 전용)
  2) 지금이 월~토 KST 09:00~20:00 이 아니면 → 아무것도 안 한다
  3) 발행 나이 > 90분  → 알린다   (매시 예약이 «두 번 연속» 빠진 것)
  4) 「자료도 안 바뀜」 → 알린다   (진짜 고장)
  5) ops-watch 를 못 읽음(UNKNOWN) 3회 연속 → 알린다 (열쇠·경로가 또 사라진 것)
  6) 같은 발행판으로는 한 번만 알린다 — 10분마다 같은 말 하지 않는다
```

## 하지 않는 것 — 여기가 중요하다

- ★**워치독은 워크플로를 걸지 않는다.** 쓰는 곳은 지금도 앞으로도 지킴이 하나다.
  둘이 걸면 이중 발행 위험이 생기고, 무엇보다 **지킴이가 있으나 마나가 된다.**
  워치독의 일은 「예약이 빠졌다」가 아니라 **「지킴이가 안 보인다」를 사람에게 알리는 것**이다.
- **멈춘 Claude 세션을 죽이지 않는다.** 프로세스를 밖에서 죽이는 건 되돌리기 어렵고, 엉뚱한 세션을 죽일 수 있다.
  알림에 「멈춘 회차가 있다 — Stop 눌러 달라」를 적는 데까지만 한다.
- 코드·시트·저장소를 건드리지 않는다. RTDB 는 어떤 경우에도 쓰지 않는다.

## 먼저 할 것 — 워치독보다 이게 급하다

워치독은 **알려 주는 장치**지 고치는 장치가 아니다. 멈춤 자체를 줄이는 건 승인 규칙이다.

`C:\dev\ai-core\.claude\settings.local.json` 의 `allow` 에 지킴이가 실제로 쓰는 명령만 넣는다:

```
PowerShell(cd C:\dev\ai-core; node scripts/ops-to-ledger.mjs:*)
PowerShell(node scripts/ops-to-ledger.mjs:*)
PowerShell(gh run list -R freepass-creator/freepasserp4:*)
PowerShell(gh workflow run erp5-ssot-refresh.yml -R freepass-creator/freepasserp4 --ref main -f apply=true)
```

앞의 셋은 읽기 전용, 마지막 하나만 쓰기이며 저장소·워크플로·인자가 전부 고정돼 있다.
★**이건 AI 가 자기 권한을 넓히는 일이라 대표가 직접 넣어야 한다.** 안전장치가 AI 의 수정을 막는다(실측, 맞는 동작).

## Codex 반례 (2026-09-28 · 1순위 규칙대로 물었다)

> **(4) 유지.** 자동복구는 단일 발행자·멱등키·락 보장 후에만.
> **발행 나이는 빈·부분·오발행과 조회·알림 고장을 놓친다.**
> 오늘 장애는 90분 뒤 탐지하지만 **PC·망·워치독 동시 장애엔 침묵한다.**
> **승인 규칙만으론 부족하다.**

네 개 다 맞다. 설계를 이렇게 고친다.

**① 나이만 보지 않는다 — 「발행됐다」와 「제대로 발행됐다」는 다르다.**
시각이 새것이어도 내용이 비었거나 반만 들어갔으면 영업자에겐 더 나쁘다(틀린 값을 믿게 된다).
그래서 나이와 함께 본다:

```
· 줄 수가 0 이다                      → 빈 발행. 즉시 알린다
· 줄 수가 직전 발행의 70% 미만이다     → 부분 발행 의심. 알린다
· ops-watch 가 「자료도 안 바뀜」       → 오발행. 알린다 (이미 있던 조건)
```
직전 값은 워치독이 자기 state 파일에 남긴다 — **새로 세지 않고, 지난 관측과 견준다.**

**② 감시자 자신이 죽는 경우 — 침묵을 침묵으로 두지 않는다.**
워치독이 죽거나, PC 가 꺼졌거나, 망이 끊기면 **아무 알림도 안 온다.** 「조용함」과 「정상」이 구별되지 않는다.
그래서 **살아있음 신호(heartbeat)** 를 둔다:

```
· 워치독은 점검할 때마다 state 파일에 시각을 남긴다 (조용해도 남긴다)
· 지킴이(Claude)가 돌 때 그 파일 나이를 본다 — 30분 넘게 멈춰 있으면 보고한다
  → 둘이 서로를 본다. 한쪽만 죽으면 다른 쪽이 안다
· 둘 다 죽는 경우(PC·망)는 «이 PC 밖»에서만 잡힌다 → GitHub Actions 예약 점검.
  지금은 과금이 막혀 불가. ★풀리면 이걸 먼저 한다 — 그게 유일한 진짜 방어선이다
```
★**그때까지는 「PC 가 꺼져 있으면 아무도 모른다」가 남은 위험이다.** 감추지 않고 적어 둔다.

**③ 자동복구를 나중에 열 조건 (Codex 가 준 문턱).**
지금은 (4)대로 워치독이 안 건다. 여는 건 셋이 갖춰진 뒤다 — **발행자가 하나임이 보장되고 · 멱등키가 있고 · 락이 있을 때.**
지금은 셋 다 없다. 그래서 「알리기만」이 맞다.

**④ 승인 규칙만으로는 부족하다.**
승인 규칙은 «오늘 겪은 그 원인» 하나를 막는다. 사용량 한도·앱 닫힘·다른 이유의 멈춤은 그대로다.
그래도 **먼저 넣는 것은 맞다** — 가장 흔한 원인을 0원에 없앤다. 워치독은 그다음이다.

## 검토해 본 대안과 탈락 이유

| 안 | 왜 안 골랐나 |
|---|---|
| GitHub Actions 예약 점검 | 가장 깨끗하다(이 PC 와 무관). **지금 Actions 과금이 막혀 CI 가 전부 안 돈다** — 풀리면 이쪽으로 옮기는 게 맞다 |
| Claude 예약작업 하나 더 | 감시자가 감시 대상과 같은 병에 걸린다(승인 대기·사용량 한도·앱 닫힘) |
| 지킴이가 스스로 유령 회차를 정리 | **불가능하다.** 유령 회차가 있으면 다음 회차가 «시작조차» 안 된다 |
| 원장(work-ledger) 신선도 검사 | 좋지만 «무언가가 그 검사를 돌려야» 한다 — 결국 같은 문제. 워치독이 생기면 그 위에 얹는다 |

## 남은 판단 — 대표가 정할 것

1. **알림을 어디로 받나** — 카톡(기존 자산, 즉시 가능) / 화면 알림 / 로그 파일만
2. **90분이 맞나** — 매시 예약이 두 번 빠진 시점. 더 예민하게(60분) 또는 느슨하게(120분)
3. **워치독을 지금 만드나** — 승인 규칙만 넣어도 오늘 겪은 고장은 안 난다. 워치독은 «그래도 또 멈출 때»를 위한 것이다
