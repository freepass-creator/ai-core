# CONTINUOUS LEARNING — 대화에서 시스템까지

상태: `candidate`  
정책 revision: `2026-09-13.1`

## 목적

AI Core는 대화에서 나온 수정 요구·실패·성공·새 판단을 일회성 기억으로 소비하지 않는다. 의사결정을 바꿀 수 있는 교훈만 비식별 관찰로 정규화하고, 재현 가능한 원칙과 작은 검사로 바꾼 뒤 AI Core/AIOPS/DevCenter의 개선 후보로 보낸다.

“완벽”은 선언 가능한 상태가 아니다. 이 정책에서 완료란 **선언한 범위·입력·revision·정책 시점 안에서 알려진 차단 요인이 없고, 모든 필수 증거가 연결된 상태**다. 범위·원본·코드·법령·정책이 바뀌면 이전 PASS는 `STALE`이며 다시 검증한다.

## 입력 경계

대화 원문, 전체 transcript, 사건 개인정보, 비밀값은 AI Core 저장소에 복사하지 않는다. 학습 입력은 다음만 허용한다.

- 비식별화된 `summary`와 기대 행동
- 불투명한 대화/자료 포인터와 관찰 시각 또는 revision
- 적용 도메인
- 근거 권위: 사용자 직접 지시 / 관찰된 결과 / 검증된 원본 / AI 추론
- 원인 원칙, 필요 조건, 실패 조건, 반례, 작은 검사

`sanitized=true`가 없거나 raw-content 계열 필드가 있으면 입력 자체를 거부한다. 이 값은 상위 수집기의 비식별화 확인 표시이지, AI Core가 내용의 민감성을 의미적으로 증명했다는 뜻은 아니다. 일부 입력만 유효해도 나머지 거부를 숨기지 않고 전체 학습 묶음을 HOLD한다.

## 승격 수명주기

`OBSERVATION → PATTERN → PRINCIPLE → SYSTEM_CANDIDATE → TRANSFER_READY → ADOPTED → PROPAGATED → OUTCOME_OBSERVED`

| 단계 | 필요한 것 | 아직 뜻하지 않는 것 |
|---|---|---|
| OBSERVATION | 출처 포인터가 있는 비식별 관찰 | 일반 법칙 |
| PATTERN | 반복 근거 또는 사용자 직접 지시 | 구현 승인 |
| PRINCIPLE | 원인·필요/실패 조건·반례 | 시스템 반영 |
| SYSTEM_CANDIDATE | 원칙을 깨뜨리거나 보장하는 작은 검사 | 채택·배포 |
| TRANSFER_READY | 재현·동일 revision 검사·독립검토·롤백·대상 수용 | 대상 기관의 최종 실행 |
| ADOPTED | 소유 기관의 승인된 정본 반영 | 전 프로젝트 효과 |
| PROPAGATED | 적용 대상과 revision이 기록된 전파 | 성과 개선 |
| OUTCOME_OBSERVED | 기준선과 사후 지표 비교 | 영구 PASS |

같은 `rule_key`에 상반된 기대 행동이 있으면 증거 권위(사용자 직접 지시 → 승인 원본 → 관찰 결과 → AI 추론)를 먼저 비교하고, 같은 권위에서는 유일하게 더 최신인 명시 지시를 적용한다. 우선순위로 단일 승자를 정할 수 없으면 `HOLD_CONFLICT`다. 과거 증거는 삭제하지 않고 superseded 관계로 남긴다.

## 귀속

- 개발 capability·검사·재사용 규칙 → DevCenter
- 법률·사업·문서·커뮤니케이션의 업무 지식과 SOP → AIOPS
- 여러 기관에 걸친 원칙, 라우팅, 증거 모델, 학습 충돌 → AI Core

귀속이 복수이면 AI Core가 중재 후보를 만들 뿐, 두 정본을 자동 병합하지 않는다.

## 처음 반영한 대화 유래 원칙

이번 candidate는 대화 원문을 저장하지 않고 다음 추상 원칙을 실행 계약으로 반영한다.

1. 사용자 최신 명시 지시와 현재 현실을 오래된 문서나 AI 합의보다 우선한다.
2. 목적·범위·완료조건·SSOT·revision을 작업 시작 전에 고정한다.
3. 사실·가설·추론·불확실성을 분리하고 UNKNOWN을 추측으로 채우지 않는다.
4. 작성·검증·승인·실행·성과를 별도 상태와 증거로 관리한다.
5. 파일 존재·hash·핵심 값·실행된 검사를 확인하지 않고 만들었다거나 PASS라고 말하지 않는다.
6. 완료조건마다 안정적인 ID·fingerprint·검증 방식(자동/수동/외부)을 주고 같은 task/project/revision/요구사항 digest의 영수증으로 연결한다.
7. 실패·SKIP·0회 실행·다른 revision·고아 영수증은 PASS가 아니다.
8. 원본 데이터는 보존하고 노출용 정규화 필드는 분리하며, 낮은 신뢰 매핑은 사람이 확인한다.
9. 시각 변경은 코딩 전 승인 시안 또는 최신 지시의 명시적 면제를 요구한다.
10. 운영 배포·삭제·대량 실제 데이터 변경·권한 변경·외부 발행은 자동 실행하지 않는다.
11. 모든 과거 대화를 싣지 않고 현재 결정에 영향을 주는 결손만 조회·적용한다.

## 도메인별 증명

공통 게이트 위에 도메인별 실패 방식에 맞는 증명 의무를 더한다.

| 도메인 | 별도 핵심 증명 |
|---|---|
| 개발 | 입출력·상태전이, 보안, 재사용, 정상/실패/회귀, UI 시안, 배포·롤백, 관찰 가능성 |
| 법률 | 관할·쟁점·구제, FACT/EVIDENCE/상대 주장/INFERENCE/AUTHORITY/UNCERTAINTY, 연표, 최신 공식 근거, 기한, 최강 반론, 인용, 책임 있는 인간 검토 |
| 사업 | 계약/매출/현금/행동/성과 분리, 비용·마진·현금흐름, 가정·민감도, 하방 위험, 기준선 대비 성과 |
| 문서 | 목적·독자, 원본·인용, 숫자/날짜/용어 일관성, 실제 렌더, 접근성·개인정보 |
| 커뮤니케이션 | 발신자·수신자·채널, 사실·약속·첨부, 행동·기한, 어조·공개범위, 초안/승인/발송/수신/성과 분리 |

법률 작업은 AIOPS 기억만으로 READY가 되지 않는다. 적용 시점의 최신 공식 법령·판례·절차 원본 포인터와 책임 있는 인간의 동일 revision 최종 검토가 필수다.

## Truth State 불변식

- `artifact=CREATED`는 `verification=PASS`가 아니다.
- PASS는 1회 이상의 실제 검사, 실패 0, SKIP 0, 같은 artifact revision을 요구한다.
- 각 증명 영수증은 검증자·시각·산출물 포인터·실행 로그·근거 포인터를 요구한다.
- 수동 기준은 같은 revision의 `CONFIRMED`, 외부 기준은 실제 `EVIDENCED` 전까지 `PARTIAL`이다.
- 승인 근거 없이 실행 성공을 주장할 수 없다.
- 실행 로그 없이 실행 성공을 주장할 수 없다.
- 기준선·사후값·관찰 근거 없이 성과 개선을 주장할 수 없다.
- 현재 revision과 다른 PASS는 `STALE`다.

## 현재 범위

v0.4 candidate는 정규화·중복 제거·충돌 차단·성숙도 분류·귀속·증명 계약·영수증 평가까지 구현한다. 실제 ChatGPT 대화 수집, 대상 기관 자동 제출, 채택, 배포, 외부 발송, 성과 수집은 실행하지 않는다.
