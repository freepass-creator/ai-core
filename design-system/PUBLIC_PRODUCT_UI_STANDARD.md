# Public Product UI Standard

최종: 2026-09-19  
상태: CURRENT / AI Core 공개형 상품 UI 규격

## 1. 기준 구현

공개형 상품 조회·검색 화면의 기준 구현은 **ERP4 White Label / freepasserp.com Product Browse**다.

이 규격은 내부 업무용 Admin UI를 그대로 복사하지 않는다. 대신 다음을 공통으로 공유한다.

- 정보 위계
- 토큰 체계
- 여백 사다리
- 상태·행동 문법
- 반응형 원칙
- 접근성 기준
- 색상 사용 원칙

즉 **Admin과 Public Product는 같은 디자인 시스템의 서로 다른 프로필**이다.

## 2. 제품 인상

목표는 화려함이 아니라 다음 네 가지다.

- 깔끔하다
- 잘 정리됐다
- 빠르게 찾을 수 있다
- 모바일에서도 자연스럽다

피할 것:

- 과한 카드 장식
- 모든 값을 badge/chip으로 표현
- 큰 고정 chrome
- 불필요한 그림자
- 지나치게 둥근 모서리
- 과장된 마케팅형 대형 텍스트
- PC 화면을 그대로 축소한 모바일

## 3. Public Product 기본 구조

### Desktop

`Search → Quick Filter → Side Filter + Product Grid → Detail`

- 최대 콘텐츠 폭: 1280
- 좌측 필터: 260
- 기둥 간격: 32
- 중간 웹: 상품 3열
- 1280px 이상: 상품 4열
- 상세 읽기 폭: 1120
- 상세은 목록 폭에 억지로 맞추지 않는다

### Mobile

`Search / Filter → Product List → Product Detail`

- 상품 1열
- 검색/상세조건 진입은 상단에 둔다
- 빠른조건은 가로 스크롤
- 조건은 시트로 연다
- 주요 터치영역 최소 44px
- 목록으로 돌아왔을 때 검색·필터·스크롤을 가능한 한 복원한다

## 4. 목록 카드 규격

디자인은 크고 화려하게 만들기보다 **비교 밀도**를 우선한다.

### 기본 웹

- 3열
- 카드 내부 정보 순서: 차량명 → 사실줄 → 기간·대여료·보증금 → 조건
- 카드 내부 주요 줄 간격: 8
- 가로 카드 간격: 16
- 세로 카드 간격: 24

### Wide Web (1280px 이상)

- 4열
- 차량명: 14px
- 월 대여료: 18px
- 보조정보: 12.5px
- 캡션/작은 라벨: 11.5px
- 카드 내부 정보 순서와 위계는 바꾸지 않는다

### Mobile

- 1열 유지
- 모바일 폰트는 넓은 웹 조밀화의 영향을 받지 않는다
- 터치 편의 때문에 카드 자체를 무리하게 축소하지 않는다

## 5. Typography

타이포는 크기 자체보다 **서로의 비율**을 지킨다.

- 차량명 > 보조정보
- 대여료 > 보조정보, 단 차량명보다 지나치게 앞서지 않음
- 섹션 제목 > 본문
- 라벨 < 값
- 숫자·금액은 tabular numeral을 우선
- 한 화면에서 의미 없이 0.5~1px 차이의 새 단계들을 계속 만들지 않는다

상세화면은 목록보다 읽기 중심이므로 목록 카드 축소값을 그대로 적용하지 않는다.

## 6. Spacing

배치 여백은 의미별 사다리를 사용한다.

- 4: 붙은 것
- 8: 한 덩어리 안
- 12: 덩어리 경계
- 16: 화면 가장자리 / 조밀한 카드 가로 간격
- 24: 서로 다른 카드·구역
- 32: 큰 기둥 사이
- 48: 넓은 웹의 큰 그룹 분리

임의의 10, 14, 18, 20, 28 같은 배치 여백을 새로 만들지 않는다. 광학 보정은 예외다.

## 7. Radius

- 표시/작은 badge: 8
- control: 10
- card: 12
- 원형이어야 하는 것만 999

모든 요소를 pill로 만들지 않는다.

## 8. Search Feedback

검색 결과는 별도 설명 배지나 새 줄을 추가하기보다 **이미 보이는 일치 값**을 옅게 강조한다.

- 차량명·차번·연식·연료 등 보이는 값이 검색어와 직접 맞으면 그 부분만 강조
- `저신용 → 무심사`, `무보증 → 보증금 없음`처럼 검색 별칭이 화면 표기와 다르면 화면의 canonical 값을 강조
- 강조는 브랜드색의 매우 옅은 배경 수준으로 제한
- 결과 카드 구조와 줄 수는 검색 때문에 늘리지 않는다

## 9. Detail

ERP4 White Label 상세를 현재 기준 구현으로 사용하되, 상세는 계속 미세 개선 대상이다.

현재 유지:

- 웹 1120 읽기 폭
- 모바일/웹 같은 상하 스크롤 순서
- 사진 → 차량 식별 → 대여료 → 차량정보 → 보험/이용조건
- 상세 사진 4:3
- 웹은 섹션 제목 200px 기둥 + 내용
- 모바일은 한 열

웹 상세의 기존 sticky 실행줄(`목록으로 ↔ 공유`) 가운데에는 `대여료 · 차량정보 · 보험 · 이용조건` 인페이지 길잡이를 둘 수 있다. 이는 내용을 감추는 탭이 아니라 현재 긴 페이지 안에서 이동만 하는 anchor navigation이다.

개선은 구조를 갈아엎지 않고 다음 순서로 한다.

1. 제목·섹션명·요금의 타이포 위계
2. 섹션 사이 세로 리듬
3. 불필요한 선/박스 제거
4. 긴 값 줄바꿈
5. sticky header/action의 높이와 충돌

## 10. Profile Separation

### Admin Profile

- 고밀도 업무
- 30~38px 중심 컨트롤
- 표·목록 스캔 우선
- 내부 업무 속도 우선

### Public Product Profile

- 탐색·비교
- 웹 44 / 모바일 48 수준의 주요 컨트롤
- 모바일 최소 44px 터치영역
- 카드/사진/조건 탐색 우선
- 공개 화면 신뢰감 우선
- 반복되는 장식 애니메이션보다 hover/focus/press 등 **사용자 행동에 대한 반응**을 우선

두 프로필의 픽셀 값을 억지로 같게 만들지 않는다.

## 11. Acceptance

공개형 상품 UI 변경 시 최소 다음을 확인한다.

- 360 / 390 / 412px
- 1280 / 1440px
- 검색
- 빠른조건
- 상세조건
- 0건
- 긴 차량명
- 긴 보증금 문구
- 사진 없음/1장/여러 장
- 스크롤 복원
- 키보드 focus
- reduced motion
- 모바일 safe-area

목록 카드에 hover 사진 넘김이나 별도 썸네일 탐색 UI는 기본 표준에 포함하지 않는다. 2026-09-19 ERP4 기준에서 제외했다.

## 한 문장

> **Public Product UI는 ERP4 White Label의 정돈된 탐색 경험을 기준으로 삼고, 프로젝트마다 다시 디자인하지 않는다.**
