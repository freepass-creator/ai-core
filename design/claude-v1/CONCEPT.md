# Claude v1 — 컨셉

> **Status: NOT_CANONICAL / HISTORICAL DESIGN STUDY (2026-09-26)**  
> 이 폴더는 2026-09-23 당시의 디자인 탐색 기록이다. 아래의 `tokens.json` 정본 선언과 규칙은 현재 정본이 아니다. 현재 UI/UX 정본은 `docs/UI_UX_START_HERE.md` → `design-system/tokens.json` → `design-system/runtime-v2.css`/registries 순서다. 이 문서를 근거로 새 UI 규격이나 별도 토큰 체계를 만들지 않는다.

대표가 정한 것은 한 줄이다.

> **심플하고 미니멀. 대신 구분이 되어야 하고 표시가 되어야 하고 기능은 다 할 수 있어야 한다.
> 버튼과 박스에는 라인이 없다.**

나머지는 그 한 줄에서 기계적으로 따라 나와야 한다. 취향이 끼어들면 그건 규격이 아니다.

---

## 1. 규칙은 «지워 보고 확인한다»

선·그림자·구분선·상자를 지운 뒤 세 가지를 본다.

1. **자리가 구분되나** — 면 대비·간격·글자 위계로
2. **상태가 읽히나** — 면·굵기·아이콘·글 중 **둘 이상**이 바뀌나. 색 하나로는 안 된다
3. **기능이 그대로인가** — 같은 명령, 같은 키보드 경로

셋 중 하나라도 무너질 때만 그 요소를 남긴다. 그래서 남은 것이 **입력의 밑줄**과 **표·목록의 읽기 줄**, 그리고 **파일 놓는 자리의 점선**뿐이다.

이 판정이 규범과 충돌하지 않는다는 근거: WCAG 2.2 SC 1.4.11 은 «요소를 식별하는 데 필요한» 시각 정보에만 3:1 을 요구하고, Understanding 문서는 *글자나 충분한 대비의 아이콘이 있으면 경계선은 요구되지 않는다* 고 적는다.

## 2. 값은 세어서 쓴다

| 축 | 값 | 그 사이 값 |
|---|---|---|
| 글자 크기 | 7단 (12·13·14·15·17·20·22·28) | 만들지 않는다 |
| 굵기 | 3단 (400·600·700) | 500·800 금지 |
| 모서리 | 4값 (알약·12·8·4) | 6·10·16·20 금지 |
| 면 | 3층 (바탕·면·옅은 면) + 목록 박스 | 4층이 필요하면 화면을 잘못 나눈 것이다 |
| 강조색 | 1개 | 상태색은 상태일 때만 |

값의 정본은 [`tokens.json`](tokens.json) 이다. CSS 와 화면은 여기 없는 값을 쓰지 못한다 — [`scripts/check-claude-v1.mjs`](../../scripts/check-claude-v1.mjs) 가 잡는다.

## 3. 모서리가 뜻을 나른다

선이 없으면 모양이 몇 안 되는 신호가 된다. 그래서 모서리는 장식이 아니라 **분류**다.

- **알약** — 버튼·뱃지·태그·아바타·스위치·라디오 (주류가 캡슐로 간다: Material 3 Expressive · Apple 2025)
- **8px** — 칩(필터)·목록 줄 (여러 개가 나란히 선다. 각져야 줄이 정돈된다)
- **12px** — 박스·카드·대화상자·알림 (담는 것)
- **4px** — 체크박스만 (라디오와 **모양**으로 갈라야 한다)

## 4. 상태는 사다리다

기본 → 호버 → 선택 → 선택+호버가 **각각 다르게** 보여야 한다. 호버는 중립 층(회색), 선택은 강조 면(보라) — **다른 축**이라 겹쳐도 읽힌다.

실측(밝은 화면): 기본 1.09:1(흰 면) · 호버 +1.12 · 선택 1.25(기본 대비) · 선택+호버 +1.13. 상태 층 불투명도는 Material 3 공표값(hover .08 / pressed .10)에 맞춘다.

## 5. 목록의 «한 건»은 박스다

선택이 박스를 **만들지** 않는다. 선택은 이미 있던 박스를 **바꾼다**. 줄 목록·카드·이력이 모두 같은 박스를 쓴다. 표와 값 묶음(라벨-값)은 목록이 아니므로 박스가 아니다 — 표는 가로줄로, 값 묶음은 글자 위계로 읽는다.

## 6. 글자가 진짜 일을 한다

부품은 단순하다(버튼·입력·검색·표·박스). 어려운 것은 그 **안의 글자**다. 부품마다 어떤 글자가 몇 px·몇 굵기·무슨 색인지는 [글자 규격](../../examples/claude/spec.html)에 못 박혀 있고, 한글·영문을 한 벌로 덮는 Pretendard Variable 을 **실제로 불러온다**(이름만 적어 두면 설치 안 된 기기에서 두 얼굴로 섞인다 — 2026-09-23 실측으로 데였다).

## 7. 하지 않는 것

1. 버튼·박스·카드·칩·뱃지·대화상자에 테두리를 그리는 것
2. 그림자를 쓰는 것 (겹친 판은 가림막으로 가른다)
3. 색 하나로 상태를 말하는 것
4. 토큰에 없는 값을 화면에서 만드는 것
5. 한 화면에 «면을 가진 버튼»을 둘 이상 두는 것
6. 네이티브 체크박스·라디오를 그대로 쓰는 것 (브라우저가 1px 테두리를 그린다)
