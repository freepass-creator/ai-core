# v1.1 결정 이력 — freepass-admin 에서 날짜별로 쌓인 머리글 (2026-09-24~25)

erp.css 는 이제 부품마다 한 번만 정의한다. 예전에 CSS 안에 날짜별 머리글로 쌓여 있던 결정 기록을 여기로 옮겼다 — 규칙은 erp.css, 왜 그렇게 정했는지는 여기.
원래 순서(오래된 것 → 새 것) 그대로다. 대표 발언 원문은 README 본문과 freepass-admin docs/ui/admin-ui-ux-ssot.json 에 있다.

## 1. 2026-09-24 — Surface type / Interaction hierarchy

* 물성은 타입이 정하고, 상호작용은 hover가 정한다.
- Card/Box/Button = 같은 기본 높이(elevation-1)에서 시작
- Passive card = 떠 있지만 hover 없음
- Interactive card/button = 같은 기본 높이 + hover/press
- Selected = 더 뜨지 않고 눌려 고정
- Card line / Control line / Input line 은 서로 다른 역할 토큰

## 2. 2026-09-24 — Borderless search.

크기·padding·radius·배치는 그대로. 보이는 선만 없애고 surface + focus elevation으로 입력 affordance를 만든다.

## 3. 2026-09-24 — Line-free UI standard

* visible border는 쓰지 않는다.
hierarchy는 surface + elevation + spacing + state로 만든다.
Web Panel은 canvas 위의 surface island, Mobile Panel은 screen surface.

## 4. 2026-09-24 — Final line-free semantic hierarchy

canvas → panel → component → state.
Badge(signal)와 Control(action/selection)을 절대 같은 물성으로 만들지 않는다.

## 5. 2026-09-24 — Scale normalization

FreePass Admin에서 먼저 검증하는 공통 스케일.
generated erp-standard.css를 직접 수정하지 않고 consumer override로 압축한다.
* Typography: 24 / 20 / 18 / 16 / 14 / 12
Spacing:    4 / 8 / 12 / 16 / 20 / 24 / 32
Desktop:    small 32 / standard 36 / row 40 / topbar 56
Mobile:     control/action/touch 44 (admin-final.css)
Radius:     4 / 6 / 8 / pill

## 6. 2026-09-24 — Surface depth refinement

Canvas → Panel → Component surface의 색 차이까지 명시한다.
shadow만으로 hierarchy를 만들지 않는다.

## 7. 2026-09-24 — Interaction state consistency

focus-visible도 line-free 문법 안에서 soft halo로 통일한다.

## 8. 2026-09-24 — Density contract

실제 업무 화면의 세로 리듬을 padding 우연값이 아니라 명시적인 tier로 고정한다.

## 9. 2026-09-24 — Alignment & information hierarchy

text=left, numeric/money=right, status=compact, actions=foot.

카드↔카드=12px, 섹션↔섹션=16px.

## 20. 2026-09-25 — Detail panel inner rhythm

상세는 슬림하게, 카드/섹션 계층은 유지한다.

## 21. 2026-09-25 — Natural ERP typography roles

숫자 토큰만 바꾸고 generated component의 옛 크기가 남는 일을 막는다.
화면마다 예쁘게 꾸미지 않고, 통상적인 업무도구의 크기 위계만 고정한다.

## 22. 2026-09-25 — Typography weight hierarchy

굵기는 위계에, 선택 상태는 surface에 맡긴다.

## 23. 2026-09-25 — Flat resting surfaces, subtle interaction elevation

평상시는 납작하게, hover/floating에서만 elevation을 쓴다.

## 24. 2026-09-25 — Brand restraint & neutral selected-card text

큰 카드 선택은 tint로, brand 색은 compact selection/action에 집중한다.

## 25. 2026-09-25 — Compact card signal de-duplication

상태 썸네일이 이미 상태를 전달하면 같은 Badge를 제목 옆에 반복하지 않는다.
wide card에서는 thumb가 사라지므로 Badge를 유지한다.

## 26. 2026-09-25 — Residual divider cleanup

장식성 선은 제거하고, 의미 있는 구조선만 남긴다.

## 27. 2026-09-25 — Compact signal hierarchy

QuickFilter=pill, Badge/Status=compact rounded rect, Tag=smallest signal.

## 28. 2026-09-25 — No-wrap responsive density

좁은 폭에서 세로로 비대해지지 않게 choice/action rows는 가로 흐름을 유지한다.

## 29. 2026-09-25 — Solid commercial ERP materiality

기본 화면은 뜨지 않는다. Canvas → Panel → Component의 surface 차이와
정렬/간격으로 구조를 만들고, shadow는 hover/floating에만 제한한다.

## 30. 2026-09-25 — Geometry contract

단단함은 장식보다 geometry 반복에서 만든다.
Panel 8 / Card·Tile 6 / Control 6 / card padding 12.

## 31. 2026-09-25 — Card line contract

목록 카드는 줄 수가 먼저 정해지고, 정보는 그 줄 안에 들어간다.
내용 때문에 카드 구조를 매번 새로 늘리지 않는다.

## 32. 2026-09-25 — Three-line list card semantics

1행 Main / 2행 Key / 3행 Support. 상태는 Main 옆 compact badge.

## 33. 2026-09-25 — 64px visual tile contract

차량=실사진 우선 / 일반목록=동일 크기 상태 아이콘+텍스트.
본문 3줄(20+2+20+2+20=64)과 시각 타일 높이를 정확히 맞춘다.

## 34. 2026-09-25 — Status tile semantic tones

진행/info=navy, 완료/ok=green, 보류/warn=amber, 오류/err=red, neutral=grey.

## 35. 2026-09-25 — Detail information row contract

## 36. 2026-09-25 — Embedded one-line offer selection list

## 37. 2026-09-25 — Balanced compact list columns

## 38. 2026-09-25 — Stable list card rhythm

## 39. 2026-09-25 — Compact list text rails

## 40. 2026-09-25 — Content panel horizontal rails
