```
[1 상품찾기 — 한 화면]                                   [2 계약접수]              [3 실적] → [4 정산관리]
 ① 차 고르기 → ② 요금 고르기 → ③ 접수 넣기 ─ 접수 저장 ─▶ «계약서 받기» 묶음 → 인도하기 → 청구하기 → 수금·지급 확인
```

## 상품 · 접수 한 화면 (`index.html`)

왼쪽에서 오른쪽으로 한 길. 화면을 옮기지 않는다. 칸 머리에 번호(끝난 칸 ✓), 칸 사이 › 화살표.

| 칸 | 하는 일 |
|---|---|
| ① 차 고르기 | 검색창 + 상세 필터(건 조건은 칩) + 출고상태 탭 → 두 줄 긴 카드(차명 · 차번 · 월 대여료 · 연식 · 색 · 공급사 · 우대조건) |
| ② 요금 고르기 | 고른 차의 상세 + 기간별 요금. 조건에 맞는 요금이 골라져 있고, 기간을 누르면 그 요금이 ③ 으로 간다 |
| ③ 접수 넣기 | 차 · 요금 · 수수료(ERP5 수수료표)는 자동. 사람이 넣는 건 고객 · 영업채널 · 담당(+ 결제 · 계약방식)뿐. 나머지는 «더 넣기» |

접수 저장 → 계약접수 «계약서 받기» 묶음에 올라간다. 같은 차량번호 + 접수일이면 새로 만들지 않고 그 건을 연다(기능 규칙 그대로).

## 고도화 (대표 2026-09-23 「좋네 조금 더 고도화해줄래」)

| 자리 | 더한 것 | 왜 |
|---|---|---|
| ② 요금 | 기간마다 **남는 것**(청구 − 지급, ERP5 수수료표) + «가장 많이 남음» | 기간을 값이 아니라 돈으로 고른다 |
| ③ 고객 | 이름을 치면 **이전 고객**을 찾고, 고르면 영업채널 · 담당까지 채움. 없으면 «새 고객으로 넣기» | 다시 오는 고객은 한 번에 |
| ③ 저장 전 | **확인 줄** — 차량번호 중복 없음 · 요금이 ERP5 와 같음(기준 시각) · 분납 주의 | 잘못 넣고 되돌리는 일을 막는다 |
| ③ 저장 단추 | **필수 3/3 채움** · Ctrl+Enter | 무엇이 빠졌는지 단추 옆에서 본다 |
| 저장 직후 | 같은 자리에 **접수번호 + 이 건의 다음 걸음 4개**(계약서 → 인도 → 청구 → 수금·지급) · «같은 고객 · 다른 차» · «다음 접수». 목록에는 «방금 접수» 표시, 걸어 둔 조건은 그대로 | 저장하고 끝이 아니라 다음 할 일로 이어진다 |
| 폰 | 세 칸을 한 장씩. 위 점 = 지금 칸, 아래 단추 = 다음 걸음(«쏘렌토 요금 보기 ›» → «36개월로 접수 ›» → «접수 저장»). 같은 부품 | 폰으로 그대로 넘어간다 |

## 카드로 통일 (대표 2026-09-23 「카드타입으로 통일해봐」)

화면의 모든 덩어리 = 카드 한 장. 두 층만 쓴다.

| 층 | 무엇 | 모양 |
|---|---|---|
| 큰 카드 | 칸 ① ② ③ · 처리 서랍 | 바탕 위에 뜬 카드(둥근 모서리 · 옅은 그림자), 머리 = 번호 + 이름, 바닥 = 단추 줄 |
| 작은 카드 | 칸 안의 정보 묶음 — 차 목록 한 대 · 차 정보 · 기간별 요금 · 우대조건 · 고른 차 요약 · 고객 · 영업 · 저장 전 확인 · 다음 걸음 · 서랍의 진행 · 처리 · 조건 · 이력 | 우묵한 바탕 위의 흰 카드. 목록 카드와 같은 선 · 모서리 |

폰도 같은 두 층(폰 화면 = 큰 카드, 안의 묶음 = 작은 카드).

## 계약접수 (`queue.html`)

목록을 날짜가 아니라 다음에 할 일(계약서 받기 · 인도하기 · 청구하기 · 수금·지급 확인)로 묶고, 카드마다 그 일을 하는 단추. 고른 건은 오른쪽 처리 서랍에서 바로 처리.

## 공통

- 흐름 메뉴(`fpa-flow`) — 좌측 메뉴 대신 1 상품찾기 → 2 계약접수 → 3 실적 → 4 정산관리. 전자계약은 오른쪽 «흐름과 별도».
- 요약 카드 · 대수 카드는 없다(대표 지시).
- 채택되면 `fpa-*` 틀을 `erp.css` 추가 부품으로 옮기고 어드민에 입힌다. 폰은 칸을 한 장씩 넘긴다(①→②→③).
