대표 2026-09-24 확정 흐름:
1. 「관리자 페이지고 공간이 여유 있으니 … 패널이 총 3개였으면 좋겠어 — 상품목록 패널 · 상세내용 패널 · 접수목록 패널」
2. 「상세내용 패널에 접수하기 버튼이 있고, 누르면 그 상세내용이 접수 패널로 바뀌는 거지」(패널 두 개로 줄이는 게 아니라 **세 개를 유지**)
3. 「목록은 다 검색 · 필터가 되어야 하니까 목록 패널 규격이 똑같다 — 목록 패널, 뭔가 작업하는 상세내용 패널이 있고,
   나중에 다 모바일로 뎁스를 넣어서 봐야 되니까 그걸 감안해서」

## 메인 페이지 — 패널 3개, 항상 같이 뜬다

```
[① 상품목록]                    [② 상세내용 — 상품상세]              [③ 접수목록]
 검색 · 필터 · 퀵필터 → 줄 카드    사진 · 조건 · 기간 카드 → 「접수하기」    검색 · 필터 · 퀵필터 → 상태 줄 카드
                                        │
                                        ▼ (같은 자리에서 뒤집힘)
                                [② 상세내용 — 접수 작성]
                                 영수증 + 고객 · 영업 폼 → 「취소」/「접수 저장」
                                        │
                                        ▼ 저장
                                (①③ 는 그대로, ③ 맨 위에 방금 접수가 상태 펼친 채로)
```

## 목록 패널 규격 — 상품목록 · 접수목록이 완전히 같다

두 목록 모두 머리가 **검색창 + 「필터」 버튼(상세 필터를 연다) + 퀵 필터 한 줄**로 똑같다(`f3v-searchbar` · `f3v-search` · `f3v-quick`).
다른 건 줄 카드 안의 내용뿐이다.

| 목록 | 줄 카드가 보여주는 것 |
|---|---|
| 상품목록 | 이 차가 무슨 차인지 — 차명 · 차번 · 트림 · 공급사 · 월 대여료 |
| 접수목록 | 이 접수가 지금 어떤 상태인지 — 고객 · 차번 · 금액 + **진행 단계가 카드 안에 작게 펼쳐짐**(접수 → 계약서 → 인도 → 청구 → 수금·지급) |

나중에 실적목록 · 정산목록도 같은 머리(검색 · 필터 · 퀵 필터)에 그 대상에 맞는 줄 카드 내용만 채우면 된다.

## 상세내용 패널 — 두 면

「접수하기」 버튼이 있는 **상품상세**가, 그 자리에서 뒤집혀 **접수 작성**(고객 · 영업 폼 + 취소/저장)이 된다(시안 G 의 뒤집기 그대로).
접수상세 · 실적상세 · 정산상세는 같은 패널 자리에 그 대상의 내용을 채운 것 — 상세내용 패널도 하나의 규격이다.

## 폰 — 뎁스 내비게이션 (4장)

PC 의 패널 셋이 폰에서는 **화면 하나씩**이 된다. 같은 부품 · 같은 클래스를 쓰고 폭만 꽉 채운다.

```
1 상품목록 (전체 화면) → 2 상세내용 · 상품상세(‹ 목록으로 뒤로) → 3 상세내용 · 접수 작성(뒤집힘, ‹ 취소로 뒤로)
                                                                        → 4 접수목록(저장 후, 방금 접수가 상태 펼친 채로)
```

- 목록 화면(1·4)은 검색창 · 필터 버튼 · 퀵 필터가 PC 와 똑같다.
- 뎁스는 머리의 «‹ 뒤로» 하나로 쌓이고 풀린다. 별도 탭바 없이 화면 전환만으로 depth 를 표현한다.
- 저장은 화면을 접수목록으로 보낸다(취소는 뎁스를 한 칸만 되돌린다).

## 공통
