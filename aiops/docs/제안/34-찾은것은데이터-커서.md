# 제안 — 찾은 것은 데이터로 박고, 다음엔 찍어서 확인한다

2026-08-26 · Cursor → 대표·Claude
상태: **제안**. 정본 아님.

대표: 「클로드가 내용을 잘 못 찾아. 일단 한번 찾은 건 정확하게 데이터화해서, 다음에 물어보면 또 찾는 게 아니라 그걸 찍어서 확인해야 하는데.」

이미 있는 말: `어디를보나.md` ③, `ROLES.md` 「알아낸 것은 그 자리에서 적는다」, `AI에게.md` 「새로 세지 마라」.
그런데도 **다음에 또 검색**한다. 문장으로 남겨서다. 도구가 못 읽으면 없는 것과 같다.

---

## 문제

| 지금 | 다음에 물으면 |
|---|---|
| 채팅·HANDOVER·INBOX에 「어디에 있더라」 | 저장소를 다시 뒤진다. 다른 파일을 집는다 |
| 마크다운 표만 늘린다 | Claude가 표를 건너뛰고 grep 한다 |
| 숫자만 `jeongbon`에 있다 | **자리**(어느 파일·어느 키·어느 헤더)는 데이터가 아니다 |

고객141 입금을 세 번 「없다」고 한 것과 같은 사고다. 숫자만이 아니라 **내용의 자리**도 매번 새로 찾는다.

---

## 바꾸자는 것 — 찾기 한 번, 확인은 그 자리

```
없다          → 찾는다 (시트·드라이브·문서)
찾았다        → 그 자리에서 JSON으로 박는다. 답하기 전에 박는다
다음에 묻는다 → 그 파일을 연다. 값을 읽는다. 기준일을 말한다
이상하다      → 그 파일에 적힌 출처만 되짚는다. 전수 검색부터 하지 않는다
없다(자리도)  → 그때만 찾는다. 찾으면 또 박는다
```

★**확인 = 저장된 자리를 가리키고, 지금 값이 그 자리와 같은지 본다.**
검색은 확인이 아니다.

---

## 쓸 칸 — `lib/찾은자리.json` (신설)

한 물음에 이 칸만. 원문·고객명 키 금지. 차번은 있어도 됨(이미 원자와 같음).

| 칸 | 무엇 |
|---|---|
| `물음` | 사람이 묻는 말의 짧은 키 (`미수.고객141`, `전화.정본열`) |
| `자리` | 파일 경로 또는 `시트명/탭/헤더명` |
| `키` | JSON 키 · 헤더명. 열 번호 아님 |
| `기준일` | 이 값이 언제까지인지 |
| `값` | 숫자·짧은 코드·「모름」. 문장 에세이 아님 |
| `확인` | 다시 읽는 명령 하나 (`node scripts/미수.mjs …`) |
| `출처` | 원본이 어디였나 (헤더명·파일명). 찾은 사람 |

이미 `daesu-jeongbon.json` · `jaryo-jeongbon.json` · `wonja/*.json` 에 들어가는 숫자는 **그쪽이 자리**다. 찾은자리에는 **아직 원자에 없는 것**(탭이 어디인지, 전화 열 이름, 문서 경로)만 넣는다. 같은 값을 두 파일에 안 적는다.

`어디를보나.md` 표는 이 JSON을 사람이 읽게 펼친 그림자다. 표만 고치고 JSON을 안 고치면 무효.

---

## 안 쓰는 칸 / 하지 말 것

- 찾은 내용을 INBOX·HANDOVER 한 줄로만 남기기
- 다음에 같은 물음으로 저장소 전체 검색
- 열 번호로 자리 박기
- 고객 원문·연락처를 `값`에 넣기
- 「없다」를 자리 없이 답하기 (구멍이면 `값: 모름` + `jaryo` 구멍)

---

## 답하는 꼴

```
고객141 미수  900,000원
자리  lib/wonja/미수.json  기준일 2026-08-19
확인  node scripts/미수.mjs 고객141   ← 지금 같은지
```

자리가 없으면 「아직 박지 않았다」고 하고 찾은 뒤에 박은 **경로를 답에 적는다.**
경로 없는 숫자는 검산값이다. 다음 세션이 못 찍는다.

---

## 검증

1. 같은 물음을 두 세션에서 한다. 두 번째 세션은 grep/시트 전수 없이 `찾은자리` 또는 해당 원자만 연다.
2. 원자가 있으면 명령을 한 번 돌려 값이 같은지 본다. 다르면 원자를 고친다. 검색으로 새 답을 만들지 않는다.
3. 제안함 번호가 겹치면(지금 28·29가 두 줄) Claude가 내용을 못 찾는다. **대장은 번호 하나=한 줄.** 겹친 대기 줄은 접는다.
