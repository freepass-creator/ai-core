# AI 문서 내비게이터 — 찾는 문제가 아니라 “현재 답을 고르는” 문제

제안자: Codex · 2026-08-26  
상태: 제안

## 문제

지금은 `AI에게`, `어디를보나`, `데이터가는길`, `오류`, `제안함`, 주제 매뉴얼이 모두 유용하다.
하지만 같은 주제의 옛 결론·새 결론·실패 원인이 여러 곳에 있어 Claude나 새 AI가 파일을 찾아도 **어느 문장이 현재인지** 다시 추론해야 한다.

문서를 더 쓰는 것으로 해결하지 않는다. 질문 하나에 필요한 문서·현재성·충돌을 바로 주는 길을 만든다.

## 제안 구조

```text
AI 질문
  ↓
docs/문서찾기.mjs "스위치 미수 얼마?"
  ↓
현재 답 패킷
  - 먼저 읽을 문서 1~3개
  - 답의 정본/허용 명령
  - 마지막 검증 시각·자료 공백
  - 살아 있는 오류·충돌 문서
  - 낡은 문서/문장을 쓰지 말라는 경고
```

## 1. 각 문서의 머리에 붙일 최소 메타정보

```yaml
status: current | reference | superseded | draft
topic: arrears | insurance | work | data | finance
answers: ["현재 미수", "입금 반영", "회수 대상"]
authority: answer | source-map | procedure | error-log | proposal
last_verified: YYYY-MM-DD
replaces: [문서 또는 결정 ID]
depends_on: [원천/도구/규격]
```

문서 본문을 바꾸는 것이 아니라, AI가 무엇을 읽어야 하는지 기계적으로 고를 수 있게 하는 주소표다.

## 2. 질문별 현재 답 패킷

예: `스위치 미수 얼마?`

```text
1. 답 규칙: AI에게.md / 미수답하는법.md
2. 데이터 경로: 어디를보나.md / 데이터가는길.md
3. 실행: 허용된 읽기 명령 1개
4. 주의: 오류.md의 미수 관련 열린 항목
5. 현재성: 마지막 수납/계좌/원자 기준시각
6. 금지: 과거 스냅샷·대여료×개월 계산 결과를 현재 답으로 사용하지 않음
```

AI는 이 패킷 밖의 넓은 시트·드라이브 탐색을 기본값으로 하지 않는다.

## 3. 문서의 역할을 겹치지 않게 정리

| 문서 | 역할 | 넣지 않을 것 |
|---|---|---|
| `AI에게.md` | 질문을 이해하고 답하는 공통 원칙 | 긴 데이터 수치·실행 이력 |
| `어디를보나.md` | 질문 → 정본/도구 주소 | 판정 근거의 긴 설명 |
| `데이터가는길.md` | 데이터 모델·원천/보관소/시트 관계 | 당일 운영 지시 |
| `오류.md` | 아직 열린 오류와 재발 방지 | 정본 답 자체 |
| `제안함.md` | 바꿀지 말지 논의와 판정 | 현행 매뉴얼 |
| `sop/` | 안전한 작업 절차 | 제품 구조 토론 |

## 4. 새 결정이 나오면 지킬 규칙

1. 새 결론은 먼저 `오류` 또는 `제안함`에서 근거와 함께 판정한다.
2. 채택되면 답 규칙·주소표·SOP 중 **영향받는 한 곳만** 갱신한다.
3. 이전 문서는 지우지 않고 `superseded`와 대체 결정 ID를 붙인다.
4. `문서찾기`가 current와 superseded를 동시에 내면 실패로 처리한다.
5. 같은 질문이 두 답을 내면 테스트 실패로 `오류`에 남긴다.

## 5. Claude가 확정할 것

1. 메타정보의 최소 필드와 current/reference/superseded의 정확한 뜻
2. `문서찾기`가 출력할 질문 패킷의 형식
3. 각 주제의 답 규칙 문서 한 곳과 데이터 경로 문서 한 곳
4. 문서 갱신과 오류·제안 판정 사이의 연결 규칙

## 기대 효과

- Claude가 필요한 내용을 “문서 이름 기억”으로 찾지 않아도 된다.
- Codex/Gemini/Cursor도 같은 질문에서 같은 현재 규칙을 시작점으로 삼는다.
- 옛 문서가 삭제되지 않아도 현재 답에 섞이지 않는다.
- 문서가 많아질수록 더 찾기 쉬워진다.
