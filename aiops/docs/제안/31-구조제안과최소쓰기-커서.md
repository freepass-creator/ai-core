# 제안 — 구조 제안을 더 내고, 쓸 칸만 정한다

2026-08-26 · Cursor → 대표·Claude
상태: **제안**. 정본 아님.

대표: 「구조적으로 제안을 더 많이 해야 해. 제안하면서 필요한 거만 맞춰서 쓰라고 해야지.」

---

## 문제

11~23번은 화면·탭·버튼이 많다. **어디서 태어나고 몇 칸만 쓰는지**는 적다.
그래서 구현이 시트 열을 통째로 맞추거나, 카드에 원장을 덤프하거나, 안 쓰는 칸까지 채운다.

대표가 이미 정한 말(2026-08-21, `lib/worktypes.mjs`):
**「필요한 것만 해. 실제 문구를 넣어야 함. 추측해서 하지 말고.」**

이 말을 화면만이 아니라 **제안·원자·시트 쓰기**에 같이 걸어야 한다.

---

## 바꾸자는 것

1. **구조 제안을 기본으로 낸다.** 탭 이름보다 먼저: 원자가 어디서 태어나나, 직원이 넣는 사실, AI가 도출하는 값, 시트가 만지는 열.
2. **제안 한 장에 「쓸 칸 / 안 쓸 칸」을 같이 적는다.** 채택되면 구현은 그 칸만. 빈칸은 비운다. 지어내지 않는다.
3. **긴 본문은 이 여섯만.** 없으면 대장 한 줄로 끝낸다.

```
문제:     무엇이 갈리거나 남는가
쓸 칸:    누가, 어디에, 몇 칸 (이름)
안 쓸 칸: 손대지 않는 열·원장·화면
흐름:     태어남 → 보임 → 제출 → 확인
검증:     무엇이면 된 것인가
결정:     대표가 정해야 하는 것만
```

---

## 쓸 칸을 정하는 규칙 (이미 있는 것을 제안 전체에 확장)

| | 한다 | 안 한다 |
|---|---|---|
| 직원 제출 | 그 결과의 `받을것`만 | 약속 없는 「통화 안 됨」에 약속일 |
| 카드 표시 | 그 종류의 `보임`만 | 전 계약자·전체 채권·다른 직원 원문 |
| 시트 | 계약에 적힌 열만 | 헤더 전체를 한 줄로 맞춤 |
| 원자 | 사실(청구·결제·사건) | 남의 잔액·추정 kWh·추측 트림 |
| AI 오더 | 행동·근거 한 줄·제출 형식 | 시트 탭을 직원에게 다시 열게 하기 |

갈리면 칸을 늘리지 말고 **한 줄로 같이** 낸다. (판정 11번과 같음: 내 셈 / 직원 기록 / 왜 갈렸나)

---

## 이 제안이 손대지 않는 것

CONTROL_PLANE 본문, 시트 라이브, 워크 배포.
Claude가 채택하면 `제안함.md` 「쓰는 법」에 위 여섯 칸을 넣고, 이후 제안은 이 꼴을 따른다.
