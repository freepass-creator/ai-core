# SOP · 문자·알림톡 발송 (알리고)

주인: 코덱스 · 만든 날 2026-08-20 · 고친 날 2026-08-21 (운영 상태 반영)

> **쓰임은 둘이다**(사장님 2026-08-20 「이건 우리 내부 공지만 쓰고 손님용으로 발송할 수 있게끔」).
> ① **내부 공지** — 기존 알리고 연동과 현재 등록된 개인 발신번호를 내부 알림에만 쓴다.
> ② **고객·파트너 발송** — 회사 업무폰(또는 회사 대표번호)을 발신번호로 등록하기 전에는 발송하지 않는다. 등록 뒤에도 알림톡은 사전 승인 템플릿이 필요하고, 광고성 문자는 수신동의·야간발송 규제를 받는다.
> 알리고 계정·연동은 이미 있다. 이 문서는 새 가입이나 키 재발급 절차가 아니라, **회사 발신번호 전환 전후의 운영 경계**를 정한다.

## 1. 언제
- 자동동기가 멈췄을 때(내부)
- 회사 업무폰 번호 등록과 승인 후, 견적·계약·정산 등 거래 이행 안내를 보낼 때

## 2. 회사 발신번호 전환 전 확인

알리고는 **사업자 인증**과 **발신번호 사전등록**을 해야 한다(전기통신사업법 — 안 하면 발송이 막힌다).

| 준비물 | 어디서 |
|---|---|
| 사업자등록증 사본 | 회사 문서고 |
| **발신번호로 쓸 번호** | 업무폰 번호 또는 대표번호 |
| **통신서비스 이용증명원** | 그 번호의 통신사에서 발급(휴대폰이면 통신사 앱·고객센터). 번호 명의가 **회사(또는 대표)** 여야 한다 |
| 알리고 관리자 권한자 | 기존 계정에서 번호 등록·승인 상태 확인 |

★ **명의가 다르면 등록이 반려된다.** 업무폰이 개인 명의면 그 사람 명의 증명원을 내거나, 회사 명의로 개통된 번호를 쓴다.

## 3. 순서

### ① 기존 알리고 계정에 회사 업무폰 번호 등록
1. 회사 명의 업무폰 번호를 개통한다. 개인 번호를 고객·파트너 발신번호로 재사용하지 않는다.
2. 알리고 관리자에서 **문자 → 발신번호 관리**로 들어가 번호와 통신서비스 이용증명원을 등록하고 승인 상태를 확인한다.
3. 충전 잔액과 내부 알림이 기존 번호에만 묶여 있지 않은지 확인한다.
4. 알림톡을 쓸 경우 기존 카카오 비즈니스 채널·발신프로필·승인 템플릿이 회사 번호/용도에 맞는지 확인한다.

번호 등록, 발신번호 환경값 변경, 실제 고객·파트너 발송은 모두 외부 영향이 있는 D등급 작업이다. 대상 번호·발신번호·수신자 범위·템플릿을 확인한 뒤 대표의 직전 승인을 받아 Codex가 실행한다.

### ② 연동값을 바꿔야 할 때
```powershell
[Environment]::SetEnvironmentVariable('ALIGO_API_KEY','발급받은키','User')
[Environment]::SetEnvironmentVariable('ALIGO_USER_ID','알리고아이디','User')
[Environment]::SetEnvironmentVariable('ALIGO_SENDER_TEL','01012345678','User')   # - 없이
[Environment]::SetEnvironmentVariable('ALIGO_SENDER_KEY','알림톡_발신프로필키','User')  # 알림톡 쓸 때만
[Environment]::SetEnvironmentVariable('ALIGO_FAILOVER','sms','User')            # 알림톡 실패 시 문자로
```
★ 기존 키를 이 문서·코드·시트에 복사하지 않는다. 연동값이 이미 배포 환경에 있으면 그 보관 위치를 유지하고, 새 값이 필요할 때만 승인된 담당자가 환경변수에 넣는다. 새 창을 열어야 값이 잡힌다.
시험할 때는 `ALIGO_DRY_RUN=true` — 실제로 안 보내고 콘솔에만 찍는다.

### ③ 보내기 — API 두 가지
같은 키로 두 길이 있다. **내부 공지는 SMS 하나면 된다.**

**일반 SMS** (템플릿 심사 없음 · 90자 넘으면 자동으로 LMS)
```
POST https://apis.aligo.in/send/     (application/x-www-form-urlencoded)
  key=<API_KEY>  user_id=<USER_ID>  sender=<발신번호>  receiver=<받는번호>
  msg=<본문>  [title=<제목·LMS만>]  [msg_type=LMS]
성공 판정: result_code === '1'
```

**카카오 알림톡** (사전 승인 템플릿 필요 · 실패 시 SMS 대체)
```
POST https://kakaoapi.aligo.in/akv10/alimtalk/send/
  apikey=<API_KEY>  userid=<USER_ID>  senderkey=<발신프로필키>  tpl_code=<템플릿코드>
  sender=<발신번호>  receiver_1=<받는번호>  subject_1=<제목>  message_1=<본문>
  [failover=Y  fsubject_1=<제목>  fmessage_1=<본문>]
성공 판정: code === 0
```

우리 코드로 부를 때(빌린카 앱):
```
POST /api/sms/send
  { "tel": "01012345678", "message": "본문" }                          ← 일반 SMS
  { "template_code": "TPL_1234", "receiver_tel": "010...",             ← 알림톡
    "variables": { "_subject": "제목", "_message": "본문" } }
```
키가 없으면 **mock 응답**을 주고 흐름을 막지 않는다(개발 중 안전장치).

## 4. 끝나고 확인
- 알리고 관리자 → **전송결과**에서 성공/실패와 잔액을 본다
- 실패코드가 나오면 대개 셋 중 하나다: **발신번호 미승인** · **잔액 부족** · **수신거부(080) 번호**
- 내부 공지는 받는 사람이 실제로 받았는지 한 번 물어본다(스팸함으로 가는 통신사가 있다)

## 5. 멈출 때 — 하면 안 되는 것
- **광고·홍보 문자는 규제 대상이다.** 수신동의 없이 보내지 않는다. 보낼 때는 맨 앞에 `(광고)`, 맨 뒤에 무료 수신거부 번호를 넣고, **21시~익일 08시에는 보내지 않는다**(정보통신망법). 견적·계약 진행 안내 같은 «거래 이행» 문자는 광고가 아니다.
- **손님 번호를 시트·문서에 그대로 쌓지 않는다.** 개인정보다 — 발송에 쓴 뒤 목적이 끝나면 지운다.
- **발신번호를 바꿔 넣지 않는다.** 등록되지 않은 번호로 보내면 발신번호 변작이 되어 계정이 정지된다.
- 키가 새면 **누구나 우리 이름으로 문자를 보낼 수 있다.** 유출이 의심되면 알리고에서 즉시 재발급.
- 템플릿 없이 알림톡을 부르면 실패한다 — 그때는 `failover=Y` 로 문자로 나간다(요금이 문자 기준).

## 6. 현재 운영 상태 (2026-08-21)
- 알리고 계정과 연동: **사용 중**. 이 SOP에서 키의 실제 위치나 값을 기록하지 않는다.
- 현재 발신번호: 대표 개인번호. **내부 공지 전용**이며 고객·파트너 발송에 쓰지 않는다.
- 다음 변경: 회사 업무폰 번호를 개통·등록한 뒤, 승인된 발신번호로 전환한다. 번호 전환 자체와 외부 발송은 별도 D등급 실행으로 등록한다.
