# SOP 한 장 형식 — 이대로만 쓰면 된다

> **여기는 «절차»만 둔다.** 표·지도·용어집 같은 «참조 자료»는 `docs/` 로 (예: [SHEET_MAP.md](../SHEET_MAP.md)).
> 절차가 아닌 문서를 넣으면 `sop-lint` 가 규격 미달로 잡는다.


파일 이름은 업무 이름 그대로. 위치는 영역 폴더(재무·차량·채권·영업·시트·AI운영).

```markdown
# SOP · <업무 이름>

주인: <코덱스/Claude> · 만든 날 · 마지막 고친 날

## 1. 언제
(매일 아침 / 파일이 오면 / 매월 5일 / 사장님이 시킬 때)

## 2. 시작 전 확인
- 선행 조건 — 이게 없으면 시작하지 않는다
- ★덮어쓰기 위험 — 무엇을 덮으면 안 되나

## 3. 순서
```bash
# ★실제 돌리는 명령을 그대로 적는다. 읽기든 쓰기든 같다.
# 쓰기는 lib/쓴다.mjs 나 scripts/with-lease.mjs --resource … 로 감싼다 (잠금이 필요해서다)
```

## 4. 끝나고 확인
- 숫자가 맞는지 어떻게 아나 (대조 대상) — ★「낸 수 = 든 수」

## 5. 멈출 때
- 이런 값이 나오면 멈추고 → INBOX · 예외함
```

**규칙**
- 순서에는 **실제 실행되는 명령**을 적는다.
- ★**2026-08-30 부터 쓰기 승인 절차가 없다** (대표: 「쓰기 이런 거 이제 다 권한 풀어」).
  옛 양식이 시키던 「작업대장 + DESIGN/FINAL + 대표 직전 승인 + with-lease」는 **더 이상 쓰지 않는다.**
  남은 것은 «잠금» 하나이고 그건 권한이 아니라 차례다 — `쓴다()` 가 알아서 잡는다.
  대표에게 올리는 것은 [`자율운영`](../자율운영.md) 의 다섯뿐이다(돈·바깥·사람·삭제·법).
- 끝나면 [`보고규격`](../보고규격.md) 다섯 칸으로 올린다.
- 「왜」는 한 줄이면 된다. 사고가 났던 것은 날짜와 함께 남긴다.
- 고치면 `docs/LOG.md` 에 한 줄.
