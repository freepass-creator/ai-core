## KH-003 동일 버전을 넘기는 인수인계 카드

출처: U1, L1, L3.
상태: 과거 기록을 바탕으로 정리한 권장 절차(이번 실행 재현 없음).
현재 열람: 2026-09-08의 KB 스냅샷 전체 읽기. 이전 세션 원문 재검수는 아님.
마지막 실행 검증: 미실시. 원문 재열람은 당시 실행 결과의 재현 검증을 뜻하지 않는다.

### 언제 쓰는가

다른 AI나 다음 세션이 이어서 구현·검토할 때.

### 핵심 원칙

한 카드가 하나의 결과를 책임진다. “검토 요청됨”과 “검토 응답 수신”은 별도 상태다.

### 실제 절차

다음 항목을 채워 전달한다.

```yaml
task: 설명 가능한 작업명
objective: 원하는 결과
source: 저장소/문서 경로 또는 파일 ID
revision: commit 또는 수정 시각과 내용 해시
scope: 허용 파일·탭·범위
preserve: 기존 규칙과 보존 대상
done: 완료한 결과와 증거
pending: 남은 작업·실패한 검증
permissions: 허용 행위와 별도 승인 대상
next: 바로 수행할 한 단계
```

받는 쪽은 실제 revision을 대조하고 다르면 먼저 차이를 보고한다. 개인정보가 있는 카드에는 공용 템플릿 대신 접근 제한된 별도 기록을 쓴다.

### 잘못된 예

서로 다른 커밋을 보고 작성한 검토 결과를 합쳐 “네 AI 합의”라고 쓴다.

### 체크리스트

- [ ] 버전·범위·다음 행동이 있는가
- [ ] 승인 대상과 검토 대상이 같은가
- [ ] 증거 파일이 실제 열리는가

## KH-004 지식 항목의 상태와 변경 이력

출처: U1, L1.
상태: 과거 기록을 바탕으로 정리한 권장 절차(이번 실행 재현 없음).
현재 열람: 2026-09-08의 KB 스냅샷 전체 읽기. 이전 세션 원문 재검수는 아님.
마지막 실행 검증: 미실시. 원문 재열람은 당시 실행 결과의 재현 검증을 뜻하지 않는다.

### 언제 쓰는가

새 팁을 추가하거나 과거 성공 사례를 재사용할 때.

### 핵심 원칙

관찰 날짜·환경·출처·실행 여부를 함께 남긴다. 명령이 문서에 있다는 이유로 지금 작동한다고 표시하지 않는다.

### 실제 절차

1. 항목 ID와 다섯 필수 절을 쓴다.
2. 상태와 적용 범위는 [공통 규격](규격.md)에 따라 표시한다.
3. 오류는 해당 주제 본문에서 고치고 변경 이유는 Git 이력과 검수 보고에 남긴다.
4. 원본은 보존하고 수정 이유·검증 결과를 추가한다.
5. 중복은 대표 문서로 연결하고 같은 규칙을 여러 곳에서 다르게 유지하지 않는다.

### 잘못된 예

한 번 성공한 모델·플랜·하드웨어 수치를 날짜 없이 영구 규칙으로 만든다.

### 체크리스트

- [ ] 출처와 상태가 있는가
- [ ] 과거 성공을 현재 성공으로 바꾸지 않았는가
- [ ] 중복·상충 규칙의 위치가 명확한가
