## KH-026 잘못된 성공 판정을 막는 사례집

출처: L1, M1, T2, T5.
상태: 과거 기록을 바탕으로 정리한 권장 절차(이번 실행 재현 없음).
현재 열람: 2026-09-08의 KB 스냅샷 전체 읽기. 이전 세션 원문 재검수는 아님.
마지막 실행 검증: 미실시. 원문 재열람은 당시 실행 결과의 재현 검증을 뜻하지 않는다.

### 언제 쓰는가

작업 계획·리뷰에서 반례가 필요할 때.

### 핵심 원칙

아래는 과거 기록에서 회수한 사례다. 사건 수치와 현재 복구 상태는 재검증하지 않았으며 교훈만 일반화했다.

### 실제 절차

| 사례 | 실패 원리 | 재발 방지 |
|---|---|---|
| 메일 경로를 못 찾아 새 위임 요청 | 기존 도구 미탐색 | 지정 범위 내 기존 도구·연결부터 조사 |
| 열 삽입 후 엉뚱한 칸 쓰기 | 위치 인덱스 의존 | 헤더/탭/범위 고정 |
| 탭 재생성으로 입력 소실 | 전체 교체 | 셀 patch·백업·재조회 |
| API 실패가 0건으로 보임 | 오류와 빈값 병합 | 실패 상태·부분 범위 명시 |
| 내용 해시로 귀속까지 확정 | 검증 축 혼합 | 원천/의미/귀속/보류 분리 |
| 같은 거래 사본 이중 집계 | ID만 중복 기준으로 사용 | 전체 내용·계정·기간 대조 |
| 빈 이름 사전이 정제값 삭제 | 상위 의존성 변경 미전파 | 빈 사전 중단·삭제량 임계 검사 |
| 로컬 UI 통과 뒤 원격 오류 | 환경 검증 누락 | 실제 배포와 실제 사용자 흐름 확인 |
| preview가 production alias 연결 | 요청과 서버 상태 혼동 | 업로드 전 보호·서버 target 확인 |
| 이미지가 임시 폴더에만 존재 | 생성과 이관 혼동 | 프로젝트 저장·참조 재확인 |
| 명령 줄바꿈 잘림 | 셸 다중 해석 | 파일/stdin과 셸 분리 |
| GPU 테스트만으로 생성 완료 | 중간 성공 확대 | 실제 생성물 확인 |

### 잘못된 예

“이번에는 주의한다” 한 줄로 끝내고 회귀 조건을 남기지 않는다.

### 체크리스트

- [ ] 증상·원인·예방·검증이 연결되는가
- [ ] 실제 확인된 원인과 가설이 구분되는가
- [ ] 새 실패가 재현 가능한 검사로 남는가
