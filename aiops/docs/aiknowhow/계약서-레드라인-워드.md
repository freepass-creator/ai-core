## 언제 쓰는가

계약 초안의 변경 이유를 표시하거나 상대방 회신본을 조·항 단위로 대조할 때 사용합니다.

## 핵심 원칙

시각적 레드라인과 Word의 실제 변경 추적은 다릅니다. 빨간 취소선·파란 밑줄만 넣은 문서는 수락/거절할 수 있는 변경 추적 문서가 아닙니다. 색과 취소선이 없다고 확정본으로 단정하지 않습니다.

상대 문서가 정본인 업무에서는 원본을 고정하고 편집 소스를 별도로 둡니다. HTML을 생성 소스로 선택했더라도 서명된 계약이나 상대 원본의 정본 지위를 대체하지 않습니다. 계약 해석·확정·발송은 원문 대조와 해당 승인 절차를 따릅니다.

## 실제 절차

1. 원본 파일과 조·항·호를 포함한 평문 추출본을 별도 보존합니다. 파일 해시와 수정 시점을 남기고 재생성 출력과 같은 경로에 백업을 두지 않습니다.
2. 시각적 검토본은 `{-기존-}{+수정+}`·`{-삭제-}`·`{+추가+}` 같은 명시 마크업을 사용할 수 있습니다. 줄을 넘는 토큰을 파싱한다면 줄바꿈 처리와 중첩·닫힘 오류를 검사합니다.
3. DOCX의 서식은 문단 전체가 아니라 해당 run에 적용합니다. `python-docx`의 취소선·색상과 필요 시 OOXML 음영을 사용합니다. 실제 변경 추적을 요청받았다면 OOXML 삽입/삭제 요소와 Word 표시를 별도로 검증합니다.
4. 한글·숫자 간 자동 간격이 문제일 때 `autoSpaceDE`·`autoSpaceDN` 설정을 점검하되 모든 문서에 일괄 적용하지 않습니다. 템플릿·스타일·개별 문단의 우선순위를 확인하고 렌더합니다.
5. 조·항 번호로 비교 후보를 만들고 표·각주·텍스트박스·번호 없는 문단도 검사합니다. 공백·문장부호 정규화는 보조 비교에만 쓰며 부정어·금액·기한·인용은 원문 그대로 다시 대조합니다.
6. 치환 전 기대 매치 수를 확인합니다. 0건 또는 여러 건이면 자동 진행하지 않습니다. 반복 표식을 `.index()`로 찾아 큰 구간을 자르지 말고 편집할 구간을 먼저 확인합니다.
7. 조·항 번호 연속성과 내부 인용의 실제 대상을 검사합니다. HTML·DOCX·PDF를 각각 재생성한 뒤 텍스트와 모든 페이지를 확인합니다. PDF는 HTML 변경만으로 자동 갱신됐다고 가정하지 않습니다.
8. 파일 잠금으로 복사가 실패하면 실제 열린 파일과 잠금 원인을 확인합니다. 사용자 문서를 임의 종료하지 않습니다. 중요 문안은 독립 검토 후 확정/발송을 별도 처리합니다.

문안에서는 상대 초안을 평가하는 어투보다 변경 목적과 효과를 설명합니다. 완충어가 조건·의무를 바꾸는지 점검합니다. 공개 범위를 넓히는 협상 전략은 과거 사례일 뿐 자동 권장하지 않습니다.

9. 현재 문서 스킬·원본 템플릿을 확인하고 제목 계층·표·각주·날짜·참조 관계를 보존합니다. 출력의 한글 글꼴·줄바꿈·빈 페이지와 본문 누락을 모두 검사합니다. 다른 세션으로 전달하는 일반 파일/자산 점검은 아래 KH-011을 사용합니다.

## 잘못된 예

- 색상 개수 0을 보고 “확정 최종본”이라고 보고합니다.
- 마침표를 제거한 비교만으로 금액·조항 의미가 같다고 판단합니다.
- 첫 페이지 나눔부터 끝까지 잘라 부록을 지우다가 본문까지 삭제합니다.
- 생성 명령 성공만 확인하고 오래된 PDF를 첨부합니다.

## KH-011 원본 보존과 재사용 가능한 산출물

출처: U1, M1, L3.
상태: 과거 기록을 바탕으로 정리한 권장 절차(이번 실행 재현 없음).
현재 열람: 2026-09-08의 KB 스냅샷 전체 읽기. 이전 세션 원문 재검수는 아님.
마지막 실행 검증: 미실시. 원문 재열람은 당시 실행 결과의 재현 검증을 뜻하지 않는다.

### 언제 쓰는가

문서·이미지·코드 결과를 다른 세션에 전달할 때.

### 핵심 원칙

원본/중간본/최종본을 분리하고 사람이 열 수 있는 파일을 남긴다. 생성 성공과 프로젝트 이관 완료는 다르다.

### 실제 절차

1. 정본 파일의 위치·크기·수정 시각을 기록한다.
2. 중간 작업은 work, 완성본은 outputs 등 정해진 결과 폴더에 둔다.
3. 상대 참조 파일과 이미지도 함께 보존한다.
4. 파일 존재·크기·열기·링크를 확인한다.
5. 버전과 변경 요약을 남긴다. 원본 재생성은 원본을 못 찾았다는 근거부터 확인한다.

### 잘못된 예

이미지가 임시 생성 폴더에만 있는데 “프로젝트에 저장했다”고 말하거나 원래 모바일 시안을 찾지 않고 새로 만든다.

### 체크리스트

- [ ] 원본을 덮지 않았는가
- [ ] 다른 세션에서도 파일을 찾을 수 있는가
- [ ] 첨부 자산·링크가 포함됐는가
