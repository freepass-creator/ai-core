## KH-022 계정·권한·승인 범위 분리

출처: U1, L1.
상태: 과거 기록을 바탕으로 정리한 권장 절차(이번 실행 재현 없음).
현재 열람: 2026-09-08의 KB 스냅샷 전체 읽기. 이전 세션 원문 재검수는 아님.
마지막 실행 검증: 미실시. 원문 재열람은 당시 실행 결과의 재현 검증을 뜻하지 않는다.

### 언제 쓰는가

Drive·메일·데이터베이스·공개 저장소에 접근할 때.

### 핵심 원칙

로그인한 AI 계정과 Workspace 데이터 계정은 다를 수 있다. 읽기 권한은 쓰기·공유 권한을 의미하지 않는다.

### 실제 절차

1. 정본 데이터 계정은 보호된 연결 설정에서 확인한다. 공용 문서에는 실제 이메일/토큰을 넣지 않는다.
2. 필요한 파일·탭·범위만 읽는다.
3. 민감 원문 대신 최소 비식별 정보로 보조 검토한다.
4. 외부 쓰기·발송·삭제·권한·운영 배포는 구체적인 실행 대상을 보여주고 직전 승인을 받는다.
5. 대상·revision·범위가 바뀌면 이전 승인을 재사용하지 않는다.
6. 실행 후 결과를 재조회하고 승인 기록에는 비밀값을 넣지 않는다.

### 잘못된 예

연결된 Gmail이 있다고 정본 계정이라고 추정하거나, 과거 “모두 해도 된다”를 영구 발송 승인으로 쓴다.

### 체크리스트

- [ ] 계정과 파일 ID가 맞는가
- [ ] 비밀값이 로그·Git·프롬프트에 없는가
- [ ] 실행 범위와 승인 범위가 같은가

## KH-023 공용 KB와 민감 증거 분리

출처: U1, L1.
상태: 과거 기록을 바탕으로 정리한 권장 절차(이번 실행 재현 없음).
현재 열람: 2026-09-08의 KB 스냅샷 전체 읽기. 이전 세션 원문 재검수는 아님.
마지막 실행 검증: 미실시. 원문 재열람은 당시 실행 결과의 재현 검증을 뜻하지 않는다.

### 언제 쓰는가

실패 사례를 공용 문서나 GitHub에 정리할 때.

### 핵심 원칙

공용은 재사용 가능하다는 뜻이지 공개 인터넷 게시 허가가 아니다. 개인 식별자는 예제에서도 제거한다.

### 실제 절차

1. 사람 이름·전화·이메일·계좌·차량번호·비밀값을 제거한다.
2. 날짜·금액·속성 조합으로 재식별되는지 확인한다.
3. 원문은 원래 보호된 위치에 두고 KB에는 교훈과 출처 위치만 남긴다.
4. 저장소 공개 여부와 첨부·이미지·메타데이터를 검사한다.
5. 외부 AI에는 문서 전체 대신 필요한 비식별 발췌만 준다.

### 잘못된 예

실제 고객 전사본이나 인증 파일을 “재현 예제”라며 공용 문서에 복사한다.

### 체크리스트

- [ ] 원문 대신 비식별 설명인가
- [ ] 조합 식별 가능성을 확인했는가
- [ ] 공개·공유 범위를 확인했는가

## 손오공 비밀번호 — 급하지 않다 (2026-09-17 대표 판정). 다만 사실은 기록해 둔다

> ★**2026-09-17 대표 판정: 「손오공 계정 그냥 써도 돼. 개인정보 없고 그냥 상품 보는 사이트야.」**
> **바꾸지 않는다. 이 항목을 급한 일로 다시 올리지 마라.**
>
> 클로드 검증: 코드가 이 계정으로 부르는 것은 **전부 읽기 전용 `/product/...` GET** 이다
> (`lib/sonokong.mjs` — `/product/homepage/view/:id` · `/product/view/:id` · 목록).
> 고객·계약·결제 엔드포인트가 **없다.** 대표 판정과 코드가 일치한다.
>
> ★**내가 이것을 「대표 결정 대기 A순위」로 올린 것이 과했다.** 「평문이 원격에 있다」는
> 사실만 보고 **그 계정이 무엇을 할 수 있는지를 안 쟀다.** 노출의 크기는
> 「비밀이 샜나」가 아니라 **「그 비밀로 무엇을 할 수 있나」**로 정해진다.
>
> 아래 측정은 **지우지 않고 남긴다** — 나중에 이 계정에 쓰기 권한이나 고객 자료가 붙으면
> 그때는 판정이 달라지고, 그 판단에 필요한 사실이 여기 있기 때문이다.

### (참고) 그때 잰 것 — 판정이 달라질 경우에만 쓴다

★**이 문서에 비밀번호를 적지 않는다.** 아래는 전부 값을 안 찍고 잰 결과다.

### 잰 것 넷

**① 평문이 원격에 «실제로» 갔다.**
`lib/sonokong.mjs` 의 주석 한 줄에 `계정 <id>/<pw>` 형태로 박혀 있었다.
그 줄을 넣은 커밋 `0795567`(2026-08-26)이 **`origin/main` 의 조상**이다 — 직접 확인했다.
지운 커밋 `85e0bbd`(2026-09-16)는 **아직 로컬에만** 있다(aiops push 가 100MB 벽에 막혀 있다).
즉 **지운 사실은 원격에 없고, 적힌 사실은 원격에 있다.**

**② 원격에 닿은 커밋이 45개다.** (로컬만인 것 25개와 따로 셌다.)

**③ 저장소는 PRIVATE 다.** 노출 범위는 「이 저장소에 접근 권한이 있는 사람」으로 갇힌다.
공개 인터넷에 떠 있는 상태는 **아니다.** 다만 그것이 「안전하다」는 뜻은 아니다.

**④ ★그리고 이것이 핵심이다 — 비밀번호가 「우리가 매일 쓰는 낱말」이다.**
8자, **영문 소문자만**, 숫자도 기호도 없다. 그리고 그 낱말은 이 저장소의 **경로 이름에 수백 번**
나온다(`…erp4` 앞에 붙는 그 낱말이다). 그래서 두 가지가 동시에 참이다:

- **추측이 쉽다.** 사전에 있고 우리 문서 도처에 있는 낱말이다.
- **★이력 수술이 «불가능»하다.** 문자열로 지우면 **저장소의 모든 경로가 같이 망가진다.**
  `git filter-repo` 로 이 문자열을 치환한다는 것은 `freepasserp4` 라는 이름 자체를 지우는 일이다.

★**「지운다」는 길이 없다.** 문자열 수술이 경로를 다 망가뜨리기 때문이다. 즉 **이 계정은 앞으로도
계속 「원격 이력에 평문이 있는 계정」이다.** 지금은 그래도 괜찮다는 것이 대표 판정이고, 그 근거는
이 계정이 상품 조회밖에 못 한다는 점이다. ★**그 전제가 바뀌면 이 문단부터 다시 읽는다.**

### 바꿀 때 실제로 해야 하는 일 — 딱 둘

현재 코드는 **소스에 비번을 두지 않는다.** `lib/sonokong.mjs` 가 gitignore 된 파일에서만 읽는다.
그래서 바꾸는 절차가 짧다.

```
1. 손오공 포털에서 비밀번호를 바꾼다                     ← ★대표만 할 수 있다
2. lib/wonja/.손오공계정.json 의 "password" 를 새 값으로  ← gitignore. 이 파일 하나뿐이다
3. lib/wonja/.손오공토큰.json 을 지운다                   ← 옛 토큰(8시간짜리)이 남아 있으면
                                                           만료 전까지 옛 세션을 계속 쓴다
```

`3` 뒤에는 다음 호출에서 `lib/sonokong.mjs` 의 `login()` 이 **자동 재로그인**한다.
★`.손오공토큰.json` 을 안 지우면 「바꿨는데 왜 그대로 되지」가 된다 — 토큰이 살아 있어서다.

### ★새 비밀번호에 거는 조건

**우리 문서·경로에 나오는 낱말을 쓰지 않는다.** 그게 이번 일의 원인이다.
숫자·기호를 섞는다. 그래야 다음에 또 평문이 새더라도 **경로와 구별되어** 지울 수라도 있다.

### 하지 않은 것 / 못 하는 것

- **AI 는 비밀번호를 바꾸지 않는다.** 외부 서비스에 자격증명을 넣는 일은 대표가 직접 한다
- 이력 수술을 **시도하지 않았다.** 위 ④ 때문에 시도 자체가 저장소를 망가뜨린다
- `⚠ 서로 다른 비번으로 반복 로그인 = brute force 로 오탐·차단`(`lib/sonokong.mjs:11`).
  바꾼 뒤 **저장된 계정만** 쓰게 두고, 손으로 여러 번 시도하지 않는다

### 겸사겸사 확인한 것 — 문서에 남은 매치는 «무고»하다

작업본을 훑으니 `AI_GUIDE.md` · `docs/SHEET_MAP.md` · `price-pipeline.md` 등에서 같은 문자열이
잡힌다. 전부 **`freepasserp4` 경로**다. 자격증명이 아니다. **「문자열이 있다」와 「비밀이 샌다」는
다른 주장이다** — 지우지 않았다.
