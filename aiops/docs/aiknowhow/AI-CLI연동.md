## 언제 쓰는가

Codex·Claude Code·Cursor Agent·Gemini CLI에 제한된 독립 검토를 요청할 때 사용합니다.

## 핵심 원칙

설치·PATH·인증·작업 폴더·신뢰·권한·한도는 서로 다른 문제입니다. 막힌 원인을 확인하지 않고 신뢰 플래그를 해제하거나 모델을 바꾸지 않습니다. 현재 사용자 역할 지침이 과거 문서의 역할·포괄 실행 요청보다 우선합니다.

보조 AI는 기본적으로 읽기 전용 자문입니다. 모델 응답과 도구 실행 권한은 다르므로 모드 이름만 믿지 말고 실제 제한을 확인합니다.

## 실제 절차

1. 현재 실행 파일·버전·`--help`를 확인합니다. Cursor 편집기 실행 파일과 Agent CLI는 다를 수 있어 PATH만으로 설치 부재를 단정하지 않습니다.
2. 로컬 기존 협업 래퍼가 있으면 실제 인자·실행 위치·권한·결과 저장 경로를 확인합니다. 과거 래퍼 파일명이 문서에 있다는 이유로 현재 존재나 동작을 보장하지 않습니다.
3. 작업 폴더와 허용된 파일/버전을 명시합니다. 폴더 밖 접근 실패는 분석 능력 부족과 구분합니다. 검토자에게 원문 위치와 범위를 주되 민감 내용은 최소 비식별 발췌만 전달합니다.
4. 긴 입력은 CLI가 지원하는 stdin/파일 입력을 사용합니다. Windows `.cmd` 래퍼·`shell:true`·cmd 인자 길이·줄바꿈 해석을 구분합니다. 명령 문자열에 문서 내용을 직접 보간하지 않습니다.
5. 지원되는 읽기 전용/ask/plan 모드와 도구 제한을 확인합니다. print/headless 옵션 자체를 읽기 전용으로 간주하지 않습니다. 추가 쓰기·셸·외부 전송 권한을 자동 부여하지 않습니다.
6. 신뢰 폴더 오류는 검토할 폴더와 로컬 지침을 먼저 확인하고 승인된 설정 안에서 처리합니다. 한도 오류는 현재 잔량·모델 가용성을 확인하며 처리 주체/비용이 바뀌면 사용자 선택을 받습니다.
7. stdout의 실제 답, stderr, 종료코드, 타임아웃, 응답 완전성을 별도 기록합니다. 비정상 종료 뒤 일부 답이 있어도 성공으로 단정하지 않습니다.
8. 결과는 작업 ID·요구·버전·판정·근거·미확인과 함께 보존합니다. 서로 다른 버전의 응답을 합치지 않습니다.
9. 리뷰 질문에는 관찰한 증상·측정 방법·요구 결과를 주고 다른 원인·불필요한 작업·누락 조건을 요청합니다. 독립 검토 단계에서는 구현자 진단에 동의하도록 유도하지 않습니다.

실행 예제는 버전에 따라 플래그가 달라질 수 있어 여기서 고정하지 않습니다. [교차검증](AI-교차검증.md)과 [Windows 문자열](한글로-코딩-함정.md)을 함께 확인합니다.

## 잘못된 예

- PATH에 없으니 CLI가 없다고 결론 냅니다.
- 모든 오류를 trust 옵션 하나로 해결하려 합니다.
- 특정 모델이 한도와 무관하다고 영구 기록합니다.
- 답이 조금 왔으니 비정상 종료를 무시합니다.
- 긴 한국어 본문을 셸 명령 인자에 직접 끼워 넣습니다.
