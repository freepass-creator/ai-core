## KH-018 목적별 템플릿

출처: U1, O2; 신규 재사용 템플릿.
상태: 과거 기록을 바탕으로 정리한 권장 절차(이번 실행 재현 없음).
현재 열람: 2026-09-08의 KB 스냅샷 전체 읽기. 이전 세션 원문 재검수는 아님.
마지막 실행 검증: 미실시. 원문 재열람은 당시 실행 결과의 재현 검증을 뜻하지 않는다.

### 언제 쓰는가

매번 긴 지시를 다시 작성하거나 결과 형식이 흔들릴 때.

### 핵심 원칙

목표·맥락·제약·완료 조건을 짧게 채운다. 빈칸은 추정하지 않게 한다.

### 실제 절차

아래에서 목적에 맞는 것을 복사하고 대괄호를 채운다.

**세션 시작**
```text
[저장소/정본]의 노하우 README와 적용 규칙을 먼저 읽어라.
목표: [결과]. 범위: [파일/탭]. 보존: [기존 동작].
현재 상태와 버전을 확인하고 [완료 조건]까지 수행하라.
검증하지 못한 항목은 완료로 표시하지 마라.
```

**세션 인계**
```text
현재 목표, 정본 버전, 실제 변경 파일, 검증 증거, 실패,
남은 일, 승인 범위, 다음 한 단계를 인계 카드로 남겨라.
```

**독립 검토**
```text
읽기 전용 검토다. 원래 요구사항 [요구]와 동일 버전 [버전]을 기준으로
누락·반례·권한·회귀를 찾아라. 구현자의 결론을 전제하지 마라.
판정/근거/중요 위험/미확인/필수 수정으로 답하라.
```

**표 검증**
```text
[파일/탭/범위]의 값과 수식·표시형식을 구분해 읽어라.
키 중복·빈값·기간·단위·합계를 원문과 대조하라.
읽기 실패는 0으로 바꾸지 말고 수정은 before/after 제안만 하라.
```

**이미지 편집**
```text
참조 [파일/버전]을 기준으로 얼굴·체형·머리·[고정 요소]를 유지하라.
이번 변경은 [변경 요소]만이다. 구도 [구도], 출력 [비율/용도].
결과를 참조와 비교하고 달라진 점을 밝혀라.
```

**배포 전 점검**
```text
[프로젝트/환경]을 읽기 전용으로 확인하라. target·alias·보호·
업로드 파일 목록·익명 자산 접근 검증안을 작성하라.
비공개 콘텐츠 업로드 전에 보호를 입증하고 최종 실행안을 제시하라.
```

**반복 작업**
```text
[대상]을 [주기/시간대]에 [읽기 범위]로 확인하라.
변화 없으면 조용히 유지하고 [의미 있는 변화/실패] 때만 알린다.
중복 실행 방지, 재시도 한도, 종료 조건 [조건]을 명시하라.
```

### 잘못된 예

“완벽하게 해”, “모든 걸 기억해”, “어떻게든 뚫어”만 넣고 대상·검증·권한을 생략한다.

### 체크리스트

- [ ] 대괄호를 채웠는가

- [ ] 결과와 검증 형식을 명시했는가
