## 언제 쓰는가

PDF나 이미지의 글자를 읽고 숫자·표·고유 식별자를 검증할 때 사용합니다.

## 핵심 원칙

텍스트 추출, 이미지 렌더, 문자 인식은 다른 단계입니다. 텍스트가 나오지 않는다고 무조건 스캔본은 아니며 글자가 추출됐다고 정확한 것도 아닙니다. 원본의 실제 모습과 중요한 값을 대조합니다.

Cloud OCR 사용은 현재 연결·기능·요금·외부 전달 범위를 확인합니다. 과거 API 비활성화·설치 여부·무료 구간을 현재 규칙으로 쓰지 않습니다.

## 실제 절차

1. 지정 파일/페이지를 고정하고 암호·텍스트 레이어·문자 추출 결과를 확인합니다. 텍스트 PDF는 먼저 PyMuPDF 등 현재 지원 도구로 읽습니다.
2. 글자 없음/깨짐은 스캔·폰트 매핑·인코딩·권한·도구 실패 등 후보로 분류합니다. `ToUnicode` 문제는 실제 PDF 구조를 확인한 뒤 원인으로 확정합니다.
3. 페이지를 이미지로 렌더하여 본문·표·차트·누락을 확인합니다. 작은 글자는 해상도와 크롭을 높여 다시 봅니다. 특정 DPI가 모든 문서에 충분하다고 보장하지 않습니다.
4. 반복적 문자 추출이 필요하면 로컬 또는 승인된 OCR 경로를 선택합니다. 렌더는 OCR의 대안이라기보다 원본을 표시하는 단계일 수 있습니다.
5. 현재 OCR 서비스 권한·프로젝트·요금·언어 지원을 확인하고 필요 없는 서비스 활성화를 요청하지 않습니다. 민감 원문 외부 업로드는 별도 범위 확인과 승인을 따릅니다.
6. 결과에 페이지·위치·원본 파일을 연결합니다. 금액·날짜·사업자/계좌/차량 식별자는 원본과 재대조하며 모호한 문자는 미확인으로 남깁니다.
7. 사진의 차량번호 등은 후보이며 프로젝트가 지정한 시트/원문 정본과 비교합니다. OCR만으로 정본 값을 바로 수정하지 않습니다.
8. 전사와 마찬가지로 추출 성공/원문 확인/정본 반영을 별도 상태로 보고합니다.

9. 음성 추출은 [로컬 전사](전사-통화녹음.md)의 원음·시간대·화자 확인을 따릅니다. 상담원 예시와 고객 확정 조건은 구분하며, 원음 대조 없이 상담원의 기간 제안을 고객 희망값으로 저장하지 않습니다.

## 잘못된 예

- 글자가 없으니 Cloud API를 켜야 한다고 결론 냅니다.
- 숫자가 추출됐으니 표의 행·열 관계도 맞다고 가정합니다.
- 110dpi면 모든 작은 글자가 충분히 읽힌다고 보장합니다.
- 사진에서 읽은 식별자를 원문 대조 없이 저장합니다.
