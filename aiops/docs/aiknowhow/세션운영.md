## KH-001 목표·범위·완료 조건을 먼저 고정

출처: U1, T1, O1, O2.
상태: 과거 기록을 바탕으로 정리한 권장 절차(이번 실행 재현 없음).
현재 열람: 2026-09-08의 KB 스냅샷 전체 읽기. 이전 세션 원문 재검수는 아님.
마지막 실행 검증: 미실시. 원문 재열람은 당시 실행 결과의 재현 검증을 뜻하지 않는다.

### 언제 쓰는가

긴 작업을 시작하거나 대화가 여러 주제로 흐를 때.

### 핵심 원칙

목표와 예시는 구분한다. 사용자가 설명한 예시를 곧바로 데이터 규격으로 만들지 않는다. 프로젝트 공유 맥락도 필요한 파일을 실제 읽었는지 확인해야 한다.

### 실제 절차

1. 원하는 결과물, 대상 저장소/문서, 바꿀 범위, 보존할 것을 적는다.
2. 성공 조건을 결과물과 증거로 정의한다.
3. 원문을 읽고 모호한 핵심만 질문한다.
4. 중간에는 발견·불확실성·다음 검증을 짧게 알린다.
5. 최종에는 결과 경로와 미완료를 함께 남긴다.

### 잘못된 예

“다 알아서 해”만 남긴 뒤, AI가 만든 중간 보고를 실행 완료로 간주한다.

### 체크리스트

- [ ] 정본을 실제로 읽었는가
- [ ] 예시와 요구사항을 구분했는가
- [ ] 범위 밖 변경이 없는가
- [ ] 완료 기준마다 증거가 있는가

## KH-002 끊겨도 작업을 이어갈 수 있게 만들기

출처: U1, L1, O1.
상태: 과거 기록을 바탕으로 정리한 권장 절차(이번 실행 재현 없음).
현재 열람: 2026-09-08의 KB 스냅샷 전체 읽기. 이전 세션 원문 재검수는 아님.
마지막 실행 검증: 미실시. 원문 재열람은 당시 실행 결과의 재현 검증을 뜻하지 않는다.

### 언제 쓰는가

대화가 길어지거나 다른 세션·기기로 이동할 때.

### 핵심 원칙

대화 제목과 마지막 요약만으로 상태를 복원하지 않는다. 결정과 실제 저장 상태를 분리한다.

### 실제 절차

1. [인수인계 규격](인수인계.md)에 현재 목표·정본 버전·완료·보류를 기록한다.
2. 작업 파일을 영구 경로에 저장하고 존재를 재확인한다.
3. 다음 세션은 기록과 실제 파일/브랜치를 대조한다.
4. 사용자의 수정 지시를 이전 목표에 반영하되 취소되지 않은 작업을 잊지 않는다.

### 잘못된 예

“지난번에 다 했음”이라는 대화만 믿고 실제 산출물 없이 다음 단계로 넘어간다.

### 체크리스트

- [ ] 재개 시작점이 한 줄로 있는가
- [ ] 첨부 파일/임시 URL이 여전히 유효한가
- [ ] 남은 작업과 금지 작업이 구분되는가

## COL-001 사용자와 맥락을 이어 가는 협업

상태: 권장 절차 · 편집 단계: 검수안 · 출처: 2026-09-08 노하우·이미지 작업의 실제 피드백에서 도출 · 실제 업무 개선 효과: 미검증.

### 언제 쓰는가

이전 결정을 다시 설명하게 되거나, AI가 말만 따라 하고 목적을 놓치거나, 여러 작업자가 서로 다른 방향으로 진행할 때.

### 핵심 원칙

더 나은 협업은 많은 AI·긴 문서가 아니라 필요한 맥락을 읽고, 판단과 실행을 연결하며, 결과를 검증하는 데서 나온다. 사용자에게 생각의 모든 과정을 보여주거나 매번 같은 질문을 하지 않는다. 결과와 판단 근거·남은 불확실성만 필요한 만큼 설명한다. 이 절차는 모델 능력·영구 기억·권한을 변경하지 않는다.

### 실제 절차

1. **재개부터 한다.** 현재 사용자 요청, 해당 작업의 마지막 결정·채택 버전·미해결 사항, 실제 파일을 대조한다. 작업과 관계없는 과거 대화나 다른 프로젝트를 광역 수집하지 않는다. [인수인계](인수인계.md)의 기존 기록을 이용한다.
2. **의도를 짧게 잡는다.** `원하는 결과 / 반드시 유지 / 이번 변경 / 완료 증거`를 내부 작업 기록의 기존 항목에 채운다. 이미 알려진 답을 다시 묻지 않는다. 모호함이 작고 되돌릴 수 있는 선택은 합리적인 가정을 밝히고 진행한다. 가정이 보이는 결과에 영향을 주면 한 줄로 알리되, 채택 기준본·권한을 추정으로 대체하지 않는다. 서로 다른 결과·비용·접근 범위가 생기는 선택이나 필수 정보 부족만 한 번에 짧게 확인한다. 짧은 “계속”은 직전의 명확한 작업 범위에만 적용한다.
3. **추천에 이유를 붙인다.** 지금 작업에 직접 도움이 되는 추천 하나와 필요할 때만 대안 1~2개를 제시한다. 결과·시간·비용·자료 처리 범위 차이를 설명한다. 사용자가 선택한 방식을 유지하고 거절한 대안을 말만 바꿔 재권유하지 않는다. 사소한 일에는 선택 메뉴를 만들지 않는다.
4. **증거가 있는 최소 작업을 한다.** 한 번에 검토할 수 있는 결과를 만들고 실제 원본·화면·파일로 확인한다. 범위가 명확한 요청은 계획만 제시하고 멈추지 않는다. 사용자 요청이나 실질적인 선택이 없는 한 도구 설치·플랫폼 구축·배포로 넓히지 않는다.
5. **필요한 반례만 독립 검토한다.** [AI 교차검증](AI-교차검증.md)의 현재 위험별 역할과 비식별·승인 절차를 따른다. 네 제품을 매번 의무 호출하지 않는다. 외부 AI에 전달하는 대상·목적·자료 범위가 현재 사용자의 승인에 포함되는지 확인한다. 승인 범위가 같으면 불필요하게 다시 묻지 않되 다른 수신자·민감 원문·목적으로 확대하지 않는다. 비식별 최소정보로 검토를 요청하고 구현자 설명과 독립된 반례를 받는다. 다른 AI의 자신감·다수결 대신 원본과 재현 결과로 결정한다. 도구에 검토를 보냈다는 사실과 실제 응답 수신을 구분한다.
6. **실패를 다음 행동으로 바꾼다.** 근거 부족이면 필요한 출처, 품질 불만이면 달라진 요소, 기술 오류면 실행 증거, 권한·안전 문제면 가능한 범위를 구분한다. 똑같은 불만이 반복되면 생성량을 늘리기 전에 원요청과 결과의 차이를 짚는다. 수정은 현재 승인된 범위에서 수행하고, 다른 디자인·범위의 대안은 변경점을 밝힌다.
7. **피드백을 좁게 축적한다.** 확정 결정과 AI 해석을 분리하고 해당 작업의 기존 제작/검토 기록에 남긴다. 다음 작업에 영향을 주는 교훈만 다시 읽는다. 종료된 미정 사항을 영구 할 일로 만들거나 한 번의 취향을 모든 프로젝트의 규칙으로 바꾸지 않는다. 일반 교훈은 기존 대표 카드의 수정안으로 만들고 승인된 범위에서 통합한다.
8. **짧게 인계한다.** 여러 세션·작업자 사이에 이어야 하거나 중요한 결정·미해결 사항이 생긴 때 결과·검증·미완료·다음 시작점을 남긴다. 단순 답변·오타 수정마다 별도 문서나 인계문을 만들지 않는다. 새 작업자는 기록을 읽었음을 내용으로 보여준다. 예: “기준 v3의 얼굴·복장은 유지하고 구두 잘림만 수정한다.” 읽었다는 체크 표시만 남기거나 실제 파일을 보지 않고 이어받지 않는다.

중단 조건은 필수 정보·권한·원본 불일치·필수 검증 실패이며 해당 단계만 보류한다. 보류 이유와 재개에 필요한 것을 사용자에게 알리고 독립적으로 가능한 작업은 계속한다. 공통 카드 수정도 해당 변경을 포함하는 사용자 승인 범위에서 수행하며, 현재 사용자 지시의 승인 규칙을 유지하고 과거 승인을 다른 실행으로 확대하지 않는다. 되돌릴 때는 이번 변경만 대상으로 하며 다른 작업자의 변경을 보존한다.

### 잘못된 예

- 사용자가 소재를 고쳐 달랬는데 새 의상을 만든 뒤 완료라고 한다.
- 이미 지정된 기준본 대신 최신 수정 파일을 고르고 사용자에게 처음부터 취향을 다시 묻는다.
- 매 작업마다 네 AI를 호출하고, 모두 같은 답이면 실제 결과 확인을 생략한다.
- 문서를 추가했으니 모든 AI가 자동으로 영구 학습했다고 말한다.

### 체크리스트

- [ ] 마지막 결정과 실제 정본을 대조해 중복 질문을 줄였는가
- [ ] 결과·유지·변경·완료 증거가 서로 맞는가
- [ ] 추천이 현재 목적에 직접 도움이 되고 선택 범위를 넘지 않는가
- [ ] 결과가 나왔다는 것과 요구를 충족했다는 것을 구분했는가
- [ ] 다음 작업자가 관련 피드백과 시작점을 찾을 수 있는가

평가는 대화량이나 문서 수 대신 해당 작업에서 발생한 불필요한 재질문·의도와 다른 수정·같은 오류의 재발·인계 시 누락으로 한다. 수치는 실제 기록이 있을 때만 계산하며 개선율을 추정하지 않는다.
