## 언제 쓰는가

웹 표·모달·인쇄 문서의 잘림·줄 높이·정렬을 실제 화면에서 검사할 때 사용합니다.

## 핵심 원칙

눈으로 보는 검사와 DOM 치수 검사는 함께 사용합니다. viewport가 0이거나 스타일/폰트가 준비되지 않은 측정은 통과 근거가 아닙니다. 특정 미리보기 도구의 숨김 동작을 모든 브라우저의 법칙으로 일반화하지 않습니다.

현재 제공된 브라우저 도구를 우선 사용합니다. 과거 `--no-sandbox`·모든 origin 허용 실행 예제는 보안 범위를 넓히므로 기본 절차에서 제외합니다.

## 실제 절차

1. 실제 URL·계정·viewport·배율·폰트 준비를 확인합니다. 숨겨진 창에서 폭이 0이면 측정 실패로 보고하고 유효한 화면/허용된 headless 환경에서 다시 봅니다.
2. 독립 브라우저 실행이 허용된 경우 임시 프로필과 loopback 연결을 사용하고 사용자 프로필과 충돌하지 않게 합니다. CDP와 screenshot은 현재 도구 규칙 안에서만 사용합니다.
3. HTML/PDF의 고정 높이와 `overflow:hidden`을 검사합니다. 페이지 수가 정상이어도 내용이 잘릴 수 있어 `scrollHeight`와 `clientHeight` 차이, 실제 렌더의 마지막 줄을 함께 봅니다.
4. 스타일시트 개수만으로 준비 완료를 판단하지 않습니다. 기대 CSS의 실제 computed style, 웹폰트 로딩, 이미지·동적 내용 준비를 확인합니다. 준비 실패는 검사 불가입니다.
5. 표 행은 큰 셀의 내용·padding·border·체크박스 기본 margin 때문에 늘어날 수 있습니다. 문제 요소의 실제 box를 측정합니다. collapsed border의 소수 픽셀 자체를 오류로 단정하지 않습니다.
6. 열폭·table width·min-width·overflow 관계를 봅니다. `table-layout:fixed`가 언제나 모든 열을 비례 축소한다는 가정 대신 실제 사용 폭을 측정합니다. 긴 한글·세 자리 이상 번호·빈 값으로 검사합니다.
7. 정렬 비교에서 `start/end`는 `direction`과 writing mode에 따라 해석합니다. LTR에서만 `start`와 `left`가 일치할 수 있으므로 무조건 문자열 치환하지 않습니다.
8. 잘림은 `scrollWidth > clientWidth`, 페이지 넘침은 높이 차이 등을 후보로 삼되 허용 스크롤·의도된 말줄임을 구분합니다. 임계 픽셀은 화면/배율별 근사치입니다.
9. `line-height:normal`은 글꼴 의존 값을 뜻하며 언제나 결함은 아닙니다. 레이아웃 계약에 맞춰 필요할 때 명시값을 사용하고 폰트 변경 후 재검사합니다.
10. 동일 상태의 전후 screenshot과 DOM 측정을 남깁니다. 데스크톱/모바일·빈 상태·오류 상태·키보드 가림도 확인합니다.

## 잘못된 예

- 창폭 0을 실제로 좁은 UI라고 판단합니다.
- 페이지 수가 같아서 PDF 본문이 보존됐다고 보고합니다.
- RTL에서도 `start`를 `left`로 바꿉니다.
- stylesheet 하나가 있으니 필요한 CSS와 폰트가 모두 준비됐다고 생각합니다.
