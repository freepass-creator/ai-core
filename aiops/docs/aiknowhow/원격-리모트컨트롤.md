# 원격(Remote Control) — AI 가 켤 수 있나

> ✗ **안 된다.** 2026-09-11 에 실제로 다 해 보고 막혔다. 대표: 「원격은 안 되는 거 같다」
>
> ★이 문서의 값은 「된다」 가 아니라 **「이 길로는 안 된다 — 여기까지 해 봤다」** 다.
> 다음 세션이 같은 길을 또 파지 않게 적는다.

---

## 물음

대표: 「원격 꺼진 애들 리모트 컨트롤 네가 켤 수 있잖아. **메시지 보내가지고** 그건 안 되나?」

`ListAgents` 를 치면 이렇게 나온다 —

```
webtoon-studio-b0 [4a89b8]  ·  interactive        ← 살아 있다
누구 없나? [2d9a9e]         ·  Remote Control · ★offline
코덱스 연동 [74c16d]        ·  Remote Control · ★offline      … 14개
```

## 해 본 것과 결과

| 길 | 되나 |
|---|---|
| **다른 세션에 메시지 보내기** | ○ **된다.** ★offline 로 뜨는 세션에도 «닿는다» (실측: delivered, turn started) |
| 그 세션이 자기 원격을 켜기 | ✗ **그쪽에도 켜는 도구가 없다** (webtoon-studio 세션이 직접 확인해 회신) |
| `RemoteTrigger` 도구로 | ✗ **이름만 비슷하다.** claude.ai routines(예약 실행) API 래퍼다 — 새 클라우드 실행을 «만드는» 쪽 |
| `mcp__ccd_session_mgmt__*` 로 | ✗ list_sessions·get_session·send_message·set_session_title·archive_session 뿐. **설정을 바꾸는 항목이 없다** |
| `claude --resume local_… --remote-control` | ✗ 「**not a UUID**」 — §id 두 벌 |
| `claude --resume "제목" --remote-control` | △ **세션은 찾는다.** 그런데 「Provide a prompt to continue」 에서 멈춘다 |
| Bash 도구에서 직접 실행 | ✗ **호출이 끝나면 프로세스가 죽는다.** 원격이 유지될 수 없다 |
| 창을 «떼어» 띄우기 (`Start-Process cmd /c claude …`) | ✗ **같은 오류로 죽는다** — 아래 §로그 |

★**결론 — 원격 연결은 사람이 그 창에서 해야 한다.** AI 도구로 켜는 길이 없다.

## ★로그 — 떼어 띄운 창도 «같은 오류로» 죽었다

```
Error: No deferred tool marker found in the resumed session.
       Either the session was not deferred, the marker is stale (tool already ran),
       or it exceeds the tail-scan window. ★Provide a prompt to continue the conversation.
```

★**내가 처음에 「창은 뜬다」 고 적었는데 틀렸다.** 창은 떴지만 그건 `--resume` 이 «실패한»
그냥 «새» 세션이었다(`ListAgents` 에 `interactive` 로 잡혔을 뿐 `Remote Control` 이 아니다).
★목록에 뭔가 새로 뜬 것을 「됐다」 로 읽으면 안 된다. **로그를 봐야 안다.**

★그리고 여기가 «완전히 막힌» 자리다 —
  「Provide a prompt」 라 해서 프롬프트를 주면 ★`--print` 모드가 되고,
  `--print` 로는 «인터랙티브 원격 세션» 이 아니다. 둘을 같이 만족시킬 길이 없다.

## ★★id 가 «두 벌» 이다 — 여기서 제일 많이 헤맸다

```
데스크탑 앱(CCD)   local_5746a03a-53ad-431c-a214-6e63c7301e64   ← list_sessions 가 주는 것
CLI --resume       5746a03a-…(UUID) 또는 «세션 제목»            ← ★앞엣것을 안 받는다
```

`local_` 을 떼도 안 된다 — `~/.claude/projects/<폴더>/` 의 `*.jsonl` 이름과도 «다르다».
★**세션을 짚을 때는 «제목»으로 짚는다.** 그게 지금 유일하게 먹히는 길이다.

```bash
cd C:/dev/webtoon-studio && claude --resume "가상배우인격부여"
```

## ★함정 넷

1. **`--remote-control` 뒤에 이름을 주면 `--print` 모드로 해석된다.**
   「`--resume requires a valid session ID or session title when used with --print`」 가 뜬다. 이름을 빼라.
2. **Bash 도구는 호출마다 cwd 가 리셋된다.** `cd A` 를 따로 치면 안 먹는다 — `cd A && claude …` 로 한 줄에.
   (안 그러면 딴 폴더에서 찾아 「No conversation found」 가 뜬다)
3. **「offline」은 「죽었다」 가 아니다.** 원격 연결만 끊긴 것이고 세션은 로컬에 살아 있다.
   ★그래서 «메시지는 닿는다». 나는 처음에 「못 닿는다」 고 했다가 틀렸다.
4. **`cmd /c … > log 2>&1` 로 띄우면 로그가 비어 있을 수 있다.** 화면을 봐야 안다.

## 쓸 수 있는 것 — CLI 옵션

```
--remote-control [name]                    ★«새» 인터랙티브 세션을 원격으로 시작
--remote-control-session-name-prefix <p>   자동 이름 앞머리 (기본: 호스트이름)
-r, --resume [값]                          세션 id 또는 ★제목으로 이어받기
-c, --continue                             이 폴더의 가장 최근 대화 이어받기
```

★**꺼진 세션을 원격으로 «되살리는» 조합은 확인하지 못했다.** `--help` 에도 안 적혀 있다.

## 그래서 무엇을 하나

- **다른 세션에게 일을 시키려면** → 원격이 필요 없다. `send_message` 로 바로 닿는다(오늘 일곱 세션에 돌렸다)
- **폰에서 데스크탑을 보려면** → 대표가 그 창에서 켜야 한다
- ★**「내가 켜 줄까요」 라고 말하지 마라.** 못 켠다. 이 문서를 보여 주고 사람이 켜게 한다
