## KH-005 기존 원본 찾기와 로컬·원격 차이 확인

출처: G1, L1, U1, O4.
상태: 과거 기록을 바탕으로 정리한 권장 절차(이번 실행 재현 없음).
현재 열람: 2026-09-08의 KB 스냅샷 전체 읽기. 이전 세션 원문 재검수는 아님.
마지막 실행 검증: 미실시. 원문 재열람은 당시 실행 결과의 재현 검증을 뜻하지 않는다.

### 언제 쓰는가

기존 폴더를 찾거나 GitHub 내용이 로컬과 다를 때.

### 핵심 원칙

원격 기본 브랜치와 로컬 작업 트리는 서로 다른 버전이다. 검색 0건이나 경로 404는 저장소 부재를 증명하지 않는다.

### 실제 절차

1. 인증된 연결의 접근 범위와 소유자/저장소를 확인한다.
2. 폴더명 변형(한글·영문·대소문자)을 검색하고 저장소 트리를 확인한다.
3. 로컬 remote·branch·HEAD·미커밋 변경을 기록한다.
4. 원격 commit에 고정한 경로와 로컬 파일 해시를 각각 남긴다.
5. 미커밋 내용을 원격 파일로 덮지 않는다.

```powershell
git -C <저장소> status --short
git -C <저장소> branch --show-current
git -C <저장소> rev-parse HEAD
git -C <저장소> remote get-url origin
```

### 잘못된 예

이번 회수에서 GitHub `docs/aiknowhow`는 404였지만 `docs/노하우`에는 원본이 있었다. 이를 “기존 폴더 없음”으로 처리하면 중복 폴더가 생긴다.

### 체크리스트

- [ ] owner/repo와 branch가 맞는가
- [ ] 한글 구경로까지 확인했는가
- [ ] 연결 권한 부재와 파일 부재를 구분했는가

## KH-006 남의 변경을 건드리지 않는 문서 반영

출처: L1, U1.
상태: 과거 기록을 바탕으로 정리한 권장 절차(이번 실행 재현 없음).
현재 열람: 2026-09-08의 KB 스냅샷 전체 읽기. 이전 세션 원문 재검수는 아님.
마지막 실행 검증: 미실시. 원문 재열람은 당시 실행 결과의 재현 검증을 뜻하지 않는다.

### 언제 쓰는가

여러 세션이 같은 저장소를 쓰거나 dirty 상태일 때.

### 핵심 원칙

수정 파일을 명시한다. 공용 main에서 무작정 pull/reset하거나 전체 add하지 않는다.

### 실제 절차

1. 변경 전 대상 파일 해시와 diff 목록을 저장한다.
2. 작업 사본이나 전용 작업 트리에서 준비한다.
3. 반영 직전 해시가 그대로인지 확인하고 달라졌으면 병합 검토한다.
4. 승인된 파일만 복사·편집한다.
5. diff --check와 대상 파일 diff를 본다.
6. 커밋이 필요하면 파일명별로 stage하고 staged diff를 확인한다. push·PR 공개 범위와 배포 트리거는 별도 확인한다.

### 잘못된 예

`git add -A`로 다른 세션의 변경까지 묶거나, 폴더명을 정리한다며 실행 스크립트 참조를 일괄 바꾼다.

### 체크리스트

- [ ] 반영 전 충돌 검사를 했는가
- [ ] 요청 범위 파일만 바뀌었는가
- [ ] 외부 게시 여부가 명시됐는가
