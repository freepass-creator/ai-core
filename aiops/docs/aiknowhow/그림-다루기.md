## 언제 쓰는가

연속 컷의 색감·비율·눈금·한글 자막을 맞추거나 SVG를 래스터 이미지로 내보낼 때 사용합니다. 참조·수정 범위는 IMG-001, 생성 차단은 IMG-002, 취향 비교는 IMG-003을 함께 봅니다.

## 핵심 원칙

승인된 원본과 유지 요소를 먼저 고정합니다. 실제 편집은 현재 세션이 제공하는 이미지 도구와 적용 규칙을 따릅니다. 특정 AI 브랜드의 생성 가능 여부, 설치 라이브러리, 글꼴 취향은 영구 규칙이 아닙니다.

수치는 시각 검수의 보조입니다. 평균 밝기·배율이 비슷해도 같은 장면이나 같은 인물임을 입증하지 못합니다.

## 실제 절차

1. 도구·폰트의 실제 설치와 지원을 확인합니다. Pillow의 가변 폰트는 제공되는 variation 이름/축을 조회한 뒤 굵기를 선택합니다. 특정 폰트나 Bold를 일괄 금지하지 않고 결과물에서 한글 모양과 가독성을 비교합니다.
2. SVG→PNG 변환에서는 출력 크기·상대 이미지 기준 경로·폰트 로딩을 확인합니다. 렌더러가 웹폰트를 지원하는지 확인하고 시스템 폰트 fallback으로 글자가 달라지지 않았는지 봅니다.
3. 같은 장면끼리 그룹화하여 평균 RGB·밝기 등 측정값을 비교합니다. 어두운 복도와 햇빛 실내를 같은 평균값으로 강제하지 않습니다.
4. 색보정은 색공간·감마·클리핑을 고려합니다. `R-=s; B+=s`는 RGB 합만 보존하며 일반적 휘도를 보존하지 않으므로 밝기 보존 코드로 쓰지 않습니다. 보정 후 피부·옷·배경을 원본과 나란히 확인합니다.
5. 반사 여백 확장은 가장자리의 구조·반복 무늬·인체·글자를 먼저 봅니다. 과거 픽셀 표준편차 임계값은 특정 샘플의 휴리스틱이며 자동 안전 판정으로 사용하지 않습니다.
6. 배경과 피부/옷의 색이 유사하면 단순 임계값 분리로 인물이 손상될 수 있습니다. 결과를 확인하고 부적합하면 허용된 분할/마스크 편집이나 원본 위 정보 오버레이를 선택합니다. 특정 분리 모델만이 유일한 해법이라고 단정하지 않습니다.
7. 키 눈금 정렬은 정수리와 발바닥 기준점을 확인하고 `(설정 키 × px_per_cm) / 원본 두 점 사이 픽셀`로 배율을 계산할 수 있습니다. 가로·세로 같은 배율을 적용하고 자동 검출점은 확대 확인합니다. 이는 그림상의 정렬이며 실측 신장이나 인물 동일성 증거가 아닙니다.
8. 원본과 결과를 실제 열어 문자·손·비율·잘림·소품을 검사합니다. 로컬 SVG 미리보기에서 상대 이미지가 안 보이면 로딩/CSP 원인을 확인하거나 허용된 PNG 렌더로 확인합니다.
9. 생성 자산을 프로젝트의 승인된 폴더에 저장하고 참조/컷 순서를 확인합니다. 임시 생성 위치에만 있는 상태를 이관 완료로 보고하지 않습니다.

10. 연속 생성·편집에서는 참조 파일과 버전을 실제 전달하고 얼굴·체형·머리·의상·색상·소품의 유지/변경 목록을 명시합니다. 한 번에 필요한 변경을 제한하고 승인된 결과만 다음 참조로 채택합니다. 실패본은 성공본과 버전을 구분합니다.
11. 실패를 사전 판단·도구 차단 응답·기술 오류·품질 불만으로 나눕니다. 비밀값 없는 요청/참조/응답/시간을 남기고 로그 없는 원인 추정을 규칙으로 만들지 않습니다. 안전장치를 속이지 않으며 실질적 창작 내용 변경이 필요하면 사용자 선택을 받습니다. 기술 성공·품질 검수·사용자 승인은 별도입니다.

## 잘못된 예

- 같은 배율이면 같은 인물이라고 확정합니다.
- 밝기 보존이라며 R과 B를 반대로 같은 양만 바꿉니다.
- 모든 컷을 하나의 평균 밝기로 맞춥니다.
- 임계값이 낮다는 이유로 인물·커튼이 반사된 여백을 검수 없이 채택합니다.

## 체크리스트

- [ ] 원본·유지/변경 요소·장면 그룹이 고정됐는가
- [ ] 현재 도구·폰트와 편집 규칙을 확인했는가
- [ ] 색공간·종횡비·기준점을 확인했는가
- [ ] 한글·손·비율·배경을 실제 보았는가
- [ ] 프로젝트 파일과 참조가 연결됐는가

## IMG-001 원하는 이미지와 수정 범위를 고정하기

상태: 권장 절차 · 편집 단계: 검수안 · 출처: 2026-09-08 이 작업의 사용자 피드백·실제 이미지·도구 응답 · 적용: 대화형 이미지 제작 · 절차 전체 재현 검증: 미실시.

### 언제 쓰는가

“최근 작업처럼”, “그 스타일”, “신발까지”, “소재만 바꿔”처럼 참조와 작은 수정이 중요한 작업.

### 핵심 원칙

최신 파일은 최신 채택본과 다르다. 수정 시간은 찾기 위한 단서일 뿐이며 복사·시험·실패본일 수 있다. 사용자 지정 이미지가 있으면 먼저 실제로 보고, 경로 또는 공유 링크·버전·채택 범위를 고정한다. 프로젝트 매뉴얼은 원래 위치에서 참조하고 개인의 취향을 모든 프로젝트의 기본값으로 만들지 않는다.

### 실제 절차

1. 지정 프로젝트 안에서 최근 이미지 후보와 해당 제작 기록을 함께 확인한다. 원본·시험본·채택본을 나누고, 다른 작업을 광역 탐색하거나 수정하지 않는다.
2. 공유 페이지의 제목만 읽고 이미지를 봤다고 하지 않는다. 실제 렌더링을 확인한다. 보이지 않으면 미확인으로 남기고 원본 첨부를 요청한다. 작은 화면 캡처는 원본의 미세 질감·얼굴·문자를 보증하지 못한다.
3. 한 줄 작업 계약을 만든다: `기준 이미지/버전 | 유지 | 변경 | 완료 조건`. 예: `채택 전신 v2 | 얼굴·체형·드레스·포즈 | 아래 여백 확장 | 양쪽 구두 앞코·굽 전체 표시`.
4. 참조별 역할을 나눈다. 얼굴 참조·복장 참조·구두 참조의 인물과 체형을 섞지 않는다. 확인된 기준 파일을 실제 전달한다.
5. 소재 변경과 디자인 변경을 구별한다. 천을 얇게 해 달라는 요청을 소매·망토 추가나 트임 변경으로 대신하지 않는다. 실질적 대안은 원요청과 차이를 밝히고 선택받는다. 승인된 대안도 원요청 달성으로 보고하지 않는다.
6. 완성 이미지를 열어 전후를 대조한다. 구두는 양쪽 앞코·굽이 프레임 안에 있고 화면 경계에 잘리지 않았는지, 소재는 같은 옷의 같은 영역에서 질감이 달라졌는지, 얼굴은 원본과 나란히 보고 같은 인물로 이어지는지 확인한다. 얼굴 점수·동일 배율만으로 동일성을 보증하지 않는다. 검사하지 않은 유지 요소는 “그대로”라고 단정하지 않는다. 프롬프트에 썼다는 사실은 결과 증거가 아니다.
7. 기준이 불명확하면 해당 부분만 확인한다. 품질 실패본은 채택 참조로 자동 승격하지 않는다. 원본을 보존하며 되돌릴 때는 그 원본에서 새 버전을 만든다.

### 잘못된 예

- 수정 시간이 가장 늦은 하의 편집 실패본을 사용자의 최종 취향으로 확정한다.
- “구두까지” 요청을 새로운 배우·다른 드레스·다른 콜라주 구성으로 바꾼다.
- 확인하지 않은 체형 취향을 “작은 얼굴·긴 다리 선호 확정”으로 저장한다.

### 체크리스트

- [ ] 기준 이미지를 실제로 보고 채택 상태와 참조 역할을 구분했는가
- [ ] 요청한 변경과 실제로 바꾼 디자인이 같은가
- [ ] 신발·손·머리 잘림과 얼굴·체형 변화를 결과에서 확인했는가
- [ ] 시각 확인과 정밀 측정, 생성 성공과 사용자 채택을 구분했는가

## IMG-002 생성 차단·품질 불만·반복 요청을 처리하기

상태: 권장 절차 · 편집 단계: 검수안 · 출처: 2026-09-08 이 작업의 실제 호출에서 출력 단계 moderation_blocked 응답 및 사용자 피드백 확인 · 적용: 현재 도구가 제공하는 응답 범위 · 서비스 정책·내부 원인 일반화: 금지 · 절차 전체 재현 검증: 미실시. 여러 실제 차단 응답을 관찰했으나 안전성·재현율의 통계 검증은 아니다.

### 언제 쓰는가

이미지 작업이 막히거나, 기술적으로 생성됐지만 사용자가 계속 원하는 결과가 아니라고 할 때.

### 핵심 원칙

AI의 사전 판단, 이미지 서비스 차단, 기술 오류, 품질 불만을 분리한다. 성인 여부·의상 이름·과거 성공만으로 현재 요청의 허용이나 생성 성공을 보장하지 않는다. 반대로 출력 차단 하나를 근거로 의상 종류 전체가 금지라고 단정하지 않는다. 현재 안전 기준을 우선하며 우회 요령을 노하우로 축적하지 않는다.

### 실제 절차

1. 실제 호출 여부, 입력 참조, 요청 변경점, 응답 문구, 제공된 오류 코드와 입력/출력 단계를 기록한다. 제공되지 않은 항목은 미확인으로 남긴다. 민감 원문과 계정·토큰을 공용 KB에 넣지 않는다.
2. 출력 단계 차단은 결과를 받지 못했다는 증거다. 특정 단어·의상·인체 부위가 원인이라는 증거가 아니다. 현재 요청 자체가 허용되지 않는 경우에는 도구 탓만 하지 않고 가능한 범위를 짧게 설명한다.
3. 동일한 차단 요청을 표현만 바꾸거나 모델·도구를 바꿔 반복하지 않는다. 사용자가 “계속”이라고 해도 안전 판단과 작업 범위는 유지한다. 사용자가 허용되는 실질적 내용 변경을 명시적으로 선택한 경우에만 바뀐 설계로 진행한다. 짧은 “계속”은 직전에 제시한 단일 대안이 분명할 때만 그 범위로 해석하며, 여러 대안이 있거나 이전 디자인과 혼동되면 먼저 확인한다. 무엇이 달라졌는지 기록할 수 없으면 재호출하지 않는다.
4. 한 번에 요청과 가장 가까운 구체적 대안 하나를 제시한다. 사용자가 거절한 대안을 소매·망토 등 다른 이름으로 되풀이하지 않는다. 적합한 대안이 없으면 해당 이미지 단계는 멈추고 원본과 실패 기록을 보존한다.
5. 생성에 성공해도 원요청과 어긋나면 `생성 성공 / 요구 미충족 / 사용자 미채택`으로 보고한다. 품질 재작업은 IMG-001의 같은 작업 계약에서 실패한 요소와 바꿀 변수를 기록한 뒤 한다. 같은 불만이 반복되거나 개선 근거가 없으면 자동 생성을 멈추고 비교본과 차이를 제시한다. 기술 오류는 원인을 해결한 뒤 같은 범위로 재시도할 수 있으나 콘텐츠 차단의 우회와 섞지 않는다.
6. 사용자가 이미지 작업을 끝내고 문서 개선으로 전환하면 생성을 멈춘다. 교훈만 일반화해 기존 대표 카드에 통합한다. 취향·허용 범위를 추정해 메모리나 프로젝트 정본을 자동 수정하지 않는다.

### 잘못된 예

- 실제 차단 응답 없이 “도구가 거절했다”고 말한다.
- “다른 곳에서 됐으니 여기서도 반드시 된다” 또는 “한 번 막혔으니 이 의상은 금지”라고 단정한다.
- 매번 다른 대안을 생성한 뒤 원래 요청대로 고쳤다고 보고한다.
- 안전 문구를 붙이면 통과한다는 프롬프트 요령을 배포한다.

### 체크리스트

- [ ] 판단·차단·기술 오류·품질 실패가 분리됐는가
- [ ] 실제 응답보다 넓은 원인을 주장하지 않았는가
- [ ] 재작업이 단순 우회가 아닌 허용된 실질적 변경인가
- [ ] 생성·검수·채택 상태를 따로 기록했는가

## IMG-003 취향을 재사용 가능한 비교 기준으로 만들기

상태: 권장 절차 · 편집 단계: 검수안 · 적용: 사용자 기준 인터뷰와 이미지 검수 · 출처: 이번 대화의 체형·소재·프레이밍 불만 · 사용자 취향 확정 및 전체 절차 검증: 미실시.

### 언제 쓰는가

예를 들어 “체형이 별로”, “소재가 두꺼워 보인다” 같은 피드백이 반복되지만 다음 세션에 전달할 기준이 없을 때.

### 핵심 원칙

관찰·AI 해석·사용자 확정을 나눈다. 동일 인물 유지와 미적 선호는 서로 다른 검사다. 수치를 많이 적는 것보다 채택/탈락 예시와 이유가 유용하다. 자세·렌즈·힐·의복에 영향을 받는 그림상의 비율을 실제 신체 치수로 주장하지 않는다.

### 실제 절차

1. 기존 [기준 인터뷰](AI활용-발전로드맵.md)의 절차를 사용한다. 새 인터뷰 매뉴얼이나 별도 지식 폴더를 만들지 않는다.
2. 같은 목적의 채택 예시와 미채택 예시를 비교하고 “어디가 달랐는가”를 한 번에 하나씩 묻는다. 배우 정체성·체형 비율·소재·디자인·구도 축을 구분한다.
3. 특정 대화의 요청과 불만은 그 작업에만 적용한다. 구체적인 이상 비율·선호 체형·전 작품 의상 기준으로 확대하려면 별도 확인이 필요하다. 실제 사건의 원문과 적용 범위는 해당 작업 기록에서 확인한다.
4. 기존 기준 인터뷰 기록에 이미지 참조 버전과 채택 상태를 연결한다. 새 평행 양식을 만들지 않는다. 사용자 이유와 AI 해석을 구분하고 반드시 유지할 것·변경 가능한 것·예외·미확인 질문을 기존 기록의 해당 칸에 적는다.
5. 새 예시에 기준을 적용해 사용자 판단과 비교한다. 한 사례의 동의를 영구 취향이나 자동 승인으로 확대하지 않는다. 기준이 바뀌면 이유와 적용 범위를 새 버전으로 남긴다.
6. 납품 전 IMG-001의 결과 대조와 IMG-002의 실패 분류를 사용한다. 별도 합격 기준을 복제하지 않는다. 체크리스트 통과가 모든 미적 품질이나 사용자 채택을 보증하지는 않는다.

### 잘못된 예

- “체형이 별로”라는 말을 임의의 등신 수치로 바꿔 모든 배우에 적용한다.
- 생성 성공이나 대안 실행 동의를 최종 취향 채택으로 기록한다.
- 네 AI의 미적 다수결을 사용자 취향보다 우선한다.

### 체크리스트

- [ ] 사용자 발언과 AI 해석이 분리됐는가
- [ ] 채택·미채택 예시와 적용 범위가 있는가
- [ ] 아직 모르는 취향을 확정하지 않았는가
- [ ] 실제 결과의 반례가 나오면 기존 통과 판정을 다시 검토하는가
