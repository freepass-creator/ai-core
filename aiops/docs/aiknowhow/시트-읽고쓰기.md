## 언제 쓰는가

Google Sheets와 Excel의 값을 읽고 비교하거나 승인된 범위를 수정할 때 사용합니다.

## 핵심 원칙

정본 계정·파일 ID·탭·범위·버전을 고정합니다. **과거 “쓰기 승인 면제” 기록은 현행 실행 권한이 아닙니다.** 실제 수정·공유·이동·삭제는 현재 사용자 지침의 직전 승인과 기존 보호 구조를 따릅니다.

잠금은 동시 실행 차례를 통제하며 승인이나 데이터 정합성을 보장하지 않습니다. 직원 입력칸·수식·서식·검증 규칙을 보존합니다.

## 실제 절차

1. 지정 계정으로 원문을 읽고 파일/탭/범위와 수정 시점을 기록합니다. 403이면 먼저 현재 계정·권한·대상을 확인합니다. 다른 신분으로 조용히 재시도하거나 도메인 위임을 자동 확대하지 않습니다.
2. 열 이름을 해석한 뒤 값에 연결합니다. 두 줄 띠 머리글은 병합 셀·상하 관계를 보고 펼치며, 휴리스틱만으로 확정하지 않습니다. 동명 열은 상위 제목·월·단위를 포함한 복합 키로 구분합니다. 미해석 헤더가 있으면 관련 출력을 보류합니다.
3. 월별 반복 열은 각 그룹의 의미를 확인합니다. 이름 없는 첫 그룹을 항상 이번 달이라고 가정하지 않습니다. 줄 수·거래 건수·고유 인원을 구분하고 목적에 맞는 안정적 키를 사용합니다.
4. Excel은 암호 여부를 분기합니다. 복호화가 필요하면 보호된 방식으로 얻은 암호를 메모리에서 사용하고, 비암호 파일은 원본 스트림을 읽습니다. 복호화한 빈 버퍼를 비암호 파일 경로로 사용하지 않습니다.
5. `openpyxl`의 `data_only=True`는 계산 결과 캐시를 읽으며 수식을 계산하지 않습니다. 수식은 별도로 읽고 캐시 없음/오래된 캐시를 0으로 바꾸지 않습니다. [openpyxl 읽기 옵션](https://openpyxl.readthedocs.io/en/stable/api/openpyxl.reader.excel.html)
6. CSV→Google Sheets는 현재 도구의 명시적 변환 규격과 반환 MIME을 확인합니다. CSV에는 수식·서식·여러 탭·드롭다운 보존을 기대하지 않습니다. 필요한 구조는 지원되는 Sheets 기능으로 별도 준비합니다. 공유는 별도 범위 승인 대상입니다.

   [Sheets API 유효성 검사](https://developers.google.com/workspace/sheets/api/samples/data)와 [조건부 서식](https://developers.google.com/workspace/sheets/api/samples/conditional-formatting)은 지원되는 기능입니다. 현재 연결 도구에 그 기능이 노출되는지는 별도로 확인합니다. 이번 도구 목록의 Drive create_file 스키마는 mime_type/title이며, 옛 contentMimeType/textContent 예제를 이 연결에 그대로 전달할 수 없습니다. API 가능 여부와 현재 도구 가용성을 구별합니다.
7. 수정안을 셀별 before/after와 영향 건수로 준비합니다. 기존 잠금의 소유자·만료·범위를 확인하고 직전 원문을 재조회합니다. 과거 전용 잠금 함수를 승인 대체로 사용하지 않습니다.
8. API 호출 수를 측정하고 적절한 batch 요청을 사용합니다. 하나의 원자적 요청 범위와 여러 요청 전체를 구분합니다. clear 후 write처럼 나뉜 단계는 중간 실패 시 빈 시트를 남길 수 있어 승인된 덮어쓰기·복구 전략을 준비합니다.
9. 재시도는 오류 유형·쿼터·backoff와 한도를 정해 수행합니다. 읽지 못한 탭은 실패로 남기고 부분 합계를 전수 결과로 보고하지 않습니다.
10. 수정 후 같은 범위의 값·수식·서식을 재읽습니다. 기존 프로젝트의 Apps Script 트리거 금지 등 운영 규칙은 그대로 유지합니다.

11. 값·수식·표시 형식을 따로 확인하고 날짜의 저장값과 표시 의미를 혼동하지 않습니다. 페이지네이션과 탭별 읽기 성공을 확인하여 전체 분모를 보고합니다. 원본 접근이 실패하면 로컬 사본을 정본으로 조용히 대체하지 않습니다.

## 잘못된 예

- 열 번호만 보고 새 열이 삽입된 시트에 씁니다.
- 암호가 없는 Excel을 빈 복호화 버퍼로 읽습니다.
- 캐시가 없다는 이유로 수식 결과를 0으로 저장합니다.
- clear와 write가 별도인데 묶음 작업 전체가 원자적이라고 보장합니다.
- 위임 subject 한 줄만 추가하면 권한이 생긴다고 생각합니다.
