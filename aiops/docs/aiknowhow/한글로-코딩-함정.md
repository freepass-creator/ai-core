## 언제 쓰는가

PowerShell·Git Bash·Python·JavaScript 사이에서 한글과 긴 코드를 전달하거나 파일을 편집할 때 사용합니다.

## 핵심 원칙

셸·언어·문자열 해석 층을 구분합니다. 오류를 한글이나 heredoc 자체의 한계로 단정하지 않습니다. 긴 코드와 문서는 파일 편집 도구로 작성하고 긴 프롬프트는 현재 CLI가 지원하는 stdin으로 전달합니다.

JSON 직렬화는 셸 인용 처리가 아닙니다. 실제 경로·UTF-8·프로그램 실행 위치를 먼저 확인합니다.

## 실제 절차

1. 셸과 버전을 확인합니다. PowerShell 5.1과 7은 `&&`·`||`·삼항 연산자 지원이 다릅니다. Bash heredoc을 PowerShell에 그대로 넣지 말고 스크립트 파일이나 해당 셸의 지원 문법을 사용합니다.
2. JavaScript의 ASCII 중심 단어 경계를 한국어 식별자 검색에 그대로 쓰지 않습니다. Unicode 문자·숫자·연결기호와 실제 식별자 규칙을 고려하고 동적 문자열은 정규식 메타문자를 escape합니다. 다른 언어의 정규식 엔진은 별도 확인합니다.
3. `★` 같은 식별자로 쓸 수 없는 기호가 키에 있으면 문자열 키와 대괄호 접근을 사용합니다. 문자열 값 안의 기호와 식별자 문법을 구분합니다.
4. 한국어 조사는 한글 음절 범위를 확인한 뒤 종성 유무와 ㄹ 예외를 처리합니다. 빈 문자열·숫자·영문·기호는 별도 정책이 필요합니다.
5. Windows 경로는 확인된 `C:/...` 또는 적절한 raw 문자열로 전달합니다. Python의 `\a`·`\t`·`\n`·`\b`는 실제 제어문자가 되므로 파일에 보이지 않는 손상이 있는지 검사합니다. 발견된 제어문자를 전역 치환해 원문을 더 훼손하지 않습니다.
6. Python에서 미인식 escape는 현재 역슬래시를 유지하지만 경고 또는 향후 오류 대상입니다. `\d` 경고 자체가 역슬래시를 지웠다고 진단하지 않습니다. 정규식에는 raw 문자열을 사용하고 실제 생성 문자열을 확인합니다. [Python 문자열 리터럴](https://docs.python.org/3/reference/lexical_analysis.html)
7. 따옴표 친 Bash heredoc delimiter는 본문의 셸 확장을 막습니다. 외부에 겹친 셸/문자열 계층을 따로 검사합니다. 종료표와 같은 전체 줄이 본문에 있으면 조기 종료될 수 있으므로 고유한 표식이나 파일 편집을 사용합니다.
8. Git의 한글 경로 escape 표시는 파일 손상과 다를 수 있습니다. 실제 파일명을 확인하고 필요 시 표시 설정을 조정합니다. 폴더 이름을 임의로 바꾸지 않습니다.
9. Git Bash의 `/c/...`·`/tmp/...`와 Windows Python이 보는 경로를 혼동하지 않습니다. 프로그램에 전달할 실제 절대 경로를 확인하고 읽기 성공 뒤에만 개수를 셉니다.
10. 콘솔 인코딩 실패는 데이터 처리 실패와 구분합니다. 출력만 실패했는데 파일은 이미 바뀌었을 수 있어 재실행 전 결과를 읽습니다. UTF-8 출력 설정은 실제 stdout 지원과 소비자 인코딩을 확인합니다.
11. 치환 전 매치 건수·원본 해시·예상 diff를 확인하고 편집 후 재읽습니다. 공동 저장소에서는 대상 파일만 stage하고 다른 세션의 변경을 reset하거나 전체 add하지 않습니다.

## ★git ls-files 를 «다른 프로그램에 넘길» 때 (2026-09-10 실측 · ○ 해 봤고 됐다)

8번의 구체 사례다. 표시만 이상한 게 아니라 **넘기면 실제로 깨진다.**

`core.quotePath` 기본값이 `true` 라서 `git ls-files` 는 한글 경로를
`"\353\257\270\354\210\230.mjs"` 처럼 **따옴표까지 붙인 8진 이스케이프**로 낸다.
그 줄을 그대로 `execFile` 인자로 넘기면 파일을 못 찾는다.

```js
// ✗ 916개 중 100개가 「문법 오류」로 둔갑했다 (실은 MODULE_NOT_FOUND)
execFileSync('git', ['ls-files', '*.mjs'], { encoding: 'utf8' }).split('\n')

// ○ NUL 로 끊어 받는다 — 이스케이프도 따옴표도 없다
execFileSync('git', ['-c', 'core.quotePath=false', 'ls-files', '-z', '*.mjs'],
             { encoding: 'utf8' }).split('\0')
```

★그리고 **「못 찾음」과 「문법 탈」을 갈라 세라.** 못 찾은 것은 대상의 탈이 아니라
**내 도구의 탈**이다 — 「없다」가 아니라 「모른다」. 안 가르면 오탐 100개를
그대로 보고하게 된다. `scripts/구문검사.mjs` 가 그렇게 짜여 있다.

★이 절을 처음 적을 때 나도 여기 걸렸다 — heredoc→파이썬→파일 세 겹을 지나며
역슬래시가 한 겹씩 먹혀 `\0` 은 진짜 NUL 바이트가, `\n` 은 진짜 줄바꿈이,
8진 예시는 실제 문자가 됐다. **7번(계층)과 5·6번(이스케이프)이 한꺼번에 터진 자리다.**
고친 법 — 역슬래시를 리터럴로 적지 않고 `String.fromCharCode(92)` 로 만들어 붙였다.

## 잘못된 예

- `\b`가 모든 언어에서 한국어 경계를 똑같이 처리한다고 생각합니다.
- Python 경고가 백슬래시를 지웠다고 원인 확인 없이 결론 냅니다.
- quoted heredoc이 원래 모든 역슬래시를 접는다고 기록합니다.
- 출력 실패 후 이미 적용된 편집을 다시 실행합니다.
- 경로 해석 실패를 “파일 0개”로 처리합니다.
